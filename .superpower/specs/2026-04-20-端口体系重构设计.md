# InduForge 端口体系重构设计

## 1. 背景与目标

当前仓库的默认端口存在三类问题：

- 根 `.env`、根 `.env_example` 与 `README.md` 的端口定义不一致。
- 节点执行链路与前端存在历史端口漂移，例如 `runtime/node_agent`、`runtime/node_agent_front` 在本地实际值与文档默认值不同。
- 现有端口大量落在常见开发端口区间附近，容易与用户本机其他项目冲突。

本次重构目标是：

- 重新定义一套整齐、可扩展、低冲突的默认端口体系。
- 把端口配置收口为“根 `.env` 单一事实来源”。
- 同步更新 `.env`、`.env_example`、`README.md` 和直接依赖这些默认值的配置项。
- 不顺手扩散到无关业务逻辑或基础设施端口。

## 2. 设计原则

- 避开 `3000`、`5173`、`8080`、`8081`、`9000`、`9090`、`9091` 这类高频本地开发端口。
- 不使用 Windows 常见动态端口范围 `49152-65535` 作为固定默认端口。
- 端口分段应能表达模块归属，看端口就能知道服务类别。
- 端口默认值必须在根 `.env`、`.env_example`、`README.md` 中保持一致。
- 用户本机如有冲突，应只需改根 `.env`，不要求改代码和文档默认值。

## 3. 新端口分层

### 3.1 节点执行链路：`176xx`

- `runtime/node_agent`：`17601`

### 3.2 前端：`186xx`

- `dev_ide`：`18601`
- `datacenter`：`18602`
- `designer`：`18603`
- `runtime/node_agent_front`：`18604`

### 3.3 平台与数据域后端：`196xx`

- `dev_core`：`19601`
- `data_service`：`19602`

### 3.4 基础设施保留段

- `SeaweedFS S3`：`25000`

本次不调整数据库、Redis、SeaweedFS 等基础设施已有默认端口。

## 4. 配置收口策略

### 4.1 单一事实来源

- 根 `.env` 作为本机实际运行端口的唯一来源。
- 根 `.env_example` 作为默认模板，端口定义必须与根 `.env` 一致。
- `README.md` 只描述默认端口，不承载本机临时端口。

### 4.2 各模块读取方式

- 前端继续读取各自的 `VITE_*` 端口变量。
- `dev_core` 继续读取根 `.env` 中的 `PORT` 和 `CORS_ORIGINS`。
- `data_service` 继续读取 `DATA_SERVICE_ADDR`。
- `runtime/node_agent` 继续读取 `NODE_AGENT_PORT`。

### 4.3 文档与规则约束

- 文档中描述端口时，默认引用根 `.env_example` 代表的默认端口体系。
- 根 `AGENTS.md` 增补一条：端口以根 `.env` 为准，文档应与根模板保持一致。

## 5. 本次改动范围

### 5.1 需要修改的文件

- 根 `.env`
- 根 `.env_example`
- `README.md`
- `AGENTS.md`
- 直接依赖旧默认端口且写死默认值的少量配置文件

### 5.2 不在本次范围内的内容

- MySQL、PostgreSQL、Redis、SeaweedFS 的默认端口
- 与端口无关的业务逻辑
- 各模块启动流程的整体重构
- 用户机器上已有冲突端口的个性化处理

## 6. README 展示方式

`README.md` 需要增加一个端口总览表，至少包含：

- 模块名
- 服务类型
- 环境变量名
- 默认端口
- 默认访问地址

这样可以避免未来再次出现“模板、文档、实际值”三处漂移。

## 7. 迁移策略

- 本次直接切换到新默认端口，不保留双默认值体系。
- `README.md` 会明确提示：若本地仍在使用旧端口，需要同步更新根 `.env`。
- 代码层保留“从根 `.env` 读取端口”的机制，但不再保留旧默认端口回退逻辑。

## 8. 风险与验证

### 8.1 主要风险

- `CORS_ORIGINS` 未同步更新，导致前端跨域失败。
- 某些模块内部若仍有写死旧端口，会导致 README 与运行行为不一致。
- 用户本地脚本或代理配置若引用旧端口，需要一并同步。

### 8.2 本次验证要求

- 校验根 `.env`、`.env_example`、`README.md` 三处端口是否一致。
- 校验 `dev_core` 的 `CORS_ORIGINS` 是否覆盖全部前端默认端口。
- 校验仓库内是否仍存在写死的旧默认端口引用。

## 9. 实施结论

本次端口体系采用以下默认值：

- `runtime/node_agent = 17601`
- `dev_ide = 18601`
- `datacenter = 18602`
- `designer = 18603`
- `runtime/node_agent_front = 18604`
- `dev_core = 19601`
- `data_service = 19602`
- `SeaweedFS S3 = 25000`

该方案兼顾低冲突、可识别和后续扩展性，适合作为仓库新的统一默认端口体系。
