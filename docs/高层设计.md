# 一、InduForge 全链路交付与运维架构设计（概要设计）

## 1. 背景与目标

### 1.1 目标

- 支持 **大屏 / PC / 移动端**应用的低代码设计与发布
- 工程可发布到 **任意节点**运行（在线拉取部署 / 离线导入部署）
- 节点运行时具备 **统一运行时引擎 RuntimeEngine**
- 节点具备 **上报状态、接收启停/部署指令**能力
- 工程运行时自带 **工程内部用户体系（RBAC）**，与 IDE 用户体系完全解耦

### 1.2 非目标（建议在文档里写清，避免后期需求爆炸）

- 不承诺纯静态离线模式具备强对抗安全（可提供“弱安全/强安全”两档）
- 不在第一期实现多人实时协作（但底层预留 patch/版本能力）

---

## 2. 术语与边界

- **IDE 域**：平台开发/配置人员账号体系（dev_core 管）
- **Ops 域**：运维人员账号体系（Ops 服务管，可与 IDE 域共用或独立）
- **Runtime 域**：工程内部用户账号体系（节点侧/工程侧）
- **工程制品（IFP）**：工程发布后的可部署包（zip）
- **NodeAgent**：节点控制面守护进程（部署/启停/上报）
- **RuntimeEngine**：节点业务面运行时引擎（渲染/数据/权限/动作）

> **关键原则**：IDE 域 / Ops 域 / Runtime 域三域隔离。
> IDE 用户从不进入工程包；Runtime 用户不需要在平台存在。

---

## 3. 总体组件与职责

### 3.1 平台侧（你已有 + 建议新增）

- **dev_ide（工程管理入口）**：工程列表、进入 Designer/DataCenter、触发发布
- **designer（设计中心）**：编辑工程 Schema、预览、校验、生成发布产物
- **datacenter（数据中心）**：数据 ID 目录/结构（仅逻辑层），不绑定节点 endpoint
- **dev_core（平台后端）**：IDE 域用户/租户/工程元数据/版本记录/权限（平台级）

### 3.2 运维侧（建议新增）

- **ops_center（运维系统）**：

  - 节点注册、节点分组
  - 工程版本上架、下发部署、启停、回滚
  - 状态/日志/告警/审计（分阶段做）

- **artifact_registry（制品仓库）**：

  - 存 `.ifp` 包、manifest、签名、版本元信息
  - 可简单先用对象存储/文件存储 + 索引表

### 3.3 节点侧（关键）

- **NodeAgent（必选）**：

  - 拉取/导入 `.ifp`、校验签名、解压落盘
  - 启动/停止/重启 RuntimeEngine
  - 心跳与状态上报，指令 ACK
  - 保存节点本地连接配置（Connection Profile）与密钥（Secrets）

- **RuntimeEngine（必选）**：

  - 加载工程 Schema 与 assets
  - Renderer（渲染器）+ DataService + AuthService + ActionRuntime
  - 提供 `/health` `/status` 给 NodeAgent 探活与采集

## 4. 制品与配置模型（这是能否顺利运维的核心）

### 4.1 工程制品格式 IFP（建议）

`project_xxx@1.3.2.ifp`（zip）

```text
.ifp
 ├─ manifest.json                 // 工程清单：入口/依赖/能力声明/角色声明/签名信息
 ├─ schema/project.json           // 规范化工程Schema（页面/节点/绑定/权限/动作）
 ├─ schema/migrations/            // 可选：迁移脚本或版本说明
 ├─ assets/                       // 图片/字体/静态资源
 ├─ mock/                         // 可选：mock数据
 └─ signatures/                   // 可选：签名与hash
```

### 4.2 节点运行配置 Connection Profile（部署时注入，不进 ifp）

`connectionProfile.json`（NodeAgent 管理）

```json
{
  "connections": {
    "dc_main": {
      "type": "http+ws",
      "httpBase": "http://10.0.0.5:9092/api",
      "wsUrl": "ws://10.0.0.5:9092/ws",
      "auth": { "type": "secretRef", "ref": "secret_dc_main_token" }
    }
  },
  "runtime": {
    "reporting": { "enabled": true, "intervalSec": 10 },
    "logLevel": "info"
  }
}
```

> **要点**：工程 Schema 只认 `providerAlias + dataId`；真实 endpoint 与密钥永远在节点侧。

### 4.3 节点状态模型（Ops 看板的基础）

NodeAgent 上报：

```json
{
  "nodeId": "node_001",
  "agentVersion": "0.3.0",
  "online": true,
  "runtime": { "healthy": true, "pid": 23120 },
  "running": [
    {
      "projectId": "proj_xxx",
      "version": "1.3.2",
      "status": "running",
      "since": 1736123456
    }
  ],
  "lastError": null,
  "metrics": { "cpu": 0.23, "mem": 0.41, "wsConn": 12, "dcErrors": 0 }
}
```

## 5. 发布与部署流程

### 5.1 发布入口与内容

**发布入口**：在 **dev_ide** 的工程卡片上操作（不是在 Designer 内部）

**发布内容**（IFP 包）：

| 内容          | 来源            | 说明                                            |
| ------------- | --------------- | ----------------------------------------------- |
| 设计器 Schema | Designer        | 页面、组件、绑定、权限、动作                    |
| 数据中心配置  | DataCenter      | 连接定义、查询、MQTT 订阅、数据点               |
| 资源文件      | Designer/Assets | 图片、图标等静态资源                            |
| 清单文件      | 编译生成        | manifest.json（dataRequirements、capabilities） |

```
project-v1.0.0.ifp (zip)
├── manifest.json           # 清单文件
├── project.json            # 设计器 Schema
├── datacenter.json         # 数据中心配置（连接、查询、数据点）
├── assets/                 # 资源文件
└── assets-mapping.json     # 资源映射
```

### 5.2 运维管理（dev_ide）

**节点管理**：

- 节点注册与发现
- 节点状态监控
- 节点分组管理

**部署管理**：

- 已发布版本列表
- 部署工程到指定节点
- **同一工程可部署到多个节点**
- **同一节点只能运行一个工程**
- 部署时配置（端口、ConnectionProfile 等）

**部署配置示例**：

```json
{
  "deploymentId": "deploy_xxx",
  "projectId": "proj_001",
  "version": "1.0.0",
  "nodeId": "node_factory_01",
  "config": {
    "port": 8080,
    "uiTarget": "bigscreen",
    "defaultLocale": "zh-CN",
    "defaultTheme": "light"
  }
}
```

> **注意**：数据连接配置（ConnectionProfile）在工程设置中预先配置，不在部署时设置。

### 5.3 端到端流程

#### 在线发布与部署流程（推荐主路径）

**发布阶段（dev_ide 工程卡片）**：

1. 用户在 **dev_ide 工程卡片** 点击"发布"
2. 系统加载 Designer Schema + DataCenter 配置
3. 执行校验 → 编译 manifest → 打包资源
4. 生成 `.ifp` 包，上传 Registry，写入版本记录

**部署阶段（dev_ide 运维管理）**：

1. 运维人员在 **dev_ide 运维管理界面** 选择工程版本
2. 选择目标节点（可多选），配置 ConnectionProfile
3. 下发部署指令到 NodeAgent
4. NodeAgent 下载 → 校验 → 解压 → 启动 RuntimeEngine
5. RuntimeEngine 根据 ConnectionProfile 连接数据源

**简化时序图**：

```text
User -> dev_ide: 点击"发布"
dev_ide -> dev_core: 加载 Designer Schema + DataCenter 配置
dev_core -> Registry: 上传 IFP

User -> dev_ide: 选择节点，配置 ConnectionProfile，点击"部署"
dev_ide -> NodeAgent: deploy(ifpUrl, connectionProfile)
NodeAgent -> Registry: 下载 IFP
NodeAgent -> NodeAgent: 校验/解压
NodeAgent -> RuntimeEngine: 启动(connectionProfile)
RuntimeEngine -> DataCenter: 连接数据源
RuntimeEngine -> NodeAgent: /health ok
NodeAgent -> dev_ide: heartbeat(status=running)
```

#### 离线导入流程（必须支持）

1. 平台导出 `.ifp`（可附 `connectionProfile.template.json`）
2. 人工拷贝到离线节点
3. NodeAgent 本地 UI/CLI 执行 `import`
4. 配置 ConnectionProfile（本地）→ `start`
5. 若节点未来联网，可选择"注册到 Ops 并上报当前状态"

## 6. 安全与可信（建议写成两档，让产品说得清）

- **档 A：Pure Static/弱安全**

  - Runtime 用户数据可随工程包（加密存储）
  - 适合内网可信/演示

- **档 B：Node Local Auth/强安全（建议生产默认）**

  - Runtime 用户与角色存节点 SQLite（NodeAgent 或 RuntimeEngine 附带 Auth 模块）
  - token 由本地服务签发，前端不可伪造
  - 运维可重置/审计

> 无论哪档：**IDE 用户都不进入工程**，这是你的强边界。

---

## 7. 可用性与可靠性（节点启停与回滚）

- NodeAgent 做版本目录管理：

  - `/data/induforge/projects/{projectId}/{version}/...`

- 支持：

  - 启停、重启
  - 回滚到上一版本（快速切换指针 + 重启）
  - 部署前预检查（manifest 的 dataRequirements 与 capability）

- RuntimeEngine 提供：

  - `/health`（轻量健康）
  - `/status`（工程版本、连接状态、订阅数量、错误统计）
  - （可选）`/metrics`（Prometheus 友好）

---

## 8. 测试与验收（建议最少覆盖）

- Schema 校验测试（非法绑定/缺角色/循环引用/资源缺失）
- 导出 ifp 可被 NodeAgent 导入并启动（集成测试）
- 节点离线导入 + 启动 + 本地登录（E2E）
- 权限：组件渲染限制 + 动作二次校验（安全用例）

## 10. 关键闭环机制设计

### 10.1 数据点状态与影响分析机制

#### 10.1.1 数据点状态分类

| 状态    | 含义                                | 触发条件                     |
| ------- | ----------------------------------- | ---------------------------- |
| active  | 正常可用                            | 数据源正常，最近有数据       |
| invalid | 失效（需人工处理）                  | 数据源删除/配置变更/解析失败 |
| unknown | 未知（Designer 引用了不存在的路径） | 手写路径/导入/表达式拼接     |

#### 10.1.2 数据点状态 API

**批量查询状态**（Designer 打开工程/页面时调用）：

```
POST /api/v1/datapoints/status
Body: { projectId, refs: [{ path, providerAlias? }] }
Response: [{ path, status, status_reason, last_seen_at, dataType }]
```

**实时推送**（可选增强）：

```javascript
// DataCenter 后端在标记 invalid 时发布事件
socket.emit("datapoint:invalidated", {
  projectId,
  path,
  reason,
  ts,
});

// Designer 监听
socket.on("datapoint:invalidated", (data) => {
  diagnosticsStore.markInvalid(data.path, data.reason);
});
```

#### 10.1.3 Designer 诊断展示

诊断信息存储在**内存态 diagnosticsStore**（不入库），UI 展示位置：

- **数据点选择器**：用 🔴/🟡/⚪ 提示 invalid/unknown/active
- **组件属性面板**：绑定字段旁显示状态图标，hover 显示原因
- **页面树/大纲树**：受影响节点显示小红点，可点击定位
- **发布前校验面板**：列出所有问题数据点及影响的组件

#### 10.1.4 发布校验规则

```javascript
// 发布流水线 validate 阶段
for (const dp of dataRequirements.datapoints) {
  const status = await getDatapointStatus(dp.path);
  if (dp.required && status === "invalid") {
    throw new PublishError(`必需数据点 ${dp.path} 已失效`);
  }
  if (dp.required && status === "unknown") {
    throw new PublishError(`必需数据点 ${dp.path} 不存在`);
  }
  if (!dp.required && status !== "active") {
    warnings.push(`可选数据点 ${dp.path} 状态异常: ${status}`);
  }
}
```

### 10.3 Multi-View 多端模型

#### 10.3.1 数据模型

同一逻辑页面在不同 target 下有不同视图版本：

```
design_pages:
┌────────────┬────────┬────────────┬───────────────┐
│ logicalId  │ path   │ target     │ isDefaultTarget│
├────────────┼────────┼────────────┼───────────────┤
│ logic_001  │ /home  │ pc         │ 1             │
│ logic_001  │ /home  │ bigscreen  │ 0             │
│ logic_002  │ /login │ pc         │ 1             │
└────────────┴────────┴────────────┴───────────────┘
```

#### 10.3.2 运行时选路规则

```javascript
// RuntimeEngine 启动时从 ConnectionProfile 获取 target
const currentTarget = connectionProfile.uiTarget; // 'bigscreen'

// 路由解析
function resolvePageView(path) {
  // 1. 优先匹配当前 target
  let page = pages.find((p) => p.path === path && p.target === currentTarget);

  // 2. fallback 到 default
  if (!page) {
    page = pages.find((p) => p.path === path && p.isDefaultTarget);
  }

  // 3. 再 fallback 到 pc
  if (!page) {
    page = pages.find((p) => p.path === path && p.target === "pc");
  }

  return page;
}
```

#### 10.3.3 Designer 操作

- **克隆视图**：从 PC 视图快速创建 BigScreen 视图（`Copy as target view`）
- **预览切换**：工具栏提供 target 切换，预览不同视图效果
- **差量继承**（可选增强）：支持 `baseViewId + overrides` 模式

## 数据绑定系统

> **详细文档**：[数据绑定 v2](./designer/refactor/data-binding-v2.md)

### 三态数据隔离

| 模式 | 特点 |
|------|------|
| 设计态 | 不连接真实数据源，使用 designMock 或占位符 |
| 预览态 | 通过 Bridge 连接 DataCenter，获取真实数据验证 |
| 运行态 | 通过 ConnectionProfile 连接节点侧数据源 |

> **关键原则**：设计态只做"配置"，不做"连接"。

### Binding 模式

| 模式 | kind | 用途 |
|------|------|------|
| 数据点绑定 | `datapoint` | 绑定 DataCenter 数据点 |
| 变量绑定 | `var` | 绑定页面/全局变量 |
| 表达式绑定 | `expr` | 复杂计算表达式 |

```json
"bindings": {
  "value": {
    "kind": "datapoint",
    "path": "mqtt.EMQX.温度组.temperature",
    "designMock": 25.5,
    "fallback": 0
  }
}
````

## 国际化与主题系统

> **详细文档**：[国际化与主题](./designer/refactor/i18n-theme.md)

### 国际化（i18n）

- 用户可配置页面的多语言资源
- 支持 `$i18n` 属性引用或内联多语言对象
- 提供 **LocaleSwitcher** 组件，运行时切换语言

```json
"props": { "text": { "$i18n": "page.home.welcome" } }
```

### 主题系统（Theme）

- 支持浅色/深色/自定义主题
- 基于 CSS 变量实现，组件自动响应
- 提供 **ThemeSwitcher** 组件，运行时切换主题

| 主题变量             | 浅色    | 深色    |
| -------------------- | ------- | ------- |
| --bg-color           | #FFFFFF | #141414 |
| --text-color-primary | #303133 | #E5EAF3 |
| --color-primary      | #409EFF | #409EFF |
