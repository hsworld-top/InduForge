# RuntimeEngine

## 1. 文档定位
- 本文档定义低代码工程在节点侧的运行时最小方案。
- 当前 `runtime/engine_core`、`runtime/engine_data`、`runtime/engine_front` 目录为空，本文件描述的是下一阶段要冻结的 MVP 边界。
- 正式平台结论以 [高层设计](../../高层设计.md) 和 [详细设计](../../详细设计.md) 为准。

## 2. 当前已实现
### 2.1 已有基础
- 平台已具备发布、部署、节点管理主链路。
- `runtime/node_agent` 已具备部署执行、命令控制、探活与本地前端。

### 2.2 当前缺口
- 缺少真正解释制品并提供页面访问能力的运行时引擎。
- Designer 输出和 Runtime 消费契约尚未正式冻结。
- 节点虽然能托管进程，但没有可托管的正式运行时进程。

## 3. 共创后建议目标
### 3.1 MVP 目标
- 读取 `.ifp` 制品。
- 加载项目与页面定义。
- 提供入口页访问。
- 支持首批基础组件渲染。
- 提供最小数据绑定能力。
- 暴露健康检查和运行状态接口。

### 3.2 模块拆分建议
| 模块 | 职责 |
| --- | --- |
| `engine_core` | 制品加载、路由、页面解释、运行状态 |
| `engine_front` | 页面渲染前端 |
| `engine_data` | 数据点、查询结果、变量上下文适配 |

## 4. 启动与运行流程
### 4.1 启动来源
1. `dev_core` 下发部署命令。
2. `node_agent` 下载并解压版本包。
3. `node_agent` 启动 RuntimeEngine 进程。
4. RuntimeEngine 读取制品并开放访问端口。

### 4.2 运行时接口
- `GET /health`：健康检查。
- `GET /status`：运行状态、项目、版本、启动时间。
- `GET /api/runtime/project`：项目运行态元信息。
- `GET /api/runtime/page/:pageId`：页面运行态模型。

## 5. 数据消费边界
### 当前阶段支持
- 静态值。
- 数据点值。
- 查询结果。
- 全局变量。

### 当前阶段不支持
- 复杂动作系统。
- 多视图适配。
- 完整权限系统。
- 独立桌面壳。

## 6. 与其他模块的关系
### 上游
- `designer`：输出发布态工程 Schema。
- `dev_core`：输出标准制品并下发部署。
- `datacenter`：提供数据对象模型定义。

### 下游/宿主
- `runtime/node_agent`：负责 Runtime 进程托管和探活。

## 7. 运行状态建议
- `STARTING`
- `RUNNING`
- `DEGRADED`
- `FAILED`
- `STOPPED`

## 8. 当前阶段非目标
- 不实现完整工业组件库。
- 不实现本地离线历史回放。
- 不实现复杂脚本执行沙箱。
