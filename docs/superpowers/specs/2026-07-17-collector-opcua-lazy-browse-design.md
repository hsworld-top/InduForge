# OPC UA 设备懒加载浏览设计

## 目标

在统一工业采集工作台中恢复 OPC UA 地址空间逐级展开浏览能力，并将选中的变量节点直接带入新建变量流程。

## 范围

- 仅调整 OPC UA 的设备浏览交互。
- 复用现有 DevAgent `device.browse` 调试任务和逐层浏览能力。
- 不恢复已删除的旧 OPC UA 工作台。
- 不新增数据库字段、迁移脚本或历史兼容逻辑。
- 其他工业协议的设备发现界面保持现状。

## 界面与交互

### 浏览工具栏

- NodeId 筛选输入框默认留空。
- NodeId 只作为已加载树节点的本地筛选条件，不作为浏览起点。
- 输入框提示为“筛选已加载节点的 NodeId”。
- 清空筛选后恢复当前已经加载的树，不重新请求 Agent。
- 保留刷新按钮；刷新时清空树缓存并从 OPC UA Objects 根节点重新加载。

### 地址空间树

- 浏览内部默认根节点为 `ns=0;i=85`，但不要求用户填写或看到该默认值。
- 使用 Element Plus 懒加载树，每次展开节点只调用一次 `device.browse`，请求该节点下一层，`maxDepth=1`。
- Object、Folder 等容器节点只用于展开，不可作为变量创建目标。
- Variable 节点可选，并展示名称、NodeId 和数据类型。
- 节点无子项或 Agent 返回 `hasChildren=false` 时不显示可展开状态。

### 创建变量

- 用户选择 Variable 节点后进入新建变量抽屉。
- 自动带入：
  - `address.nodeId`：节点 NodeId。
  - `name`：优先使用 DisplayName，缺失时使用 BrowseName。
  - `dataType`：使用 Agent 返回的数据类型，并按现有变量类型规则归一化。
  - `enabled`：默认启用。
  - `code`：根据节点名称生成初始编码，仍允许用户修改。
- 分组沿用当前变量工作台选中的分组；未选择分组时保存为未分组。
- 用户仍需确认并提交抽屉，选择节点本身不直接写入数据库。

## 数据流

1. 打开 OPC UA 设备浏览区域。
2. 前端创建 `device.browse` 调试任务，内部使用 `parentNodeId=ns=0;i=85`、`maxDepth=1`。
3. 前端轮询现有任务接口，成功后生成当前层树节点。
4. 用户展开容器节点时，以该节点 NodeId 重复步骤 2-3。
5. 用户输入 NodeId 时调用树组件本地过滤，不创建新任务。
6. 用户选择 Variable 节点时，将节点信息传给现有变量新建抽屉。
7. 用户确认保存后调用现有变量批量创建接口。

## 异常处理

- 未选择或 Agent 离线时禁用设备浏览，并沿用现有离线提示。
- 浏览任务失败、取消、过期或超时时展示明确错误消息，保留已经加载的其他树节点。
- 单个节点展开失败时允许用户再次展开重试，不刷新整棵树。
- Agent 返回空节点列表时将当前节点标记为叶子节点。
- 非 Variable 节点不触发新建变量抽屉。

## 验收标准

- NodeId 筛选框初始为空，页面内部仍能从 Objects 根节点开始浏览。
- OPC UA 节点能够逐级展开，展开一个节点不会加载无关子树。
- NodeId 筛选只影响已加载节点显示，不发起浏览任务。
- 选择 Variable 节点后，新建变量抽屉正确带入 NodeId、名称和数据类型。
- Object、Folder 节点不会打开变量抽屉。
- 刷新后从 Objects 根节点重新加载。
- Agent 离线、任务失败和空结果均有可理解的界面反馈。
- TypeScript 类型检查、目标 ESLint 和相关前端测试通过。
