# 数据中心 Kafka 工作台模式标签页改版设计

> 日期：2026-06-07  
> 范围：`datacenter/` Kafka 工作台的新建/编辑消费规则弹窗、右侧模式标签页、字段映射样例编辑器体验。  
> 目标：在不调整左侧规则树的前提下，降低 Kafka 消费规则配置复杂度，并让整包数据点与字段映射两种模式拥有清晰、不可混用的工作区。

## 1. 背景

当前 Kafka 工作台已经具备独立消费规则树、整包数据点模式、字段映射模式、短时拉取样本和字段映射 CRUD。现有问题集中在三个方面：

- 新建/编辑弹窗中的输出模式使用 segmented 控件，编辑时仍像可以切换模式，容易让用户误以为整包规则和字段规则可以互转。
- 整包数据点、字段映射、运行消费参数和测试样本参数混在同一弹窗内，首次创建时信息量偏大。
- 右侧 `KafkaInspectorPanel` 只是静态摘要，不能按整包或字段映射模式承载对应的测试、样本和映射辅助动作。

MQTT 工作台的交互可以作为参考，但 Kafka 不照搬 MQTT 的功能语义。Kafka 继续使用短时 reader 测试拉取，不引入 MQTT 的 preview session、socket 实时订阅、QoS 或数组拆分规则。

## 2. 成功标准

- 左侧 Kafka 消费规则树、分组、筛选、右键菜单和移动/删除交互保持现状。
- 新建消费规则时必须单选输出模式：整包数据点或字段映射。
- 编辑消费规则时复用新建弹窗结构，但输出模式只读或禁用，不允许切换。
- 如需更换输出模式，用户通过删除当前消费规则后重新创建实现。
- 右侧面板改为按消费规则打开的动态标签页，并且只存在两类模式标签页：整包数据点标签页、字段映射标签页。
- 整包数据点标签页集中提供整包样本测试拉取和样本预览。
- 字段映射标签页集中提供字段映射清单、样例编辑器、测试拉取填入样例、JSON 自动展平和保存映射。
- 字段映射第一版不支持数组拆分规则，不保存类似 MQTT batch parse rule 的配置。

## 3. 不做范围

- 不调整左侧消费规则树视觉、分组模型和右键菜单主流程。
- 不把 Kafka 工作台改成 MQTT 式实时订阅或长期消费器。
- 不新增 Kafka metadata、consumer lag、partition 详情等诊断型能力。
- 不实现数组拆分规则、JSONPath 规则编辑器或脚本解析规则。
- 不引入新的组件库或全局状态方案。
- 不为了模式切换做旧数据结构兼容分支。

## 4. 信息架构

Kafka 工作台仍然是左侧树、中间主区域、右侧面板结构。此次调整后的职责边界如下：

- 左侧树：管理消费规则和分组；提供新建、编辑、移动、删除、复制 Topic、打开规则等入口。
- 新建/编辑弹窗：创建或维护消费规则的基础配置；编辑态锁定输出模式。
- 中间主区域：保留现有模式主面板承载方式，不作为本次主要调整目标。
- 右侧面板：从静态 inspector 改为动态模式标签页容器，点击消费规则后按其输出模式打开或激活对应标签页。

右侧标签页 id 规则：

- 整包数据点：`kafka-raw-${mapping.id}`
- 字段映射：`kafka-fields-${mapping.id}`

同一个消费规则的同类标签页只打开一个。重复点击同一规则时激活已有标签页，并刷新当前 mapping 引用。

## 5. 消费规则弹窗

### 5.1 新建模式

新建弹窗保留 “新建消费规则” 标题。输出模式改为单选卡片或 radio group：

- 整包数据点：整条 Kafka 消息作为一个数据点输出。
- 字段映射：从 Kafka 消息 value 中提取字段，生成多个字段数据点。

新建时展示字段：

- 输出模式。
- 规则名称。
- Topic。
- 消费组名称。
- 描述。
- 当前模式的最小必要配置。
- 高级配置折叠区：分区策略、起始位置、起始 offset、消息解码、样本上限、预览超时。

整包数据点模式额外展示：

- 输出内容：消息体 payload/value 或完整消息。
- 数据点名称：默认使用消费规则名称。
- 数据点路径：默认自动生成，可放在高级项或编辑态中允许覆盖。

字段映射模式额外展示：

- 简短提示：保存后在字段映射标签页中粘贴样例或测试拉取样本，解析字段并保存映射。
- 不在弹窗内展示字段映射表格或样例编辑器。

### 5.2 编辑模式

编辑弹窗复用新建弹窗结构，标题为 “编辑消费规则”。编辑态输出模式只读展示或禁用，并显示提示：输出模式创建后不可修改；如需切换模式，请删除后重新创建消费规则。

编辑态允许修改：

- 规则名称。
- Topic。
- 消费组名称。
- 所属分组。
- 分区策略。
- 起始位置。
- 起始 offset。
- 消息解码。
- 样本上限。
- 预览超时。
- 描述。
- 整包数据点模式下的输出内容和数据点路径策略。

编辑态不允许修改：

- 输出模式。
- 由输出模式决定的数据点结构类型。

## 6. 右侧模式标签页

右侧面板不再是固定摘要块，也不拆成“配置/测试/诊断”固定标签，而是动态打开两类模式标签页。

### 6.1 整包数据点标签页

打开条件：点击或打开 `outputMode = raw_message` 的消费规则。

职责：

- 展示规则摘要：名称、Topic、消费组、分区、起始位置、解码。
- 展示数据点信息：数据点名称、数据点路径、输出内容。
- 触发短时测试拉取。
- 展示最近拉取样本。

主要操作：

- 测试拉取。
- 复制 Topic。
- 复制 Payload。
- 清空样本。
- 刷新当前标签页数据。

样本展示内容：

- payload/value。
- key。
- headers。
- partition。
- offset。
- timestamp。

整包标签页不负责编辑规则基础配置。规则编辑仍通过左侧树右键 “编辑规则” 打开弹窗完成。

### 6.2 字段映射标签页

打开条件：点击或打开 `outputMode = field_mapping` 的消费规则。

职责：

- 展示字段映射清单。
- 管理字段映射增删改、启停、分组筛选和分页。
- 提供样例编辑器辅助创建字段映射。
- 触发短时测试拉取，并把最近样本填入样例编辑器。
- 基于样例自动展平 JSON 字段，生成候选映射。

字段映射清单列：

- 选择框。
- 映射名称。
- 字段路径。
- 数据类型。
- 样例值。
- 输出数据点。
- 最近测试值。
- 状态。
- 操作。

样例编辑器交互参考 MQTT 批量映射编辑器，但只保留 Kafka 需要的部分：

- 编辑器可以展开/收起。
- 使用 MonacoEditor，语言为 JSON。
- 支持粘贴 JSON。
- 支持格式化 JSON。
- 支持用最近测试拉取样本填入编辑器。
- 支持解析字段。

解析行为：

- 只解析 Kafka 消息 `value`。
- 如果样本是 Kafka 完整消息对象，优先取其中 `value` 作为字段根。
- 如果 `value` 是 JSON 字符串，先尝试 JSON.parse。
- 对普通对象递归展平字段。
- 对数组按普通路径处理，例如 `items.0.value`，但不提供数组拆分规则。
- 已存在字段路径标记为已存在，不重复批量创建。

保存行为：

- 用户可勾选候选字段。
- 用户可在表格中调整映射名称和数据类型。
- 点击保存映射后，调用现有批量创建字段映射接口。
- 保存成功后刷新字段映射清单和数据点状态。

## 7. 数据与接口影响

第一版优先复用现有 Kafka 工作台接口：

- `GET /api/v1/data/projects/{projectId}/kafka/sources/{connectionId}/topic-mappings`
- `POST /api/v1/data/projects/{projectId}/kafka/sources/{connectionId}/topic-mappings`
- `PUT /api/v1/data/projects/{projectId}/kafka/topic-mappings/{mappingId}`
- `POST /api/v1/data/projects/{projectId}/kafka/topic-mappings/{mappingId}/preview`
- `GET /api/v1/data/projects/{projectId}/kafka/topic-mappings/{mappingId}/fields`
- `POST /api/v1/data/projects/{projectId}/kafka/topic-mappings/{mappingId}/fields`
- `POST /api/v1/data/projects/{projectId}/kafka/topic-mappings/{mappingId}/fields/batch`

后端需要校验：

- 创建消费规则时 `outputMode` 必须为 `raw_message` 或 `field_mapping`。
- 更新消费规则时不允许修改已有 `outputMode`。
- 指定 offset 时仍要求单分区和非负 offset。
- 数据库操作保持参数化查询。

整包数据点名称默认使用消费规则名称。若系统仍需要内部路径，则路径继续按现有规则自动生成，避免用户在新建阶段必须理解路径细节。

## 8. 组件调整建议

### 8.1 `KafkaTopicMappingDialog.vue`

- 输出模式从 segmented 改为单选卡片或 radio group。
- 编辑态禁用输出模式。
- 新建态按模式显示专属提示和最小配置。
- 运行消费与样本参数改为高级配置折叠区。
- 整包数据点名称默认跟随规则名称。

### 8.2 `KafkaWorkbench.vue`

- 左侧树和右键菜单保持现有交互。
- 选择 mapping 后，根据 `outputMode` 打开或激活右侧模式标签页。
- 管理右侧标签页列表、激活项和关闭行为。
- 测试拉取样本统一回写到对应 mapping 的样本缓存。

### 8.3 `KafkaInspectorPanel.vue`

- 从静态 inspector 改造为右侧模式标签页容器。
- 接收当前 connection、mapping、samples、preview 状态。
- 对外抛出测试拉取、样本变更、字段映射保存等事件。

### 8.4 `KafkaRawOutputPanel.vue`

- 可继续复用整包样本展示逻辑。
- 作为右侧整包数据点标签页的主体能力来源。
- 去掉规则编辑入口，只保留测试和样本操作。

### 8.5 `KafkaFieldMappingPanel.vue`

- 参考 `MqttBatchMappingPanel.vue` 的清单 + 可收起编辑器交互。
- 保留 Kafka 字段映射现有 CRUD、分组、分页能力。
- 将当前 “粘贴样本” 弹窗升级为嵌入式 JSON 样例编辑器。
- 删除数组拆分规则相关设计，只保留 JSON 自动展平。

## 9. 错误处理

- JSON 样例解析失败：在字段映射标签页内展示错误，不清空已有映射清单。
- 测试拉取失败：在当前模式标签页展示失败原因，并保留上一次成功样本。
- 样本为空：展示空态，提示可调整样本上限、超时或起始位置后重试。
- 保存字段映射失败：保留候选字段选择和编辑器内容，展示后端错误。
- 删除消费规则后：关闭对应右侧模式标签页，并清理样本缓存。
- 切换接入源后：清空右侧标签页、样本缓存和当前选择。

## 10. 验证

静态验证：

- `pnpm --filter datacenter typecheck`
- 如修改 data_service 校验逻辑，运行最贴近的 Go 测试。

人工验收：

1. 新建整包数据点消费规则，确认模式单选、保存后打开右侧整包标签页。
2. 编辑整包规则，确认输出模式不可修改，其它配置可编辑。
3. 整包标签页执行测试拉取，确认样本展示、复制和清空可用。
4. 新建字段映射消费规则，确认保存后打开右侧字段映射标签页。
5. 字段映射标签页粘贴 JSON，点击解析字段，确认生成候选字段。
6. 勾选候选字段并保存，确认字段映射和数据点状态刷新。
7. 字段映射标签页执行测试拉取，确认最近样本可填入样例编辑器。
8. 删除消费规则，确认对应右侧标签页关闭。

## 11. 风险与控制

- 右侧面板职责膨胀风险：只允许两类模式标签页，不增加诊断、metadata、lag 等独立标签页。
- 字段映射编辑器复杂化风险：第一版只做 JSON 自动展平，不做数组拆分、JSONPath 规则或脚本解析。
- 输出模式修改导致数据点混乱风险：编辑态禁止修改 `outputMode`，切换模式只能删除后新建。
- 样本解析不稳定风险：样本只用于辅助生成候选字段，最终运行仍以用户保存的字段映射为准。
- MQTT 交互照搬风险：只参考清单、工具栏、右侧编辑器和状态视觉，不复用 MQTT 实时订阅语义。
