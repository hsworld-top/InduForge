# 工业采集驱动目录全量加载设计

## 目标

工业采集连接向导加载完整驱动目录，通过现有可滚动驱动树展示全部驱动，不向用户提供分页控件。

## 方案

- 保留 Data Service 驱动目录接口现有分页契约和每页最多 100 条的限制。
- Datacenter 先请求第一页，根据响应中的 `totalPages` 并行请求剩余页。
- 客户端按页码顺序合并结果，保证驱动目录排序稳定。
- 连接向导使用合并后的完整目录，现有搜索、分组和滚动布局保持不变。
- 任意一页请求失败时整次加载失败，不展示不完整目录，继续使用现有错误提示。

## 验证

- 使用两页共 115 条模拟数据，验证全部结果均被返回且顺序稳定。
- 运行 Datacenter 单元测试、TypeScript 类型检查和生产构建。

## 不包含

- 不修改 Data Service API 或分页响应结构。
- 不调整连接向导视觉布局。
- 不增加虚拟滚动；当前 115 条静态协议目录不需要额外复杂度。
