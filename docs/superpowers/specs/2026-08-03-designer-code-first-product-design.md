# Designer 工业应用设计中心产品设计

## 1. 文档状态

- 日期：2026-08-06
- 状态：已确认
- 适用模块：`designer`、`dev_core`、`dev_ide`、`data_service`、工程运行时
- 目标：定义下一代 Designer 的最终产品形态和跨模块边界
- 旧版备份：远端分支 `拖拉拽版本Designer`

本文替代此前以 Monaco 和细粒度文件 API 为核心的源码工作台方案。Designer 不再自研通用代码编辑器，也不保留普通页面拖拽低代码模式，而是由工程级共享 `code-server`、HT 2D 编辑器、HT 3D 场景编辑器和 HT 3D 模型编辑器共同组成应用设计中心。

项目处于开发初期，不保留旧页面 Schema、旧物料体系、双编辑模式或旧接口兼容逻辑。具体代码删除、模块重建和接口调整在本设计获得书面确认后另行编写实施计划。

## 2. 产品定位

Designer 是工程内部的工业应用设计中心，不是平台外层工程 IDE。

Designer 只包含四个一级工作区：

1. **代码中心**：工程级共享 `code-server`，用于 Vue 3 + JavaScript 应用开发。
2. **2D 编辑器**：用于 HMI、工业大屏、工艺流程和设备拓扑。
3. **3D 场景编辑器**：用于数字孪生场景编排。
4. **3D 模型编辑器**：用于三维模型和材质资源维护。

3D 场景与 3D 模型共用同一套 HT 3D 内核和工程资源目录，只通过工作区入口决定默认聚焦场景库或模型库，不复制两套编辑器和资源数据。

`dev_ide` 继续负责工程创建、工程归属、平台用户、节点、部署、发布和运维。Designer 负责工程内部前端应用内容的设计、预览、检查和构建。

## 3. 产品目标

- 普通页面全部使用标准 Vue 3 与 JavaScript，源码是唯一事实。
- 客户不需要编写 TypeScript。
- Designer 不自研代码编辑器、扩展市场或开发工具管理体系。
- 2D、3D 保留专业可视化编辑能力，不要求客户手写场景内部结构。
- 工程角色、权限、数据点和场景公开接口自动输出为只读开发上下文。
- 用户和其自行选择的开发工具通过工作区文件了解平台接口。
- 平台只关心容器挂载目录、共享开发环境和用户产生的工程文件。
- 用户自行安装的扩展、CLI 和其他开发工具不属于 Designer 产品能力。
- Designer 构建不可修改的应用版本，`dev_ide` 负责部署和运维。

## 4. 不采用的方案

### 4.1 普通页面拖拽低代码

不再维护通用物料、属性面板、页面画布和普通页面 Schema。复杂业务最终仍需编码，拖拽模式会与源码形成两套事实，并增加长期维护成本。

### 4.2 普通页面双模式

不允许同一个工程同时存在“拖拽普通页面”和“源码普通页面”。双模式会让路由、组件、预览、发布和维护方式长期分叉。

### 4.3 自研 Monaco 代码工作台

不再自研文件树、代码标签、终端、调试和扩展系统。上述能力统一交给 `code-server`。

### 4.4 官方 VS Code Server 托管

Designer 不托管微软官方 VS Code Server，也不依赖微软 Marketplace。代码中心采用可自托管的 `code-server`。

## 5. 模块职责

### 5.1 `dev_ide`

负责：

- 工程创建、归属和生命周期管理。
- 平台用户和平台权限。
- 节点、机器和站点管理。
- 应用版本选择。
- 在线部署、离线打包、安装、升级和运维。
- 受控 npm 依赖仓库和离线依赖交付。

### 5.2 Designer

负责：

- 提供代码、2D、3D 场景、3D 模型四个设计入口。
- 展示共享开发环境状态和在线开发人员。
- 管理 2D、3D 场景设计体验。
- 提供 Vue 页面、2D、3D 的统一预览。
- 显示数据点调用结果和错误。
- 发起上下文刷新、构建检查和应用版本构建。

Designer 前端不直接查询数据库，不在浏览器中批量生成上下文文件，也不负责启动 Docker 容器。

### 5.3 `dev_core`

负责：

- 工程工作空间初始化和持久化。
- 工程级 `code-server` 容器生命周期。
- 校验代码中心访问权限并返回开发态映射端口。
- 在线开发人员会话记录。
- 工程角色和权限机器契约。
- 聚合数据点、2D、3D 机器契约。
- 生成和同步工程上下文包。
- 创建一致的源码快照。
- 调度独立构建容器并生成应用版本。

### 5.4 `data_service`

负责：

- 数据点定义的唯一事实来源。
- 输出面向开发的统一数据点机器契约。
- 提供工程级全量契约快照和契约版本。
- 后续按实际性能需要提供增量变更清单。
- 在预览和运行时执行数据点调用、权限校验和参数校验。

`dev_core` 不直接读取数据中心数据库表，必须通过 `data_service` 的正式服务接口获取数据点契约。

### 5.5 HT 2D、3D 场景与 3D 模型编辑器

各自负责：

- 场景内部编辑结构和资源管理。
- 保存场景源码。
- 输出稳定的场景公开机器契约。
- 声明场景输入、事件、命令、公开对象、数据点引用和权限引用。

`dev_core` 不解析 HT 内部画布格式，只负责工程目录隔离、文件读写、权限校验和公开机器契约聚合。

HT 编辑器迁移以源码目录 `E:\personal_dev\test\kf\kingdevopscenter\kingclient\exe\public\javascripts\HT3DEditor` 为唯一实现基线，不依赖旧发布包或旧 Node `kingtopo` 服务。Designer 内置静态资源保留 HT 客户端和自定义扩展，文件服务改由 `dev_core` 的 `/api/v1` REST 接口提供。

## 6. 工程资源模型

一个 Designer 工程包含：

1. Vue 页面与公共组件。
2. JavaScript 路由和菜单源码。
3. 工程级 JavaScript 工具和动作。
4. 2D 场景源码。
5. 3D 场景源码。
6. 3D 模型和材质源码。
7. 图片、SVG、字体、贴图和其他工程素材。
8. npm 依赖和锁文件。
9. 平台生成的只读工程上下文。

数据点和工程运行角色不是 Designer 可编辑资源。Designer 只消费它们的开发契约。

## 7. 代码中心

### 7.1 底座

代码中心采用开源 `code-server`。一个工程对应一个共享 `code-server` 容器，一个容器只运行一个 `code-server` 主进程。

所有拥有工程代码开发权限的人员进入同一个工程容器，使用同一份源码、扩展、配置、依赖、终端环境和开发服务。

### 7.2 客户代码语言

- Vue 3 单文件组件。
- JavaScript。
- 默认 `<script setup>`。
- 不生成 `lang="ts"`。
- 可以通过隐藏 `.d.ts` 或 JSDoc 为 JavaScript 提供编辑提示。
- 隐藏声明文件不属于客户需要维护的 TypeScript 源码。

### 7.3 源码事实

- 工作空间文件系统是 Vue 源码唯一事实。
- 路由 JavaScript 源码是路由唯一事实。
- Designer 的页面树是路由源码的可视化投影，不保存第二套路由配置。
- 页面、2D、3D 统一进入同一路由体系。
- 完整工程源码允许导出和导入。
- 第一版不提供外部目录实时双向同步。

### 7.4 多人共享开发

- 多人可以同时进入同一工程代码中心。
- 平台只显示当前在线开发人员和共享开发提示，不解析或追踪 `code-server` 内正在打开的文件。
- 不实现实时光标、CRDT、文件锁、自动合并或冲突解决。
- 同一文件或场景以最后一次成功保存的内容为准。
- 平台提示其他人员正在编辑，但不阻止保存。
- 平台不承诺恢复被其他人员覆盖的源码。
- 客户可以自行在共享环境中使用 Git 或其他版本管理工具。

代码、2D 和 3D 均采用相同的最后保存生效规则。

### 7.5 用户自主管理开发工具

- 工程代码开发人员可以在 `code-server` 容器内自行安装扩展、CLI 和其他开发工具。
- 平台不识别、不审批、不推荐、不限制具体工具，也不承诺兼容性。
- 工程成员共同使用一个 `code-server` 环境，IDE 状态和共享配置对工程成员共同生效。
- 平台只保证约定持久化挂载中的内容，不保证容器可写层中的安装结果。
- 容器因镜像升级或故障重建后，未写入持久化挂载的工具和配置允许丢失。
- 工程必须长期依赖的工具应通过 `package.json`、锁文件、项目脚本或工作空间配置声明，而不是依赖人工修改容器系统环境。

### 7.6 挂载目录与开发产物

工程容器只向平台承诺以下挂载：

```text
/workspace                              # 工程源码，可读写
/workspace/.induforge/context           # 平台开发上下文，只读
/home/coder/.local/share/code-server    # IDE 状态，可读写
/home/coder/.config/code-server         # IDE 配置，可读写
/cache                                  # 开发缓存，可读写、可清理
```

平台认定的工程开发产物只包括 `/workspace` 中的：

- Vue 页面、公共组件和 JavaScript 代码。
- 路由和菜单源码。
- 2D、3D 场景源码及其公开契约源数据。
- 图片、字体、三维模型和其他工程素材。
- `package.json`、`pnpm-lock.yaml` 和工程配置。
- 用户通过开发工具生成并保存到工程目录的其他源码文件。

以下内容不属于工程发布产物：

- `code-server` 扩展、登录信息和 IDE 设置。
- 容器系统层中安装的工具。
- `node_modules`、pnpm、Vite 和临时构建缓存。
- 开发服务器进程、终端历史和临时日志。
- `.induforge/context/` 开发文档。

正式构建只读取工作空间快照中允许进入 Release 的工程文件。

### 7.7 访问控制

- 开发阶段 `code-server` 使用宿主机映射端口，`dev_core` 校验权限后返回访问地址。
- Designer 使用 iframe 直接打开映射端口，不通过 `dev_core` 转发 HTTP、静态资源或 WebSocket。
- 前端只向具有工程操作权限的用户展示并请求代码中心入口。
- 普通工程运行用户不能进入代码中心。
- 代码开发人员视为工程开发环境内的同一信任域。

### 7.8 容器隔离

工程容器不得挂载：

- 宿主机 Docker Socket。
- 其他工程工作空间。
- 平台数据库文件或数据库管理凭据。
- 平台根目录和平台 `.env`。
- 其他工程密钥。

工程容器必须使用非 root 用户运行，并设置工程级 CPU、内存、磁盘、进程数和网络边界。

## 8. code-server 容器生命周期

### 8.1 工程创建

新建工程时创建：

- 工程源码工作空间。
- IDE 状态持久化目录。
- 开发缓存目录。
- 上下文生成状态记录。

新建工程时不立即创建或启动 `code-server` 容器。

### 8.2 首次进入

第一名用户进入代码中心时：

1. `dev_core` 校验工程开发权限。
2. 检查工程容器是否存在。
3. 不存在时使用当前工作空间镜像创建容器。
4. 挂载工程持久化目录。
5. 启动 `code-server`。
6. 健康检查通过后返回开发态映射端口。

### 8.3 空闲停止

- 有开发人员在线时保持运行。
- 最后一名开发人员离开后开始空闲计时。
- 默认空闲 30 分钟停止容器，平台可以统一调整该时间。
- 停止容器不删除工作空间、扩展、设置和缓存。
- 下次进入时重新启动原容器。

### 8.4 镜像升级

`code-server`、Node.js、pnpm 或基础工具升级时：

1. 停止旧容器。
2. 使用新镜像重新创建容器。
3. 重新挂载原有持久化目录。
4. 完成健康检查后恢复访问。

基础镜像可替换，客户源码和 IDE 状态不写入容器可写层。

镜像升级或容器重建只承诺恢复约定的持久化挂载。用户自行安装到容器系统目录或其他未挂载路径的工具允许丢失，平台不负责迁移。

### 8.5 持久化目录

逻辑结构如下：

```text
projects/{projectId}/
├─ workspace/
├─ code-server-data/
├─ code-server-config/
├─ cache/
└─ context-state/
```

- `workspace/`：Vue、路由、2D、3D、素材和依赖声明。
- `code-server-data/`：扩展、编辑器状态和用户数据。
- `code-server-config/`：共享的 `code-server` 配置。
- `cache/`：pnpm store、Vite 和其他临时开发缓存；工作空间内的 `node_modules/` 通过构建过滤排除。
- `context-state/`：上下文版本、生成状态和临时文件。

## 9. 工程上下文包

### 9.1 定位

工程上下文包是数据库和场景机器契约在代码工作空间中的只读开发镜像，正式名称为：

> InduForge 工程上下文包（Workspace Context Pack）

它帮助开发人员和其自行选择的代码工具理解工程，但不是新的事实来源，也不能通过修改文件反向更新数据库或场景。

### 9.2 数据来源

上下文包聚合：

1. `dev_core` 的工程基础信息。
2. `dev_core` 的工程运行角色和权限。
3. `data_service` 的全部工程数据点开发契约。
4. 2D 编辑器输出的全部 2D 场景公开契约。
5. 3D 编辑器输出的全部 3D 场景公开契约。
6. 当前工程使用的运行时 SDK 版本和使用规则。

上下文包不包含平台管理角色、具体运行用户名、用户角色绑定、密码、Token、真实生产值、SQL 内容、数据库连接或平台内部密钥。

### 9.3 生成职责

`dev_core` 内部按职责拆分：

- `ProjectDevelopmentContractService`：聚合机器契约。
- `ContextPackBuilder`：生成 Markdown、索引、清单和编辑提示。
- `WorkspaceContextSyncService`：校验版本并原子写入工作空间。

数据点和 HT 场景各自输出稳定机器契约，`dev_core` 不读取其数据库内部结构或私有编辑 Schema。

### 9.4 工作区结构

```text
.induforge/
├─ context/
│  ├─ README.md
│  ├─ manifest.json
│  ├─ project/
│  │  ├─ overview.md
│  │  ├─ development-rules.md
│  │  └─ runtime-api.md
│  ├─ authorization/
│  │  ├─ roles.md
│  │  ├─ permissions.md
│  │  └─ usage.md
│  ├─ points/
│  │  ├─ README.md
│  │  ├─ manifest.json
│  │  ├─ index/
│  │  └─ catalog/
│  └─ scenes/
│     ├─ README.md
│     ├─ index.md
│     ├─ 2d/
│     └─ 3d/
└─ types/
   └─ induforge-runtime.d.ts
```

上下文根目录提供统一 `README.md`，说明工程规则、目录结构和契约查找方式，不生成面向特定开发工具的专用配置。

### 9.5 全量数据点

- 输出当前工程有权查看的全部数据点契约。
- 全量保存到磁盘不等于一次打开全部内容。
- 开发人员或代码工具先搜索简要索引，再按需读取详情分片。
- 数据点数量按 10 万级设计。
- 不生成单个巨大 Markdown 文件。
- 不无条件为每个数据点创建一个独立文件。
- 索引和详情按文件大小分片，单个分片保持在可搜索和可读取范围内。
- 不把所有数据点 ID 生成成巨大的 `.d.ts` 字符串联合类型。

数据点详情包含：

- 稳定数据点 ID。
- 名称和业务说明。
- 实际存在的 `get`、`set`、`sub`、`pub` 方法。
- 参数、值、事件和结果 Schema。
- 错误说明。
- JavaScript 调用示例。
- 契约版本和更新时间。

方法存在即代表能力，不额外增加 `kind` 或重复的 `capabilities`。

### 9.6 工程角色权限

上下文包输出工程运行角色和权限定义，包括：

- 角色代码、名称和说明。
- 权限代码、名称和说明。
- 角色与权限关系。
- 当前用户查询 API。
- 角色和权限判断 API。
- 路由、按钮和组件权限示例。

上下文包不输出具体用户名及其角色归属。页面运行时通过 SDK 获取当前登录用户和实际有效权限。

### 9.7 场景上下文

2D、3D 场景上下文输出：

- 场景 ID、类型、名称和说明。
- 场景路由和嵌入方式。
- 对外输入。
- 对外事件。
- 对外命令。
- 显式公开的语义对象。
- 数据点引用。
- 权限引用。
- 场景契约版本。

不输出：

- 完整内部画布 Schema。
- 装饰节点和临时节点。
- 每个图形的坐标和样式细节。
- 3D 顶点、材质、纹理和二进制模型内容。
- 撤销重做历史和编辑器临时状态。

Vue 代码可以使用、嵌入和控制场景公开接口，但不能直接修改 2D、3D 内部场景源码。

### 9.8 同步时机

上下文在以下时机刷新：

- 首次打开工程工作空间。
- 用户点击“刷新工程上下文”。
- 数据点契约版本变化。
- 工程角色或权限变化。
- 2D、3D 场景保存、重命名或删除。
- 场景公开输入、事件、命令、对象或绑定变化。

场景拖动、缩放和旋转过程不触发上下文刷新，以场景成功保存为边界。

同步采用临时目录生成、完整性校验和原子替换。同步失败时保留上一份完整上下文并显示“已过期”状态，不用半成品覆盖旧版本。

### 9.9 开发使用边界

- 上下文包只提供开发契约，不提供真实生产数据。
- 上下文文件不能调用、创建或修改数据点、SQL 和数据源。
- 代码中心通过稳定 SDK 使用数据点、权限和场景公开接口。
- 真实调用、权限校验和运行效果由预览及运行时负责。
- 2D、3D 内部场景结构只能由对应专业编辑器维护。

## 10. 运行时 SDK

### 10.1 定位

运行时 SDK 是稳定、版本化的通用 JavaScript 包，不根据工程数据库动态生成。

示意包名：

```js
import { points, projectAuth } from '@induforge/runtime'
```

最终包名在实施计划中按现有包命名规则确定，但必须保持单一事实和固定版本。

### 10.2 Points SDK

数据点统一通过稳定 `pointId` 使用：

```js
const ordersPoint = points.point('production.orders')

const result = await ordersPoint.get({
  workshopId: 'A01',
  page: 1,
  pageSize: 20,
})
```

`get` 使用具名参数对象，可以覆盖当前值、参数化 SQL、分页、历史和统计等数据点定义。

订阅示例：

```js
const unsubscribe = ordersPoint.sub({ workshopId: 'A01', status: 'running' }, (event) => {
  // 页面处理订阅结果
})
```

Designer 不根据数据点底层 SQL、协议或存储方式生成不同 API。

### 10.3 权限 SDK

权限 SDK 至少支持：

- 获取当前运行用户。
- 判断角色。
- 判断权限。
- 路由进入前的权限判断。
- 页面组件和操作按钮权限判断。

权限文档只帮助开发，最终权限必须由运行时后端执行校验。

### 10.4 场景 SDK

场景运行能力至少支持：

- 通过稳定 `sceneId` 打开独立场景。
- 在 Vue 页面中嵌入 2D 或 3D 场景。
- 向场景传入公开输入。
- 监听场景公开事件。
- 调用场景公开命令。
- 操作显式公开的语义对象。

SDK 不暴露编辑器内部画布节点和私有 Schema。

## 11. 预览与调试

### 11.1 统一预览

Designer 提供：

- Vue 页面预览。
- 2D 场景预览。
- 3D 场景预览。
- 完整应用路由预览。

开发预览可以运行在工程 `code-server` 容器中。预览入口由 `dev_core` 通过工程权限代理，不直接暴露任意容器端口。

### 11.2 数据点调用面板

预览提供统一数据点调用调试信息：

- 数据点 ID。
- 调用方法。
- 调用参数。
- 成功或失败状态。
- 调用耗时。
- 返回结构摘要。
- 后端错误信息和请求 ID。

Vue、2D、3D 共用同一套调试机制。开发人员根据预览结果修改代码或场景。

## 12. 构建与发布

### 12.1 开发容器与构建容器分离

工程 `code-server` 容器是可变的共享开发环境，不能作为正式构建环境。

正式构建流程：

1. `dev_core` 创建工作空间只读快照。
2. 快照生成确定的内容哈希。
3. 如果快照期间检测到文件变化，则重新生成快照。
4. 启动一次性干净构建容器。
5. 按锁文件和受控依赖源安装依赖。
6. 执行检查和生产构建。
7. 生成不可修改的应用版本。
8. 销毁一次性构建容器。

### 12.2 发布边界

- Designer 负责生成应用版本。
- 应用版本记录源码快照哈希、SDK 版本、依赖锁和构建信息。
- `dev_ide` 负责选择版本并执行部署。
- 运行站点使用 Release 内的静态应用和运行契约，不在线查询中心数据库。
- `.induforge/context/*.md`、`code-server-data` 和开发缓存不进入正式应用 Release。

## 13. 一致性与失败处理

### 13.1 多人保存

- 单次文件或场景保存必须完整写入。
- 最后一次成功保存生效。
- 平台不做内容级冲突处理。
- 保存失败必须明确返回错误，不得显示为成功。

### 13.2 上下文同步失败

- 保留上一份完整上下文。
- 标记当前上下文已过期。
- 展示失败来源和请求 ID。
- 不允许半生成目录替换旧目录。

### 13.3 容器启动失败

- 显示镜像、挂载、健康检查或资源不足的明确错误。
- 不进入空白代码中心。
- 允许有权限用户重试启动或重建容器。
- 重建容器不得删除工作空间和 IDE 状态。

### 13.4 预览失败

- 区分源码编译错误、数据点错误、权限错误和运行时错误。
- 页面、2D、3D 使用统一错误展示规则。
- 后端错误保留标准 `code`、`msg`、`data`、`reqId` 响应契约。

## 14. 第一阶段范围

第一阶段包含：

- Designer 四工作区产品壳层。
- 工程级 `code-server` 容器管理。
- 共享工作空间、IDE 状态和缓存持久化。
- 多人在线提示和最后保存生效规则。
- 明确挂载目录、持久化边界和工程开发产物边界。
- 标准 Vue 3 + JavaScript 工程模板。
- 运行时 SDK 基础接口。
- 工程上下文包生成和同步。
- 数据点全量分片文档。
- 工程角色权限文档。
- 2D、3D 场景和 3D 模型公开契约文档。
- Vue、2D、3D 场景和 3D 模型统一预览基础。
- 独立快照构建容器。

第一阶段不包含：

- 普通页面拖拽低代码。
- 自研 Monaco 编辑器。
- 平台开发工具商店、扩展审批和扩展兼容管理。
- 平台对用户自行安装工具的功能承诺。
- 容器系统可写层中工具和配置的迁移保证。
- 多人实时协同光标或自动合并。
- 通过普通代码直接编辑 2D、3D 内部场景结构。
- 每用户独立工作空间或 Git worktree。

## 15. 验收标准

满足以下条件时，本产品设计视为实现：

1. 新建工程只初始化工作空间，首次进入代码中心才创建工程 `code-server` 容器。
2. 多名工程师可以同时进入同一工程代码中心并修改同一工作空间。
3. Designer 明确提示当前在线开发人员和最后保存生效规则。
4. 工作空间和 IDE 状态挂载在容器停止后保留，未挂载的容器系统修改在重建后允许丢失。
5. 工程容器无法访问其他工程、宿主机 Docker Socket 和平台密钥。
6. 客户使用 Vue 3 + JavaScript 编写普通页面，不需要维护 TypeScript。
7. 路由源码是唯一事实，Vue、2D、3D 进入统一路由体系。
8. 数据中心可以输出工程全部数据点的稳定开发契约和契约版本。
9. `dev_core` 可以生成工程、角色、数据点、2D、3D 的完整上下文包。
10. 开发人员能够从挂载的工作区文件找到正确的数据点、权限和场景公开接口。
11. 上下文包不包含真实生产数据，也不能反向修改数据库和场景。
12. 用户可以通过预览查看真实数据点调用和错误。
13. 2D、3D 场景保存后，其公开契约自动更新到工作区上下文。
14. 正式构建只读取认可的工程开发产物，不读取 IDE 状态、缓存和容器系统层。
15. 正式构建使用只读源码快照和独立干净构建容器。
16. Designer 生成应用版本，`dev_ide` 完成部署和运维。
