# InduForge 前端工作台 UI 设计规范

本文档基于 `dev_ide` 工程管理界面沉淀，用于后续 `designer`、`datacenter` 与其他管理类前端保持一致的产品气质、布局密度和交互语言。当前规范优先描述已经在 `dev_ide` 中验证过的界面风格，不包含待评估的改版建议。

## 1. 设计定位

InduForge 的工作台界面服务于平台管理、工程入口、运维状态和数据协作场景。用户通常在桌面浏览器中连续处理项目、部署、节点、日志和配置任务，因此 UI 应保持稳定、紧凑、可扫描，避免营销化、装饰化或过度动效。

核心气质：

- 专业克制：以中性色和低饱和蓝色为主，强调任务本身。
- 工具感明确：导航、筛选、表格、卡片、分页、弹窗都使用熟悉结构。
- 信息密度适中：一屏内承载足够多的项目和状态，但不牺牲可读性。
- 轻量层次：通过边框、半透明面板、细阴影和间距建立层级。
- 多端一致：桌面优先，窄屏下允许工具栏换行、网格降列、底部区域纵向堆叠。

## 3. 视觉原则

### 3.1 产品型界面，不做落地页

后台、设计器、数据中心的首屏应直接进入可操作界面。不要使用大标题营销区、装饰插画、铺满屏幕的价值主张或宣传型分屏布局。

### 3.2 结构优先于装饰

优先使用稳定结构表达层级：

- 外层工作台：页面容器、工具栏、内容区、底部分页。
- 中层信息承载：表格、卡片网格、状态面板、配置面板。
- 内层状态表达：标签、徽标、节点 chip、时间文本、图标按钮。

装饰性渐变、玻璃模糊和浮动阴影只用于关键入口或主操作，不作为普通信息块的默认样式。

### 3.3 图标优先，文字精简

高频工具按钮优先使用图标加 tooltip，例如新增、刷新、导入、分组、设置、删除。长文本按钮只用于确认、取消、保存、应用筛选等明确命令。

### 3.4 状态必须可被扫描

运行模式、部署状态、可见性、选择状态、加载状态、空状态、错误状态都要有稳定位置和稳定视觉词汇。不要只依赖颜色表达状态，应配合文本、标签或图标。

## 4. 设计 Token

### 4.1 品牌与强调色

以 `--ck-*` 作为工作台主 token 命名空间：

| 角色 | Token | 浅色值 | 深色值 | 使用场景 |
| --- | --- | --- | --- | --- |
| 主色 | `--ck-primary` | `#1d4ed8` | `#3b82f6` | 主操作、选中态、链接、聚焦边框 |
| 主色悬停 | `--ck-primary-hover` | `#1e40af` | `#2563eb` | 主操作 hover |
| 主色弱背景 | `--ck-primary-light` | `rgba(29, 78, 216, 0.12)` | `rgba(59, 130, 246, 0.15)` | focus ring、选中弱底、轻提示 |
| 辅助强调 | `--ck-accent` | `#0ea5a5` | `#14b8a6` | 主渐变第二端、少量强调 |
| 成功 | `--ck-success` | `#22c55e` | 同浅色 | 运行中、成功反馈 |
| 警告 | `--ck-warning` | `#f59e0b` | 同浅色 | 部署中、待处理 |
| 危险 | `--ck-danger` | `#ef4444` | 同浅色 | 删除、错误、失败 |

使用约束：

- 主色用于当前选择、主入口、链接和聚焦，不用于大面积背景装饰。
- 危险色只用于危险操作和错误状态，不用于普通强调。
- 辅助强调色应克制使用，避免整套系统变成高饱和蓝绿渐变主题。

## 5. 字体与排版

### 5.1 字体栈

中文产品界面默认使用：

```css
'Source Han Sans SC', 'PingFang SC', 'Microsoft YaHei', 'Helvetica Neue', sans-serif
```

时间、日志、版本号、技术标识可使用等宽字体：

```css
ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, 'Liberation Mono', 'Courier New', monospace
```

### 5.2 字号层级

| 层级 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面欢迎/重点标题 | `20px` | `700` | 仪表盘欢迎语、顶层重点 |
| 统计数字 | `32px` | `800` | 仪表盘统计值 |
| 面板标题 | `15px` | `700` | 面板 header |
| 工具栏标题 | `16px` | `700` | 管理页标题 |
| 项目名/表格重点 | `14px` | `600` | 项目卡片标题、主要链接 |
| 控件文本 | `13px` | `400-600` | 筛选、按钮、列表项 |
| 辅助文本 | `12px` | `400-600` | 标签、统计说明、按钮辅助 |
| 弱辅助文本 | `11px` | `400-600` | 节点标签、meta、更新时间 |
| 密集时间 | `10-12px` | `400` | 卡片底部时间、日志时间 |

排版要求：

- 不使用随视口变化的流式字号。
- 标题、按钮和标签不使用负字距。
- 卡片内文字必须可截断，避免撑破布局。
- 时间和日志类文本优先使用等宽字体提升扫描效率。

## 6. 工作台布局

### 6.1 页面骨架

管理类页面统一采用：

1. 外层 `.ck-workbench-page` 或同等结构。
2. 顶部工具栏 `.ck-workbench-toolbar`。
3. 主内容容器 `.ck-content-area`。
4. 可滚动内容 `.ck-content-scroll`。
5. 底部分页 `.ck-pagination-bar`。

推荐尺寸：

- 页面内边距：桌面 `16px`，窄屏 `12px` 或 `10px`。
- 工具栏 padding：`14px 16px`。
- 工具栏与内容区间距：`12px`。
- 内容区滚动内边距：`16px`。
- 分页栏 padding：`10px 16px`。
- 页面高度：桌面工作台可使用 `calc(100vh - 32px)`，并确保中间内容 `min-height: 0`。

### 6.2 导航与标签页

`dev_ide` 当前使用侧边抽屉加标签页工作区：

- 侧边栏宽度：`240px`。
- 菜单项高度：`40px`。
- 菜单图标：`20px`。
- 标签页高度：`36px`。
- 激活态使用蓝色弱背景和蓝色文本。
- 最大化标签页时隐藏侧边栏，顶部保留恢复入口。

`designer` 和 `datacenter` 若作为 `dev_ide` 子应用嵌入，应遵循宿主主题、语言和标签页状态，不在子应用内重复实现全局导航。

### 6.3 响应式

桌面端优先保持高效密度：

- 统计卡片：`repeat(auto-fit, minmax(220px, 1fr))`。
- 工程卡片：`repeat(auto-fill, minmax(min(100%, 340px), 1fr))`。
- 左右双栏：可用 `minmax(0, 1.25fr) minmax(360px, 0.75fr)`。

窄屏策略：

- 工具栏左右区块换行并铺满宽度。
- 搜索框、选择器在窄屏下宽度为 `100%`。
- 卡片网格降为单列。
- 底部分页从横排改为纵向堆叠。
- 复杂表格在窄屏下优先保留横向滚动或切换为卡片视图。

## 7. 组件规范

### 7.1 工具栏

工具栏是每个工作台页面的任务控制中心，应包含搜索、视图切换、筛选、排序、批量操作和主操作。

视觉：

- 背景：`--ck-bg-card`。
- 边框：`1px solid --ck-border`。
- 圆角：`--ck-radius-lg`。
- 阴影：`--ck-shadow-sm`。
- 支持 `backdrop-filter: blur(10px)`，但不能依赖模糊表达主要层级。

交互：

- 工具栏左侧放搜索、筛选、排序、视图切换。
- 工具栏右侧放新增、刷新、导入、设置、批量操作。
- 图标按钮尺寸统一 `32px * 32px`。
- 主操作按钮可使用 `--ck-gradient-primary`，同一工具栏中只保留一个主操作。
- 批量操作仅在有选择项时出现，减少常态干扰。

### 7.2 搜索框

搜索框用于快速过滤当前列表：

- 默认宽度：`176px` 左右。
- 高度：约 `32px`。
- 背景：`--ck-bg-tertiary`。
- 聚焦态：边框使用 `--ck-primary`，外圈使用 `0 0 0 3px --ck-primary-light`。
- 保留清空按钮。

### 7.3 视图切换

卡片/列表切换使用分段图标按钮：

- 外层弱底，圆角 `10px`，内边距 `3px`。
- 单个按钮 `32px * 32px`，圆角 `8px`。
- 激活态白底、主色图标、轻阴影。
- 深色模式下激活态使用深灰蓝底和浅色图标。

### 7.4 筛选与排序

筛选触发器使用 pill 按钮：

- 高度：`32px`。
- 圆角：`10px`。
- 字号：`13px`。
- 背景：浅色 `rgba(0, 0, 0, 0.04)`，深色 `rgba(255, 255, 255, 0.06)`。
- 有筛选条件时在按钮文案中显示数量，例如 `综合筛选 (2)`。

筛选面板：

- 宽度建议 `300px`。
- 圆角 `14px`。
- 阴影 `0 16px 36px rgba(15, 23, 42, 0.16)`。
- 每个筛选组有标题、选项 chip、底部重置和应用按钮。
- 选项可多选，复选框使用系统或组件库默认控件。

排序：

- 排序字段使用 popover 菜单。
- 排序方向使用单个 pill 按钮，通过图标和文本共同表达升序/降序。

### 7.5 项目卡片

项目卡片用于呈现工程入口和运行概览。

结构：

1. 顶部：选择框、项目名、可见性按钮。
2. 描述：最多两行，弱背景承载。
3. 运行模式：单行状态。
4. 部署状态：状态标签和节点 chip。
5. 标签：项目 tag 横向换行。
6. 底部：更新时间和图标操作。

视觉：

- 最小高度：`200px`。
- padding：`14px`。
- 圆角：`--ck-radius-md`。
- 边框：浅色 `rgba(0, 0, 0, 0.04)`。
- 背景：浅色白底，深色 `#1e293b`。
- hover：上移 `2-3px`，加深阴影，边框微染主色。
- 选中态：边框使用 `--ck-primary`，阴影使用主色弱透明。

文本：

- 项目名 `14px / 600`，单行省略。
- 描述 `12px / 1.5`，两行截断。
- 状态 label 使用 `11px` 弱文本。
- 时间使用 `10px` 弱文本，允许省略。

操作：

- 操作按钮尺寸 `28px * 28px`。
- 普通操作 hover 显示弱背景和主文本色。
- 危险操作 hover 显示危险色和危险弱背景。

### 7.6 分组卡片

工程分组在卡片网格中以文件夹卡片呈现：

- 可使用浅蓝到浅青的低饱和渐变，配合虚线边框。
- 文件夹图标容器 `40px * 40px`，圆角 `10px`。
- 分组名 `14px / 600`，数量 `11px`。
- 组内项目预览使用白色半透明弱面板，最多直接展示 5 条，剩余用 `+N`。
- 分组卡片是当前工程管理界面的特征组件，不建议在所有业务卡片上滥用虚线和渐变。

### 7.7 表格视图

表格视图用于更高密度的列表扫描：

- 表头背景使用浅灰 `#f4f6f9`，表头字重 `700`。
- 常规行单元格 padding 可保持 `18px 0`。
- 分组行使用更浅背景，鼠标 hover 轻微加深。
- 项目名使用主色链接按钮。
- 操作列固定右侧，按钮保持 `28px * 28px`。
- 描述、名称等长文本必须使用省略和 tooltip。

### 7.8 分页

分页固定在内容容器底部：

- 顶部边框使用 `--ck-border-light`。
- 背景使用 `--ck-bg-card`。
- 显示总量摘要、页码、每页条数选择。
- 每页条数菜单使用 `pagination-size-menu` 样式，当前项使用主色弱底。

### 7.9 弹窗与抽屉

弹窗用于创建、编辑、部署、版本管理等中断式任务：

- 标准宽度可使用 `520px`、`600px`、`860px`、`960px`。
- 复杂弹窗使用 `width="min(860px, 92vw)"`。
- 圆角：`12px`。
- header 背景使用浅灰，footer 顶部分割线。
- 表单 label 字重 `500`，label 宽度根据业务保持 `96px-100px`。
- 部署类弹窗需要控制最大高度，内部列表独立滚动。

### 7.10 空、加载、错误状态

加载：

- 列表和卡片区优先使用 skeleton。
- 按钮级异步操作使用图标旋转或组件库 loading。
- 避免整页中间孤立 spinner，除非页面没有任何可展示骨架。

空状态：

- 使用 `el-empty` 或简洁文本，说明当前没有数据。
- 对可操作页面，空状态应保留新增、导入或刷新入口。

错误：

- 非阻塞区域错误使用轻量 alert 或局部提示。
- 多请求并行加载时允许部分失败，成功数据仍可展示。
- 删除、部署、切换模式等高风险操作必须有确认或明确失败提示。

## 8. 动效与反馈

标准动效：

- 常规 hover、focus、颜色变化：`150-200ms`。
- 工具栏和卡片入场：`ck-fadeUp`，`0.5-0.55s`。
- 弹出筛选面板：`0.16s`，透明度加轻微上移。
- 卡片 hover：允许 `translateY(-2px)` 到 `translateY(-3px)`。

约束：

- 动效必须表达状态变化，不做纯装饰循环动画。
- 不动画布局尺寸，避免内容跳动。
- 列表项数量较多时，避免过多 stagger 动画影响响应。
- 后续应支持 `prefers-reduced-motion`，减少入场和位移动画。

## 9. 深色模式

深色模式不只是反转颜色，应保持信息层级：

- 页面底色使用深蓝灰。
- 面板使用较浅一层的深蓝灰。
- 边框使用低透明白。
- 主文本接近浅灰，次文本和弱文本降低亮度。
- 激活状态使用蓝色弱底，不使用大面积高饱和蓝。
- 表格、弹窗、标签页需要覆盖组件库默认浅色背景，避免深色模式局部发白。

## 10. 可访问性与交互约束

必须满足：

- 所有可点击自定义元素使用 `button`，不要用 `div` 代替按钮。
- 图标按钮必须提供 tooltip 或 `aria-label`。
- 筛选、下拉、弹窗状态应能同步到 ARIA 属性。
- 键盘 focus 必须可见。
- 颜色不能是状态的唯一表达。
- 文字和控件在 `375px`、`768px`、`1024px`、`1440px` 下不得重叠。
- 删除、部署、批量操作等高风险按钮必须有权限控制和二次确认。

## 11. 子应用继承规则

`designer` 和 `datacenter` 后续参考本规范时，应区分“宿主工作台”和“业务操作面”：

- 宿主级导航、标签页、主题、语言由 `dev_ide` 统一控制。
- 子应用不要重复创建全局侧边栏，除非是子应用内部的领域导航。
- 子应用首页应直接进入工作区，例如画布、数据连接、模型列表、任务列表。
- 子应用的工具栏、图标按钮、筛选、分页、弹窗应复用 `ck` 视觉语言。
- 复杂专业界面可以提高密度，但不要破坏主色、圆角、阴影、状态色的一致性。
- 嵌入场景下应响应宿主 `theme` 和 `locale` 更新。

## 12. 落地建议

后续新增页面时建议按以下顺序设计：

1. 明确页面主任务：管理、配置、编辑、监控或数据建模。
2. 选择骨架：工作台页、双栏页、表格页、卡片入口页、画布页。
3. 先放工具栏和主内容区，再放次要统计或辅助面板。
4. 使用 `--ck-*` token 和通用工作台类。
5. 为加载、空、错误、禁用、权限不足、批量选择状态补齐视觉状态。
6. 检查窄屏换行和长文本截断。
7. 检查深色模式和组件库默认样式覆盖。

不建议：

- 在业务页面使用大面积纯装饰渐变背景。
- 把每个模块都做成同样尺寸的营销卡片网格。
- 为普通信息块添加夸张阴影、玻璃模糊或大圆角。
- 用手写 SVG 临时拼装常见图标。
- 在 `designer` 或 `datacenter` 中另起一套全局色彩和控件语言。
