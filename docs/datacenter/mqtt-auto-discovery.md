# MQTT 自动发现与批量导入

## 1. 文档定位
- 本文档定义 DataCenter 中 MQTT 变量发现与导入能力的阶段目标和边界。
- 当前代码侧 MQTT 连接、订阅、消息查看和 Tag 管理已具备主干，本功能属于后续增强项。
- 本文档不再把多种发现方式直接写成“已实现”。

## 2. 当前已实现
### 2.1 已有能力
- MQTT 连接管理。
- MQTT 订阅与消息查看。
- 基础 Tag/变量管理。
- 实时数据监控主干。

### 2.2 当前缺口
- 自动发现未形成正式产品闭环。
- 批量导入对象模型、审批策略、覆盖规则未统一。
- 与 DataPoint 的映射规则还不够稳定。

## 3. 共创后建议目标
### 3.1 目标
- 为 MQTT 类数据源提供变量定义快速入库能力。
- 缩短从“接入连接”到“可用于 Designer/Runtime”的准备时间。
- 统一变量发现、导入、映射和落库规则。

### 3.2 支持方式
| 方式 | 阶段建议 | 说明 |
| --- | --- | --- |
| MQTT 自动发现 | 一期可做 | 通过约定 Topic 接收变量定义 |
| CSV 批量导入 | 一期可做 | 适合线下整理清单导入 |
| REST API 拉取 | 二期再做 | 依赖外部系统接口稳定性 |

## 4. 对象边界
### 发现对象
- 描述变量定义来源，不直接代表平台统一数据点。

### 数据点对象
- 发现结果在确认后，才能转换为平台 `DataPoint`。
- `DataPoint` 才是 Designer 和 Runtime 可引用的正式对象。

## 5. 一期推荐流程
1. 配置 MQTT 连接。
2. 配置发现来源或上传 CSV。
3. 预览发现结果。
4. 做去重、命名规范和字段映射校验。
5. 选择目标变量组或数据点分组。
6. 执行导入，生成或更新 `DataPoint`。

## 6. 一期最小字段
| 字段 | 说明 |
| --- | --- |
| `sourceName` | 来源变量名 |
| `displayName` | 展示名称 |
| `dataType` | 数据类型 |
| `unit` | 单位 |
| `description` | 描述 |
| `topic` | 来源 Topic |
| `qualityField` | 质量字段映射 |
| `timestampField` | 时间戳字段映射 |

## 7. 导入规则建议
### 新建规则
- 不存在同名数据点时直接创建。

### 冲突规则
- 已存在同名对象时，必须由用户选择覆盖、跳过或新建别名。

### 安全规则
- 自动发现只负责生成定义，不直接开放写回。

## 8. 当前阶段非目标
- 不做复杂多协议统一发现中心。
- 不把发现结果直接等同为运行态订阅对象。
- 不在一期引入自动审批和自动覆盖。
