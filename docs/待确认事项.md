# 待确认事项

## 1. 运行时策略
1. RuntimeEngine 当前阶段是否只支持浏览器访问，不做独立桌面壳。
2. RuntimeEngine 是否必须支持离线缓存、历史数据回放，还是先只做实时数据展示。
3. 运行时组件首批白名单是否限定为文本、图片、按钮、表格、容器。

## 2. 发布制品策略
1. 当前阶段制品是否只做摘要校验，不做数字签名。
2. 版本包是否允许保留运行时无关的设计态冗余字段。
3. 制品是否需要兼容旧版本历史包，还是从新协议开始切换。

## 3. Designer 与 DataCenter 边界
1. Designer 是否只引用 DataCenter 已定义的数据点/查询，不允许自行定义数据接入。
2. DataCenter 处理层一期是否进入当前周期，还是在 Runtime MVP 闭环后再推进。
3. 表达式和绑定规则的最终责任边界放在 Designer 还是 Runtime。

## 4. 运维与权限策略
1. 节点审批权是否只开放给 `SYSTEM_ADMIN` 与 `OPS_ADMIN`。
2. 发布与部署权限是否需要进一步按项目粒度收缩。
3. 数据回写是否需要审批流，还是允许部分场景直接执行。

## 5. 文档治理策略
1. `docs/rebuild` 中的重建文档确认后，是否直接替换旧文档。
2. 对于明确过时的历史文档，是否移动到 `docs/archive/`，还是直接删除。
3. 后续是否约束所有模块开发完成后必须同步回写文档与任务清单。
