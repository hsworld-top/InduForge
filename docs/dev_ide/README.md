# IDE 管理端概览

## 模块定位

- `dev_ide` 是平台管理与运维前端，负责项目入口、平台管理、发布部署操作、节点管理和运行状态可视化。

## 核心能力

- 平台管理入口
- 仪表盘租户共享便签与最近活动概览
- 工程与项目入口
- 发布与部署操作入口
- 节点、版本、运行状态与日志查看
- 平台治理相关管理视图

## 仪表盘租户共享便签

仪表盘在统计卡片下方采用左右分栏：

- 左侧为“租户共享便签”区域，用于同一租户下用户之间逐条留言、公告短信息或临时协作提醒。
- 右侧为“最近活动”区域，继续展示系统近期操作日志或活动摘要。

共享便签的设计约束：

- 便签归属于当前租户，不归属于单个用户或单个工程。
- 当前租户下已登录用户均可读取便签列表。
- 当前租户下已登录用户均可新增、编辑、删除便签；编辑只覆盖对应单条便签。
- 单条便签内容长度限制为 2000 个字符，前端应在输入区给出字数反馈或保存失败提示。
- 每条便签展示最后更新时间和最后更新用户，便于判断内容新旧。
- 便签不是审计日志，不用于长期归档；正式变更、审批和运维记录仍以系统日志或业务单据为准。

前端交互约定：

- 进入仪表盘时读取当前租户便签列表，与统计数据、最近活动并行加载。
- 用户新增、编辑或删除便签时只更新对应条目；保存过程中按钮进入加载态，避免重复提交。
- 读取失败时不阻塞仪表盘其他内容，便签区域展示轻量错误提示并允许刷新重试。
- 仪表盘刷新按钮应同时刷新统计、最近活动和便签内容。

## 正式边界

- `dev_ide` 的主后端入口是 `dev_core`。
- `dev_ide` 不承担设计器画布编辑能力。
- `dev_ide` 不承担节点执行逻辑和平台侧数据域后端能力。

## 关键交付件

- 平台管理视图
- 项目与工程管理入口
- 发布部署操作视图
- 节点与运行状态管理视图

## 质量关注点

- 管理入口展示的发布、部署、节点状态必须与后端真实状态一致。
- 平台治理、工程管理和部署操作流程必须具备稳定冒烟验证。
- 关键运维入口不能依赖隐式状态或局部约定。

## 子应用宿主化与调试

### 正式入口约定

- `designer` 与 `datacenter` 的正式入口由 `dev_ide` 作为宿主打开，不再依赖 URL 传递 `token`、`refreshToken`、`pid`、`tenant`、`theme`、`locale`。
- `dev_ide` 通过 iframe 加载正式入口，并在子应用启动后使用 `postMessage` 完成 bootstrap 握手。
- 正式入口 URL 仅允许保留 `handoff` 这类非敏感恢复票据，不允许再把鉴权或租户上下文拼到查询串。

### 调试方式

1. 调试正式链路时，先启动 `dev_ide`，再从 IDE 内打开设计中心或数据中心标签页。
2. 在浏览器开发者工具里查看 iframe 的 `APP_BOOTSTRAP_REQUEST`、`APP_BOOTSTRAP_RESPONSE`、`AUTH_REFRESHED`、`AUTH_EXPIRED` 消息，确认宿主握手与续租回传是否正常。
3. 需要验证主题、语言同步时，在 `dev_ide` 内切换对应设置，观察子应用是否收到 `THEME_UPDATE`、`LOCALE_UPDATE`。

### 顶层打开与刷新行为

- 用户直接访问 `/designer/`、`/datacenter/` 这类正式入口且本地缺少可复用工程会话时，页面应重定向回 `dev_ide`，由 IDE 决定恢复哪个子应用标签页。
- 如果子应用页面已经被单独打开成浏览器标签页，只要本地仍保留 token 与 projectId，就允许继续独立运行；`handoff` 丢失或过期、且本地会话也不可复用时，会降级回 IDE 首页。
- 独立调试请使用子应用自己的 `/debug` 入口，不要把正式入口当成独立运行入口。
