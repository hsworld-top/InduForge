# InduForge 环境端口规划

本文档说明 InduForge 在开发环境、生产环境和离线交付环境中的端口约定。文档面向开发、测试、运维人员，可以直接暴露 PostgreSQL/TimescaleDB、Redis、EMQX、SeaweedFS、Nginx 等具体技术名称。

## 端口原则

- 开发环境宿主机端口统一使用 `18xxx` 段，方便和本机既有 MySQL、Redis、PostgreSQL 等服务区分。
- 工程开发容器使用 Docker 动态宿主机端口，仅绑定 `127.0.0.1`，不要求落在固定 `18xxx` 段。
- 正式用户环境的中心系统运行在 K3s `induforge-system` 命名空间，默认只暴露中心 Nginx 的 HTTP/HTTPS
  入口；中心后端和基础设施仅通过 ClusterIP 访问。
- 生产环境 Pod 内部服务端口统一使用 `18xxx` 段；唯一例外是 Nginx 容器内部监听标准 `80/443`。
- 工程开发容器沿用组件约定的内部端口 `3000`、`30141`、`5173`，不纳入平台基础服务 `18xxx` 内部端口段。
- 对外安装包、容器名和镜像名使用 InduForge 产品体系命名；正式文档和内部研发文档可以说明底层技术栈。

## 运行节点和 K3s 端口

| 用途 | 协议 | 默认端口 | 开放方向 | 配置边界 |
| --- | --- | ---: | --- | --- |
| K3s API | TCP | `6443` | 工作节点到中心节点 | `IF_OPS_K3S_API_PORT` 可在中心安装前调整 |
| Flannel VXLAN | UDP | `8472` | 所有 Linux 运行节点互通 | 平台固定；安装前检查本机占用并提示防火墙要求 |
| Kubelet API | TCP | `10250` | 所有 Linux 运行节点互通 | 平台固定；安装前检查本机占用并提示防火墙要求 |
| 中心时间同步 | UDP | `123` | 工作节点到中心节点 | 使用 NTP 标准端口，平台固定 |

当前使用 K3s 默认 Flannel VXLAN，因此必须开放 UDP `8472`。`2379-2380/TCP` 只在未来引入多个
K3s Server 时用于 embedded etcd Server 间通信；当前单中心 Server 拓扑不开放。NodeAgent 管理接口
只绑定本机回环地址，Center 与节点的日常控制由节点主动出站，不要求中心反向访问 NodeAgent。
K3s API 端口在首次创建运行集群时固化；已安装集群修改 `.env` 会被中心拒绝，必须通过后续专门的
集群变更流程处理，不能依靠重启造成 Server 与新节点配置分裂。

## 开发环境端口

开发环境使用根目录 `.env` 或 `.env.development.example`，基础设施由 `scripts/docker/docker-compose.dev.yml` 启动。WSL2 只承载 Docker 基础设施时，业务项目和 `pnpm install` 建议在 Windows 侧执行。

| ---------------------- | ---------------- | ------------------------------- | ---------- | ----------------------- | ---------------------------------------------------- |
| 统一入口               | Nginx            | `IF_EDGE_HOST_PORT`             | `18080`    | `80`                    | 开发环境可选，用于模拟生产入口。                     |
| 控制面后端             | Go               | `PORT`                          | `18101`    | 不在 dev compose 中启动 | 开发人员自行启动 `dev_core`。                        |
| 数据域服务             | Go               | `DATA_SERVICE_ADDR`             | `18102`    | 不在 dev compose 中启动 | 开发人员自行启动 `data_service`。                    |
| 计算沙箱               | Go + Node/Python | `COMPUTE_SANDBOX_ADDR`          | `18103`    | 不在 dev compose 中启动 | 仅供 `data_service` 使用，必须使用内部令牌。         |
| 节点执行器             | Go               | `NODE_AGENT_PORT`               | `18103`    | 不在 dev compose 中启动 | 节点侧本地服务端口。                                 |
| PostgreSQL/TimescaleDB | TimescaleDB PG16 | `IF_META_STORE_PORT`            | `18432`    | `5432`                  | 开发环境只改宿主机映射端口，容器内保持镜像默认端口。 |
| Redis                  | Redis 7.2        | `IF_CACHE_STORE_PORT`           | `18379`    | `6379`                  | 开发环境默认无密码。                                 |
| EMQX MQTT              | EMQX 5.6         | `IF_MESSAGE_HUB_MQTT_PORT`      | `18883`    | `1883`                  | 模拟数据脚本默认连接此宿主机端口。                   |
| EMQX WebSocket         | EMQX 5.6         | `IF_MESSAGE_HUB_WS_PORT`        | `18083`    | `8083`                  | 供本地协议联调使用。                                 |
| EMQX Dashboard         | EMQX 5.6         | `IF_MESSAGE_HUB_DASHBOARD_PORT` | `18084`    | `18083`                 | 仅开发排查使用。                                     |
| 工程运行内部总线       | NATS JetStream   | `IF_RUNTIME_BUS_PORT`           | `18222`    | `4222`                  | Windows 原生 Collector 从宿主机连接此端口。          |
| 内部总线监控           | NATS Monitoring  | `IF_RUNTIME_BUS_MONITOR_PORT`   | `18223`    | `8222`                  | 仅开发健康检查和诊断使用。                           |
| SeaweedFS S3           | SeaweedFS        | `IF_OBJECT_STORE_PORT`          | `18500`    | `8333`                  | S3 兼容访问端口。                                    |
| SeaweedFS Master       | SeaweedFS        | `IF_OBJECT_STORE_MASTER_PORT`   | `18333`    | `9333`                  | 仅开发排查使用。                                     |
| SeaweedFS Filer        | SeaweedFS        | `IF_OBJECT_STORE_FILER_PORT`    | `18888`    | `8888`                  | 仅开发排查使用。                                     |
| IDE 前端               | Vue/Vite         | `VITE_IDE_PORT`                 | `18601`    | 不在 dev compose 中启动 | Windows 或 Linux 本机启动。                          |
| 数据中心前端           | Vue/Vite         | `VITE_DATACENTER_PORT`          | `18602`    | 不在 dev compose 中启动 | Windows 或 Linux 本机启动。                          |
| 设计器前端             | Vue/Vite         | `VITE_DESIGNER_PORT`            | `18603`    | 不在 dev compose 中启动 | Windows 或 Linux 本机启动。                          |
| 节点本地前端           | Vue/Vite         | `VITE_NODE_AGENT_FRONT_PORT`    | `18604`    | 不在 dev compose 中启动 | Windows 或 Linux 本机启动。                          |
| 工程 AI 工作空间       | Pi Web           | 动态分配                        | 动态       | `30141`                 | 仅绑定 `127.0.0.1`，由 `dev_core` 返回实际 URL。     |
| 工程源码编辑器         | code-server      | 动态分配                        | 动态       | `3000`                  | 仅绑定 `127.0.0.1`，不同工程使用不同动态端口。       |
| 工程预览控制           | Preview Control  | 动态分配                        | 动态       | `5174`                  | 仅绑定 `127.0.0.1`，管理当前工程 Vite 生命周期。     |

开发环境初始化脚本只创建 `if_core`、`if_data`、`if_dev_data` 三个业务数据库。控制面和设计中心长期共用 `dev_core`，因此设计页面、设计资源和设计工程配置表都在 `if_core` 中；`if_design` 不再创建，也不作为预留库。

## 正式用户环境端口

正式安装把中心服务部署到 K3s `induforge-system`。`scripts/docker/docker-compose.prod.yml` 和
`docker-compose.offline.yml` 只保留为构建、演示及旧版迁移输入，不再定义正式用户拓扑。

| 能力                   | 底层技术         | 环境变量                        | 宿主机端口       | 容器内部端口 | 说明                                         |
| ---------------------- | ---------------- | ------------------------------- | ---------------- | ------------ | -------------------------------------------- |
| 中心 HTTP 入口         | Nginx            | `IF_EDGE_HOST_PORT`             | `18080`          | `80`         | 可配置；正式使用优先访问 HTTPS。             |
| 中心 HTTPS 入口        | Nginx            | `IF_EDGE_TLS_HOST_PORT`         | `18443`          | `443`        | NodeAgent 和管理用户的正式入口。             |
| 平台静态前端           | Nginx            | 无                              | 不单独暴露       | `80/443`     | 与中心入口为同一 Pod。                       |
| 控制面后端             | Go               | `PORT`                          | 不暴露           | `18101`      | edge 通过内部服务名 `center-control` 转发。  |
| 数据域服务             | Go               | `DATA_SERVICE_ADDR`             | 不暴露           | `18102`      | edge 通过内部服务名 `data` 转发。            |
| 计算沙箱               | Go + Node/Python | `COMPUTE_SANDBOX_ADDR`          | 不暴露           | `18103`      | 仅连接隔离内部网络，不接受用户 JWT。         |
| PostgreSQL/TimescaleDB | TimescaleDB PG16 | `IF_META_STORE_PORT`            | 不暴露           | `18432`      | 生产容器内部端口改为 18 段。                 |
| Redis                  | Redis 7.2        | `IF_CACHE_STORE_PORT`           | 不暴露           | `18379`      | 生产必须配置强密码。                         |
| EMQX MQTT              | EMQX 5.6         | `IF_MESSAGE_HUB_MQTT_PORT`      | 不暴露           | `18883`      | 外部设备接入应通过受控网关规划。             |
| EMQX WebSocket         | EMQX 5.6         | `IF_MESSAGE_HUB_WS_PORT`        | 不暴露           | `18083`      | 默认仅内部访问。                             |
| EMQX Dashboard         | EMQX 5.6         | `IF_MESSAGE_HUB_DASHBOARD_PORT` | 不暴露           | `18084`      | 默认不对外暴露管理面。                       |
| SeaweedFS S3           | SeaweedFS        | `IF_OBJECT_STORE_PORT`          | 不暴露           | `18500`      | 业务服务通过内部服务名 `object-store` 访问。 |
| SeaweedFS Master       | SeaweedFS        | `IF_OBJECT_STORE_MASTER_PORT`   | 不暴露           | `18333`      | 对象存储内部协调端口。                       |
| SeaweedFS Volume       | SeaweedFS        | `IF_OBJECT_STORE_VOLUME_PORT`   | 不暴露           | `18081`      | 对象存储内部数据端口。                       |
| SeaweedFS Filer        | SeaweedFS        | `IF_OBJECT_STORE_FILER_PORT`    | 不暴露           | `18888`      | 对象存储内部文件元数据端口。                 |
| 工程 AI 工作空间       | Pi Web           | 无                              | 不暴露           | `30141`      | Traefik 通过工程独立 Docker 网络转发。       |
| 工程源码编辑器         | code-server      | 无                              | 不暴露           | `3000`       | Traefik 通过工程独立 Docker 网络转发。       |
| 工程预览控制           | Preview Control  | 无                              | 不暴露           | `5174`       | Traefik 通过工程独立 Docker 网络转发并鉴权。 |
| 工程开发态预览         | Vite             | 无                              | 不暴露           | `5173`       | Traefik 转发 HTTP 和 HMR WebSocket。         |

[工程开发工作空间网络架构](../02-系统设计/工程开发工作空间网络架构.md)。

## 初始化入口

开发人员在 Linux 或 WSL2 中初始化基础设施：

```bash
./scripts/dev/init-linux.sh
```

该脚本只要求 Docker 和 Docker Compose 可用，会启动 Docker 基础设施、等待 NATS JetStream 就绪、创建 `if_core`、`if_data`、`if_dev_data`，并为 `if_dev_data` 启用 TimescaleDB 扩展。默认不会执行 `pnpm install`，也不会启动业务项目。

控制面数据库结构和默认管理员数据不由开发初始化脚本直接写入；`dev_core` 在开发环境启动时根据 `DB_AUTO_SCHEMA_SYNC=true` 仅初始化空数据库；已有数据库结构由开发者直接执行 SQL 调整。生产和离线环境保持 `DB_AUTO_SCHEMA_SYNC=false`，由安装脚本在安装阶段执行 bootstrap。

Windows + WSL2 场景建议在 Windows 侧执行：

```powershell
pnpm install
pnpm dev:core
pnpm dev:data
```

测试人员构建离线包：

```bash
./scripts/release/build-offline-package-linux.sh
```

目标机器安装离线包：

```bash
./install.sh
```

目标机器卸载离线包：

```bash
./uninstall.sh
```

如需同时删除 Docker 数据卷：

```bash
./uninstall.sh --volumes
```
