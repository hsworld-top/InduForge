# 运行环境概览读模型契约

`GET /api/v1/ops/runtime-environments/:id/overview` 要求 `environment:read`，租户从会话取得，已删除、不存在或异租户环境返回既有未找到错误。统一包络的 data 为以下快照，一条 SQL 在同一数据库时间/MVCC 快照内完成，不逐节点或逐任务查询；不修改原有环境状态及列表/详情接口。

| 字段 | 内容 |
| --- | --- |
| environmentId / snapshotAt | 环境标识与数据库读取时间；snapshotAt **不是引擎健康探测时间** |
| thresholds | freshnessSeconds=45、capacityAttentionPercent=85、capacityCriticalPercent=95；前端复用返回值 |
| deployments | total、running、stopped、failed、pending、stale、unknown；六个分类互斥且总和为 total，不含逻辑删除部署 |
| nodes | total、online、offline、fault、staleMetrics、unknownMetrics、capacityAttention、capacityCritical、maxDiskUsagePercent；来自环境全部关联节点，不受当前页影响 |
| riskNodes | 最多五条：id、name、ipAddress、nodeKind、observedStatus、clusterStatus、lastHeartbeatAt、metricsStale、cpuPercent、memoryPercent、diskPercent、health |

## 部署分类边界

优先级：部署或任一引擎失败 → failed；无服务、代次缺失或运行期望没有运行引擎 → unknown；部署 pending 或引擎状态/代次未收敛 → pending；整体已停止且收敛 → stopped；最近确认 running 且代次收敛但运行引擎节点未报告心跳 → unknown，节点心跳过期/离线 → stale；其余已确认 running、代次收敛且所需节点在线/活跃、心跳在 45 秒内 → running；无法分类 → unknown。

停止意图不要求节点在线。`deployment_services.observed_at` 当前是变化确认时间，不是周期采样时间，不能施加 45 秒 TTL，否则正常稳定服务会被误判过期。本接口只反映最近确认状态 + 代次 + 可验证节点链路；不宣称具备稳定运行引擎的周期探测能力，不扩采样循环或写入生命周期。

## 节点与容量

online 要求 active + online + 数据库接收心跳晚于 now()-45 秒；offline 为其补集。fault 仅为 cluster_status=failed，不含 pending/starting/removing；这些未就绪状态通过 riskNodes.health 呈现，不另造失败计数。staleMetrics 为心跳缺失或过期；unknownMetrics 为任意 CPU/内存/磁盘百分比缺失、不是 JSON 数字或不在 0..100。风险计数可重叠，不用于相加推算总数。

仅对在线、活跃、心跳新鲜且有效指标输出对应百分比，其余为 null。maxDiskUsagePercent 仅取这些节点的有效磁盘最大值；没有有效值为 null，不能显示 0%。容量关注为 85≤磁盘使用率<95，严重为≥95，仅为新概览的容量风险展示规则，不产生告警事件、不改变 available/online 等运行状态。

`diskPercent` 来自现有 NodeAgent `disk.Usage(".")`，采集的是其**进程工作目录所在文件系统**，不是已实现的指定 `dataDir` 或独立业务数据盘采样，也不汇总所有分区。2026-09-03 对 129/130 的只读核查确认：两者 NodeAgent 工作目录均为 `/opt/induforge/node-agent`，所在文件系统均挂载于系统根分区 `/`。界面应称“节点磁盘”，不能称“业务数据盘”。本轮不改变 NodeAgent 采样路径或生命周期。

health 优先级为 offline、failed、stale、pending（运行组件 pending/starting/removing 或代次/移除意图未收敛）、unknown（应有运行组件但缺失或未安装）、capacity_critical、capacity_attention、unknown（缺指标）、healthy。只有需要 K3s 的 Linux 标准运行节点应用组件状态规则。风险排序在 SQL 对全部环境节点执行，按上述优先级、有效磁盘使用率降序、id 升序，再 LIMIT 5；不足五条时包含健康节点，不能把“前五条”当“风险总数”。

## 刷新与时间口径

概览活跃时复用共享 Socket.IO 的 nodes/environments/deployments 订阅，合并/节流后重新取单次概览快照；不全量拉部署/节点列表。原环境 recentAt 是最近环境事件时间，不能用作最后同步时间；本接口 snapshotAt 只表示本次读取时间。首次读取、重连和断线兜底遵守统一实时协议。
