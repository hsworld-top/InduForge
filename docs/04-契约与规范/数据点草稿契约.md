# 数据点草稿契约（设计）

## 路由

- `POST /api/v1/projects/{projectId}/datapoint-drafts/validate`
- `POST /api/v1/projects/{projectId}/datapoint-drafts/preview`
- `POST /api/v1/projects/{projectId}/datapoint-drafts/apply`

请求体统一为 `{baseEpoch, items}`。`items` 只包含来源类型、来源标识、输出键和期望路径，不携带数据库主键。

## 语义

`validate` 只进行权限、来源、路径规范化和冲突检查，不写入 `data_points`；`preview` 返回规范化后的候选路径及冲突详情，同样不写库。`apply` 必须在事务内以 `baseEpoch` 对项目 authoring epoch 做 compare-and-swap，成功后一次性写入并递增 epoch；重复请求使用请求幂等键返回第一次结果。

响应统一使用 `code/msg/data/reqId`，候选项不得返回对象存储内部键或连接凭据。路径生成复用 `buildV2GeneratedDataPointPath`，冲突返回具体来源和已占用路径。

## 安全要求

草稿接口复用项目读写权限；validate/preview 禁止任何写事务；apply 的 epoch 不匹配返回 409，并要求客户端重新获取上下文后重试。正式落地前需补 OpenAPI 生成路由和独立草稿持久化或事务内临时结构。
