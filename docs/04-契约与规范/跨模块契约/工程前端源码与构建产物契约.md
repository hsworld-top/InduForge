# 工程前端源码与构建产物契约

## 1. 文档定位

本文档定义工程 Vue/React Vite 源码、开发态预览、发布构建结果和运行资源之间的稳定边界。

## 2. 唯一事实

- `/workspace` 中的 Vue 或 React 源码、路由和前端资源是页面行为的唯一事实。
- 平台不维护与源码并行的页面 JSON、组件树或编辑器发布模型。
- 页面布局、交互、路由和国际化均由工程源码实现。
- 工程必须通过 `@induforge/runtime-sdk` 使用鉴权、权限、数据点和 HT 场景能力。

## 3. 最小源码结构

```text
/workspace
├─ package.json
├─ pnpm-lock.yaml
├─ index.html
├─ vite.config.js 或 vite.config.ts
├─ src/
├─ public/
└─ .induforge/
   ├─ project.json
   ├─ context/
   └─ scenes/
```

- `package.json` 必须提供 `dev` 和 `build` 脚本。
- `package.json` 必须声明 Node.js `>=24.19.0 <25`、npm `>=11.17.0 <12`、pnpm
  `>=11.21.0 <12`，并固定 `packageManager` 为 `pnpm@11.21.0`。
- `pnpm-lock.yaml` 必须随工程保存，发布构建按锁文件安装依赖。
- `project.json` 记录首次选择的官方模板和初始化时间，已初始化工程不得再次套用模板。
- `.induforge/context` 是平台生成的只读 AI 上下文，不进入前端构建产物。
- `.induforge/scenes` 保存场景公开契约，不等同于 HT 私有编辑数据。

## 4. 开发态

- Vite 监听容器内部 `5173`，由 `dev_core` 返回环境无关预览 URL。
- Pi Web、code-server 和 Vite 使用同一 `/workspace`。
- 源码保存后由 Vite HMR 更新预览；HMR 成功不替代正式构建校验。
- 开发态页面通过 Runtime SDK 连接平台提供的预览数据与场景服务。

## 5. 发布构建

发布流程必须在受控环境执行：

```text
按 pnpm-lock.yaml 安装依赖
→ pnpm build
→ 校验 dist 和入口文件
→ 打包 client-assets.tar.zst
```

任一步失败都必须阻止 Release 进入可部署状态。`client-assets.tar.zst` 只包含 `dist` 中可由
静态服务器直接托管的文件，不包含源码、依赖缓存、模型密钥或 AI 会话状态。

## 6. HT 场景与运行资源

- HT 2D/3D 编辑器负责场景、模型、材质和相关资源。
- 页面源码只持有稳定的场景 ID 和业务参数，不复制 HT 私有编辑数据。
- 场景公开契约进入 AI 上下文，供 AI 生成 Runtime SDK 调用代码。
- 发布时 HT 场景和资源进入 `runtime-artifact.tar.zst`，不重复打入前端 `dist`。
- 运行时页面通过 Runtime SDK 按场景 ID 加载资源；资源缺失或版本不匹配必须返回明确错误。

## 7. 运行态

`project-nginx` 直接托管解压后的工程前端静态产物，并代理受控的 Runtime API 和 WebSocket。
浏览器不直接访问中心 S3，也不读取开发态上下文目录。

## 8. 校验规则

- `pnpm build` 必须成功且输出非空 `dist`。
- `dist/index.html` 必须存在，所有构建资源路径必须适用于工程运行入口。
- 构建产物不得引用开发工作空间绝对路径或开发态服务地址。
- 前端声明的场景 ID 必须存在于同一 Release 的运行资源清单中。
- Release 中每个资源包必须具有 SHA-256 摘要并纳入签名范围。
