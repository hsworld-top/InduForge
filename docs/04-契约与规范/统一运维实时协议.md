# 统一运维实时协议

## 1. 范围与权威数据

控制面复用同源 Socket.IO `/control-socket.io`，覆盖运维概览、节点与时间同步、运行环境与基础服务、工程部署及其任务阶段、运维事件。浏览器页面共享一个连接，不按节点、工程、卡片或抽屉新建连接。

实时消息是**已提交状态的失效通知**，不是新的数据库或可靠消息日志。首次进入、订阅就绪、重连及明确要求对账时，通过已有 `/api/v1/ops` HTTP 接口取得权威快照。Socket 已连接不等于订阅已安装。不得以轮询计时模拟真实任务进度，也不得把入队当作启动完成。

当前是单中心控制实例：进程内 `epoch` 和序列不提供跨副本广播或历史重放。增加控制面副本前必须引入共享事件分发；不能直接依赖负载均衡使该实现变成多副本实时总线。

## 2. 订阅

客户端发送 `ops:watch`，同一 `subscriptionId` 替换此前订阅：

```json
{
  "subscriptionId": "ops-console",
  "topics": ["nodes", "environments", "deployments", "events"],
  "entityIds": ["已授权范围内的实体UUID"]
}
```

`entityIds` 可省略，表示该主题在当前租户内的所有变更。ID 是共同集合，不按主题分组；消息与订阅须同时满足主题相交及实体相交。未带实体 ID 的消息是 broad 失效，所有匹配主题的订阅都接收。分页列表应订阅 broad，避免漏掉新增、删除及总数变化；详情可使用部署/环境/已知节点 ID 集合。节点指标仅携带节点 ID，环境节点指标视图须依赖其已知节点集合。

服务端安装并裁剪权限后发送 `ops:ready`，它与后续 `ops:change` 进入同一连接的有序出站队列：

```json
{
  "subscriptionId": "ops-console",
  "epoch": "进程启动时生成的UUID",
  "sequence": 42,
  "topics": ["deployments", "environments", "events", "nodes"]
}
```

客户端发送 `ops:unwatch { "subscriptionId": "ops-console" }` 解除对应订阅。隐藏或不再使用的视图取消订阅；保留其它页面消费者的共享连接与订阅。

## 3. 变更通知

服务端事件名为 `ops:change`：

```json
{
  "epoch": "进程UUID",
  "sequence": 43,
  "topics": ["deployments", "events"],
  "entityIds": ["部署UUID", "环境UUID", "引擎服务UUID"],
  "timestamp": "2026-09-03T10:00:00Z",
  "terminal": true
}
```

- `sequence` 在同一进程内递增；租户、主题、实体过滤后允许跳号。只能丢弃同一 epoch 内已经处理的旧序号，不得把跳号当作丢包证据。
- epoch 变化、重连、订阅 ready 以及 `resync: true` 都要求对当前可见范围进行 HTTP 对账。
- `terminal` 表示应及时刷新终态，不表示成功；成功/失败以 HTTP 状态、generation 和 run 为准。
- 结构/API 操作发布 broad 失效。状态通知可合并多个实体，超过实体边界后退化为 broad。队列压力不可静默丢弃终态；连接无法继续接收时关闭，让客户端重连对账。
- 消息只包含主题、实体 ID、序号与时间，不包含令牌、制品 descriptor、对象键、连接串、原始节点消息或其它凭据。业务详情仍走原有 HTTP 鉴权接口。

## 4. 主题与权限

| 主题 | 内容 | 服务端要求 |
| --- | --- | --- |
| `nodes` | 节点接入/上下线、指标、时间同步、运行底座状态 | `node:read` |
| `environments` | 环境配置/成员、基础服务与观测时效、环境汇总 | `environment:read` |
| `deployments` | 工程部署、引擎状态、运行任务阶段与终态 | `node:read`，与当前正式部署查询一致 |
| `events` | 环境运维事件、工程部署运行事件的失效通知 | 同时满足 `node:read`、`environment:read` |

租户仅来自同源 HttpOnly `if_access` 的服务端认证结果，不接受客户端选择租户。命名空间认证完成后才允许 CONNECT；浏览器无需读取、保存或通过 URL 传递 JWT。原有 `ops:subscribe` / `ops:unsubscribe` 和旧事件消费者保留，租户房间仍由服务端决定并检查运维读取权限。

会话到期发送 `ops:auth { "code": "AUTH_EXPIRED" }` 后关闭；客户端可通过既有 Cookie 刷新会话流程进行有限重连。撤权、角色/租户变化或复核失败使用 `AUTH_FORBIDDEN`，不得无限刷新重试。初次 CONNECT 失败的 `connect_error.data.code` 使用相同分类。会话认证异常和网络异常应分别呈现，不得把无权限当作持续网络重试。

## 5. 性能、背压与生命周期

- 每进程最多 2048 个连接，每连接最多 8 个订阅，每订阅最多 4 个主题、200 个实体 ID；订阅标识与实体 ID 长度最多 80。watch/unwatch 每连接每秒最多 12 次，畸形请求同样计入配额。
- 所有连接共用一个 250ms 合并循环。节点纯指标按租户至少合并约 3 秒；状态改变、结构操作及终态使用快通道。重复节点投影使用有界指纹去重，缓存最多 4096 项、30 分钟过期。
- 待合并租户最多 1024，每租户最多 200 个 ID，溢出退化为 broad/resync。每连接出站队列最多 8 项，相邻失效消息可合并；ready、鉴权通知与状态消息保持顺序。
- 发包前检查实际传输层可写性；不可写时不调用会继续追加底层缓冲的 Emit。慢连接约 5 秒仍不可写则关闭，正常连接不会等待该连接的网络写入。
- 到期检查及权限复核使用共享维护循环。复核按唯一会话令牌合并，固定 4 个工作者、128 个待检查项；约 30 秒开始复核，不按每个状态事件或每个订阅查询权限。最后成功复核超过 60 秒即失败关闭，拥塞不能无限延长授权。到期后不继续投递状态事件。
- 工程列表恒定 3 次 SQL：当前页、当前页服务批量、同过滤 count。节点及环境节点列表的集群附加信息按当前页 ID 批量查询；所有结果集在下一查询前关闭。节点列表按创建时间/ID 稳定排序，不因心跳重排。
- K3s 调和复用全局 5 秒循环、单批最多 100 项串行执行。外部 HTTP 前释放数据库 rows，不在长事务里等待 K3s。观测写回采用捕获 generation 的 CAS；服务观测、阶段事件、部署聚合、last-ready、run 终态在同一短事务内提交后通知。重复 dispatched/阶段消息按 run、stage、message 去重。
- 节点离线与基础服务观测过期复用全局 10 秒 liveness 循环。基础服务时效扫描每页 200 环境、每次最多 5 页，游标跨轮推进，不反复只扫描前 1000 项；完整轮转约不超过 `10秒 × ceil((有基础服务的环境数 + 1) / 1000)`，另加查询耗时。仅成功读取且健康计数改变时通知。没有每客户端数据扫描或计时器。

客户端在线期间合并事件，只刷新可见列表/选中详情，不逐事件 loadAll；不能在高频事件下不断取消尚未完成的请求而造成饥饿。断线使用有界退避轮询，重连恢复一次快照；请求失败仍保留最近成功数据并显示过期提示。

## 6. 真实任务状态

现有 run 的 progress 主要是入队 0、结束 100，不代表持续百分比。使用旋转/进行中动画、真实阶段文字、已就绪引擎数量展示过程。引擎的 `desiredStatus`、`observedStatus`、`desiredGeneration`、`observedGeneration`、`lastOperation`、`lastMessage`、`replicasDesired`、`replicasObserved` 决定其真实状态；ready 必须同时满足状态与目标代次。

基础服务 HTTP 返回服务端权威 `observedStale` 布尔值，直接按 PostgreSQL `now()` 与 `observedAt` 比较，与环境汇总健康数共用 45 秒阈值；没有观测时间时为 `true`。前端对 `observedStatus=running` 但 `observedStale=true` 的服务显示观测过期/待关注，不自行用浏览器时钟判定，也不能持续显示健康。统一任务清单尚无新增 API，本协议只覆盖既有部署 run 与环境事件，不提供虚构任务记录。
