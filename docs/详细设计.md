# 详细设计

## 1. 设计范围
本文聚焦下一阶段必须定义清楚、且能直接指导开发的能力：发布制品、部署执行、运行时引擎、Designer 输出契约、DataCenter 处理层一期。

## 2. 当前已实现
### 2.1 已有服务与类职责
- `publishService`：负责工程打包、清单生成、版本记录。
- `deploymentService`：负责部署单创建、节点分发、回滚和状态管理。
- `nodeService`：负责节点注册、审批、心跳、命令下发与回执处理。
- Designer Editor Core：负责文档模型、命令、锁、校验、绑定和表达式基础能力。
- NodeAgent Executor/Orchestrator：负责部署执行、进程控制、状态管理。

### 2.2 当前缺口
- 发布制品字段不完整，资源组织与 Schema 版本不足。
- RuntimeEngine 无代码落地，无法承接 Designer 输出。
- DataCenter 的计算、报警、回写尚未形成统一对象模型。

## 3. 共创后建议目标
- 先冻结 Runtime MVP 的最小功能面，避免边做边扩。
- 所有详细设计围绕“可发布、可部署、可运行、可监控”主线收敛。

## 4. 功能点设计
### 4.1 发布制品 V1.1
#### 目标
- 让 `dev_core` 产出的制品能够被 `node_agent` 和 `runtime_engine` 稳定消费。

#### 制品结构
```text
project.ifp
  manifest.json
  project/project.json
  project/pages/*.json
  project/assets/**
  project/data/points.json
  project/data/queries.json
  project/data/connections.json
```

#### `manifest.json` 建议字段
| 字段 | 说明 |
| --- | --- |
| `schemaVersion` | 制品协议版本 |
| `projectId` | 工程 ID |
| `projectCode` | 工程编码 |
| `version` | 发布版本号 |
| `entryPageId` | 入口页 |
| `pages` | 页面索引 |
| `assets` | 资源索引 |
| `capabilities` | 运行时能力声明 |
| `buildTime` | 打包时间 |
| `checksum` | 包摘要 |

#### 异常处理
- 页面缺失：中止发布并返回工程校验错误。
- 资源缺失：标记为阻断错误，不生成成功版本。
- 数据引用无效：支持“阻断”与“警告”两级规则，默认阻断关键引用。

### 4.2 部署与节点执行
#### 流程状态
- `PENDING`
- `DOWNLOADING`
- `EXTRACTING`
- `STARTING`
- `RUNNING`
- `FAILED`
- `STOPPED`
- `ROLLED_BACK`

#### NodeAgent 责任
- 拉取部署命令。
- 下载版本包并做基础校验。
- 解压到版本目录，维护当前版本软链接或当前目录标识。
- 启停 RuntimeEngine 进程。
- 上报状态与错误日志。

#### 异常处理
- 下载失败：标记部署失败，可按次数重试。
- 运行时探活失败：进入 `FAILED` 并记录最后错误。
- 回滚失败：保留当前状态并强制人工处理。

### 4.3 RuntimeEngine MVP
#### 目标功能
- 加载项目配置。
- 路由到入口页和普通页面。
- 渲染首批组件：文本、图片、按钮、表格、容器。
- 解析基础绑定：静态值、数据点值、查询结果、全局变量。
- 提供健康检查与运行状态接口。

#### 建议服务职责
| 服务/类 | 职责 |
| --- | --- |
| `ProjectLoader` | 读取制品并构造内存项目模型 |
| `ManifestValidator` | 校验制品结构与版本 |
| `PageRouter` | 页面路由与入口页解析 |
| `BindingResolver` | 绑定表达式求值 |
| `RuntimeDataClient` | 获取数据点、查询结果、订阅更新 |
| `ComponentRegistry` | 组件类型到渲染器映射 |

#### 接口定义建议
- `GET /health`：进程健康。
- `GET /status`：当前项目、版本、启动时间、运行状态。
- `GET /api/runtime/project`：返回简化后的项目元信息。
- `GET /api/runtime/page/:pageId`：返回页面运行态模型。

### 4.4 Designer 输出契约
#### 最小对象模型
- `project.json`：工程基础信息、入口页、主题、语言、全局变量声明。
- `page.json`：页面元信息、组件树、布局、事件、绑定、数据依赖。
- `component`：`id/type/props/style/layout/bindings/events/children`。

#### 设计要求
- 页面输出必须和运行态消费格式一致，避免二次转换。
- `bindings` 中字段名称要稳定，例如：`sourceType`、`sourceKey`、`expression`、`fallbackValue`。
- Designer 保存态与发布态允许结构不同，但发布导出必须落到统一 Schema。

### 4.5 DataCenter 处理层一期
#### 建议对象
- `calculation_unit`：计算表达式、输入点、输出点。
- `alarm_rule`：阈值、等级、触发条件、恢复条件。
- `writeback_task`：写回动作配置与审批策略。

#### 状态流转
- 计算单元：`draft -> enabled -> disabled`
- 报警规则：`draft -> enabled -> silenced -> disabled`
- 写回任务：`draft -> approved -> executed/failed`

## 5. 权限控制
### 5.1 当前已实现
- 平台侧已有多角色访问控制。
- 节点审批与部署权限已具备基础隔离。

### 5.2 建议补强
- 发布权限：`PROJECT_ADMIN` 以上。
- 部署权限：`OPS_ADMIN` 以上。
- 节点审批：`SYSTEM_ADMIN` 或 `OPS_ADMIN`。
- 写回能力：必须单独审批，不默认开放给设计器用户。

## 6. 扩展点
- Runtime 组件注册表后续可扩展更多工业组件。
- DataCenter 后续可扩展 OPC UA、WebSocket、Modbus 等新接入器。
- 制品协议后续可补签名、增量包、差分发布。

## 7. 待确认事项
- Designer 发布态 Schema 是否允许保留运行时不识别字段。
- Runtime 是否需要支持离线资源缓存与本地历史数据。
- DataCenter 处理层一期是否进入本阶段，还是后置到 Runtime MVP 完成后。
