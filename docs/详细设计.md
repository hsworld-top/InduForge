# 详细设计

## 1. 文档定位

本文档在正式产品定义和高层设计基础上，定义平台主对象、运行对象与关键机制，重点回答“关键能力具体靠什么对象成立、对象之间如何协作”。

## 2. 设计原则

- 平台治理对象、开发态数据域对象和节点运行对象分域定义，避免职责混写。
- 开发态与运行态共享同一套运行内核，但分别接入 `data_service` 与 `runtime_data_service`。
- 节点侧以工程运行单元为最小托管边界，而不是以整节点共享运行实例为边界。
- 稳定入口、动态网关、运行引擎和运行态数据引擎组分层解耦，降低单工程变更对已运行工程的影响。

## 3. 平台治理与工程控制对象

平台治理与工程控制对象由 `dev_core` 长期持有和编排。

| 对象                     | 责任归属   | 说明                         |
| ------------------------ | ---------- | ---------------------------- |
| `Tenant`                 | `dev_core` | 租户边界与租户级治理对象     |
| `User`                   | `dev_core` | 平台用户主体                 |
| `PlatformRole`           | `dev_core` | 平台角色与能力模型           |
| `Project`                | `dev_core` | 工程主对象                   |
| `ProjectGrant`           | `dev_core` | 平台侧工程授权与成员关系     |
| `ProjectRuntimeUser`     | `dev_core` | 工程运行态登录用户           |
| `ProjectRole`            | `dev_core` | 工程运行态角色定义           |
| `ProjectUserRoleBinding` | `dev_core` | 工程运行态用户与角色绑定关系 |
| `ProjectRoleGrant`       | `dev_core` | 工程运行态资源授权规则       |
| `DesignWorkspaceMeta`    | `dev_core` | 设计中心相关工程元信息       |
| `ProjectRelease`         | `dev_core` | 工程发布版本元信息           |
| `DeploymentPlan`         | `dev_core` | 平台侧部署计划               |
| `Node`                   | `dev_core` | 节点主对象                   |
| `NodeCommand`            | `dev_core` | 下发给节点的执行命令         |
| `NodeRuntimeReport`      | `dev_core` | 节点运行状态、结果与回报对象 |

这组对象的核心边界是：

- `dev_core` 持有平台治理、工程生命周期与部署编排能力。
- `dev_core` 持有工程运行态用户、角色与资源授权规则主数据，并在发布时构建对应安全快照。
- `dev_core` 不长期持有开发态或运行态的数据域实现职责。

### 3.1 租户共享便签

租户共享便签是 `Tenant` 的轻量扩展能力，用于 `dev_ide` 仪表盘左侧展示同租户用户可见的逐条协作留言。

对象归属与存储：

- 责任归属：`dev_core`。
- 数据归属：当前登录用户所属 `Tenant`。
- 存储位置：优先使用 `Tenant.settings.dashboardNotes`，避免为轻量租户级短文本新增独立业务表。
- 单条数据结构：

```json
{
  "id": "便签ID",
  "content": "便签正文",
  "createdAt": "2026-04-24T12:00:00.000Z",
  "createdBy": "用户ID",
  "createdByName": "用户显示名",
  "updatedAt": "2026-04-24T12:00:00.000Z",
  "updatedBy": "用户ID",
  "updatedByName": "用户显示名"
}
```

访问规则：

- 当前租户下已登录用户可以读取便签列表。
- 当前租户下已登录用户可以新增、编辑、删除便签。
- 超级管理员如果未绑定当前租户上下文，不参与该便签读写。
- 单条便签编辑采用整段覆盖，不做多版本合并；并发编辑以后提交者为准。

边界约束：

- 便签用于临时留言或公告提示，不替代系统日志、审批记录、运维工单或正式通知。
- 单条便签内容最大 2000 字符。
- 便签内容不进入发布包，不随工程导入导出。
- 更新便签属于平台操作，应按现有操作日志中间件记录接口调用。

## 4. 平台侧数据域对象

平台侧数据域对象由 `data_service` 持有，为 `datacenter` 和开发态预览提供能力。

| 对象                  | 责任归属       | 说明                               |
| --------------------- | -------------- | ---------------------------------- |
| `DataConnection`      | `data_service` | 数据连接定义                       |
| `QueryDefinition`     | `data_service` | 查询定义                           |
| `DatapointDefinition` | `data_service` | 数据点定义                         |
| `MqttSubscription`    | `data_service` | MQTT 订阅与消息消费定义            |
| `ProtocolConfig`      | `data_service` | 各类协议接入配置                   |
| `ComputeUnit`         | `data_service` | 平台侧计算单元                     |
| `PreviewSession`      | `data_service` | 开发态预览数据会话                 |
| `DataDomainSnapshot`  | `data_service` | 用于发布时导出的运行所需数据域快照 |

这组对象的核心边界是：

- 面向设计态、配置态与开发态预览。
- 由平台侧 `data_service` 管理。
- 发布时只导出运行所需的数据快照和运行约束，不把整个平台数据工作台能力原样迁移到节点侧。

## 5. 发布制品与运行快照对象

发布链路需要同时承载工程定义和运行所需数据域定义。

| 对象                      | 责任归属                    | 说明                                                     |
| ------------------------- | --------------------------- | -------------------------------------------------------- |
| `ProjectReleasePackage`   | `dev_core`                  | 最终发布制品，承载工程结构、资源索引、运行配置和数据快照 |
| `RuntimeProjectSpec`      | `dev_core`                  | 工程运行配置，描述运行引擎与运行态数据引擎组的期望结构   |
| `DataDomainSnapshot`      | `data_service` + `dev_core` | 运行态所需的数据域快照                                   |
| `RuntimeSecuritySnapshot` | `dev_core`                  | 工程运行态用户、角色、绑定关系与资源授权快照             |
| `RuntimeRouteKey`         | `dev_core`                  | 工程在节点侧网关注册时使用的路由标识                     |

`ProjectReleasePackage` 至少应包含：

- 工程与页面定义
- 资源索引
- 共享运行内核消费所需运行配置
- 运行态所需的数据域快照
- 运行态所需的安全快照
- `RuntimeProjectSpec`

## 6. 节点运行对象

节点运行对象由 `node_agent` 托管，由 `runtime_gateway`、`runtime_engine` 和 `runtime_data_service` 协作承接。

### 6.1 工程运行单元

| 对象                     | 责任归属          | 说明                                                   |
| ------------------------ | ----------------- | ------------------------------------------------------ |
| `ProjectRuntimeUnit`     | `node_agent`      | 某工程在某节点上的运行单元                             |
| `ProjectRouteRecord`     | `runtime_gateway` | 工程访问入口、运行引擎、数据引擎组与版本状态的路由记录 |
| `RuntimeGatewayRegistry` | `runtime_gateway` | 节点本地工程路由注册表                                 |

一个 `ProjectRuntimeUnit` 至少包含：

- 一个 `RuntimeEngineInstance`
- 一组 `RuntimeDataServiceInstance`
- 一条 `ProjectRouteRecord`
- 当前版本、状态与健康信息

### 6.2 运行引擎对象

| 对象                    | 责任归属         | 说明                     |
| ----------------------- | ---------------- | ------------------------ |
| `RuntimeEngineInstance` | `runtime_engine` | 某工程的页面运行引擎实例 |
| `RuntimeProjectContext` | `runtime_engine` | 工程运行上下文           |
| `PageRuntimeModel`      | `runtime_engine` | 页面运行态模型           |
| `BindingResolver`       | 共享运行内核     | 绑定求值能力             |
| `ComponentRegistry`     | 共享运行内核     | 组件类型到运行渲染器映射 |

### 6.3 运行态数据引擎组对象

| 对象                         | 责任归属                    | 说明                                      |
| ---------------------------- | --------------------------- | ----------------------------------------- |
| `RuntimeDataServiceGroup`    | `runtime_data_service`      | 某工程的一组运行态数据引擎实例            |
| `RuntimeDataServiceInstance` | `runtime_data_service`      | 组内某个具体实例                          |
| `RuntimeDataEndpointSet`     | `node_agent` / 本地注册信息 | `runtime_engine` 可消费的数据引擎目标集合 |

这组对象的核心约束是：

- 多实例服务于同一个工程。
- 多实例的目的在于负载均衡和吞吐扩展。
- 它们不是节点级共享公共数据服务。

## 7. 关键交互机制

### 7.1 发布与节点落地机制

平台侧到节点侧的主线为：

1. `dev_core` 聚合工程定义、资源索引与数据域快照，生成 `ProjectReleasePackage`。
2. `dev_core` 生成 `DeploymentPlan` 并下发到 `node_agent`。
3. `node_agent` 在节点侧展开制品，创建 `ProjectRuntimeUnit`。
4. `node_agent` 拉起该工程对应的 `RuntimeDataServiceGroup`。
5. `node_agent` 在数据引擎组健康后拉起 `RuntimeEngineInstance`。
6. `node_agent` 通知 `runtime_gateway` 写入或更新 `ProjectRouteRecord`。
7. 外部流量再通过节点稳定入口访问该工程。

### 7.2 节点稳定入口与动态路由机制

节点侧访问链路固定为：

`nginx -> runtime_gateway -> runtime_engine`

其中：

- `nginx` 保持节点级稳定入口，不负责工程级动态编排。
- `runtime_gateway` 维护节点本地工程路由注册表。
- 工程部署、重启、扩缩容优先更新 `RuntimeGatewayRegistry`，而不是频繁改动节点公共入口配置。

### 7.3 运行引擎与运行态数据引擎组的协作机制

- `runtime_engine` 不直接处理复杂数据域逻辑。
- `runtime_engine` 只消费该工程绑定的 `RuntimeDataEndpointSet`。
- `runtime_engine` 不绑定到单一 `RuntimeDataServiceInstance`，而是面向整个 `RuntimeDataServiceGroup` 工作。
- `runtime_data_service` 组内实例共同服务同一个工程运行单元。

### 7.4 开发态与运行态的数据连续性机制

- 开发态预览通过平台侧 `data_service` 获得数据域能力。
- 运行态通过 `runtime_data_service` 获得工程级数据域能力。
- 两者共享同一套数据域契约和运行所需数据语义。
- `DataDomainSnapshot` 是平台侧数据域定义转入运行态的桥梁。

### 7.5 `node_agent` 的托管机制

`node_agent` 负责：

- 工程制品展开与运行单元创建
- `runtime_gateway` 进程托管
- `runtime_engine` 进程托管
- `runtime_data_service` 实例组进程托管
- 工程运行单元健康检查、摘流、加流、切换与回报

## 8. 稳定边界

- `dev_core` 负责平台治理、设计中心接口、工程管理和发布部署编排，不负责长期数据域后端。
- `data_service` 负责平台侧数据域与开发态预览数据能力，不负责节点运行编排。
- `runtime_engine` 负责页面运行，不负责平台治理和数据引擎生命周期。
- `runtime_data_service` 负责工程级运行态数据域，不负责平台治理和页面解释。
- `runtime_gateway` 负责节点本地工程路由，不负责平台治理和数据域逻辑执行。
- `node_agent` 负责托管和编排，不负责页面语义解释与平台业务控制。
