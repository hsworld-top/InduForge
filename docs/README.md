## 维护规则

- 同一事实只维护一处正文，其他文档链接引用；导航页不复制版本号、端口和能力进度表。
- 产品要求、目标设计、代码实现和目标环境验收分别说明。目标不得写成已交付，代码存在也不能替代真实安装、断网、升级或恢复验收。
- 代码与文档冲突时，先判断是实现缺陷还是设计过期。过期说明直接修正或删除；有效但未实现的产品要求保留并注明边界。
- 不在仓库保存阶段计划、审计报告、整改流水、会话摘要或旧入口；过程记录保留在任务对话，历史通过 Git 查询。
- 被替代的设计及失效图稿直接删除，同步移除引用。不创建归档目录或重复的“新版 / 旧版”文档。
- 正式文档优先使用中文文件名。改动契约时同步实现与必要回归；修正说明时检查路径、链接和术语，不为文档改动启动业务服务。
