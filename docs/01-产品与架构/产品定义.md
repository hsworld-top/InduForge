# 产品定义

## 1. 文档定位

本文档定义 InduForge 的最终态产品形态、产品分层、一级模块职责与协作边界。本文档是平台正式产品主文档，不承载当前阶段计划、任务拆分、完成度统计与实现细节。

## 2. 产品目标与核心价值

InduForge 是一个面向工业互联网场景的低代码开发平台，提供从设计、数据接入、工程聚合、发布部署到节点运行与运维管理的完整产品能力。

平台的核心价值体现在以下三个方面：

- 面向业务与方案侧：降低工业应用交付门槛，缩短从方案到可运行系统的交付路径。
- 面向研发与实施侧：打通设计、数据、发布、部署、运行链路，降低跨角色协作成本。
- 面向运维侧：提升部署、观测、维护、回滚与问题追踪能力，适配复杂现场环境。

## 3. 产品分层与总体结构

InduForge 的最终态产品结构分为五层：

- 设计层：`designer`
- 平台数据层：`datacenter`、`data_service`
- 控制与管理层：`dev_core`、`dev_ide`
- 共享运行内核层：预览与运行时共用的解释、渲染、绑定、变量与事件能力
- 运行与节点层：`project_nginx`、`client_engine`、`runtime_api`、`runtime_data_service`、`runtime/node_agent`、`runtime/node_agent_front`

以上分层用于明确平台长期职责边界：

- 设计层负责工程与页面定义。
- 平台数据层负责开发态数据域能力与数据工作台入口。
- 控制与管理层负责平台治理、离线授权、工程聚合、发布部署与管理操作。
- 共享运行内核层负责开发态预览与最终运行时共用的核心运行能力。
- 运行与节点层负责工程入口、客户端运行、工程运行网关、运行态数据引擎、节点托管、本地运维入口，以及 Windows / Linux 原生采集站点。

## 4. 设计层

### 4.1 `designer`

**职责**

- 负责低代码页面、组件、变量、交互和工程内容的设计与组织。
- 作为平台设计层的核心入口，承接页面建模与设计态操作。

**核心能力**

- 页面设计与组件编排
- 属性配置、变量配置、绑定配置与表达式配置
- 工程结构组织与设计态内容管理
- 设计态预览接入能力

**协作边界**

- `designer` 负责设计态与发布态内容的组织，不负责数据治理与数据域后端能力。
- 设计输出交由控制与管理层完成工程聚合、发布与部署编排。
- 数据语义与数据服务能力由数据层提供，运行承载由共享运行内核层与运行层共同完成。

## 5. 平台数据层

### 5.1 `datacenter`

**职责**

- 作为平台的数据工作台前端，为项目提供数据配置、数据调试、数据消费入口和数据侧操作界面。

**核心能力**

- 数据连接管理
- 查询定义与执行入口
- 数据点配置与查看
- MQTT、协议接入、计算与调试等数据域前端工作台能力

**协作边界**

- `datacenter` 是数据工作台前端，不承担数据域最终后端实现。
- 数据域实际后端能力由 `data_service` 提供。
- `datacenter` 为设计层、控制层和运维人员提供数据侧可视化操作入口。

### 5.2 `data_service`

**职责**

- 作为平台侧和开发态的数据域服务，承接连接、查询、数据点、采集、协议接入、计算、存储、预览会话等核心开发态数据域能力。

**核心能力**

- 数据接入与连接管理
- 查询执行与数据访问服务
- 数据点采集、读写与状态支撑
- MQTT 与多协议数据接入
- 计算与数据处理服务
- 预览会话与运行期数据支撑
- 数据域 API 与数据域存储能力

**协作边界**

- `data_service` 不承担平台控制、发布部署编排和平台管理职责。
- `data_service` 为 `datacenter`、`designer` 开发态预览和其他平台模块提供统一的平台侧数据域服务能力。
- `data_service` 与运行态的 `runtime_data_service` 共享数据域契约与领域模型，但不是同一部署实体。

## 6. 控制与管理层

### 6.1 `dev_core`

**职责**

- 作为平台控制与工程聚合后端，负责租户、用户、平台角色、工程管理、离线授权、工程运行态用户角色主数据、设计中心接口、平台管理接口、发布部署编排和平台侧控制能力。

**核心能力**

- 租户、用户、平台角色与平台治理能力
- 工程管理与设计中心接口能力
- 离线授权导入、租户授权分配、授权使用量统计、授权提醒和节点授权下发能力；工程数量只统计运行工程，节点数量只统计服务运行节点
- 工程运行态用户、角色、授权规则与安全快照组织能力
- 工程聚合与制品组织
- 发布编排、部署控制与节点协同
- 平台侧资源、管理接口与能力集成

**协作边界**

- `dev_core` 不承担长期数据域后端职责。
- `designer` 和 `dev_ide` 的主后端入口是 `dev_core`。
- 数据域能力通过 `data_service` 提供，`dev_core` 负责调用、编排和聚合。
- `dev_core` 不承担页面解释和节点本地托管。

### 6.2 `dev_ide`

**职责**

- 作为平台管理前端，提供平台管理、项目入口、发布部署操作与管理可视化界面。

**核心能力**

- 平台管理与项目入口
- 发布与部署操作入口
- 节点、版本、运维信息的管理视图
- 平台侧管理和治理操作界面

**协作边界**

- `dev_ide` 不承担数据域后端和节点托管逻辑。
- `dev_ide` 通过调用 `dev_core` 和相关服务提供统一管理入口。

## 7. 共享运行内核层

### 7.1 共享运行内核

**职责**

- 为开发态预览与最终运行时提供共用的页面解释、组件渲染、绑定求值、变量上下文与事件分发能力。

**核心能力**

- 页面结构解释
- 组件渲染与组件注册
- 绑定求值与变量上下文管理
- 事件分发与基础交互能力
- 对接数据层的数据消费能力

**协作边界**

- 共享运行内核不承担平台管理、数据治理和节点托管职责。
- 开发态预览与最终运行时通过不同引擎接入同一套核心运行能力，避免长期形成两套并行实现。

## 8. 运行与节点层

### 8.1 `project_nginx`

**职责**

- 作为工程 compose 内唯一入口，托管客户端静态资源并反向代理工程运行网关。

**核心能力**

- 映射独立宿主机端口
- 托管 `client_engine` 静态资源和工程发布资源
- 反向代理 `runtime_api`
- 反向代理采集盒子上行入口
- 按需代理 MQTT 等受控入口

**协作边界**

- `project_nginx` 不承担页面解释、平台治理、运行态权限和数据域逻辑执行职责。

### 8.2 `client_engine`

**职责**

- 作为工程页面静态客户端引擎，负责页面解释、渲染、绑定求值和运行态交互。

**核心能力**

- 共享运行内核在运行态的落位与集成
- 页面路由与页面运行上下文承载
- 组件渲染与绑定求值
- 运行态页面交互处理
- Data SDK 和 WebSocket 客户端

**协作边界**

- `client_engine` 不承担平台治理、节点托管和运行态数据引擎管理职责。
- `client_engine` 是 Vue/TypeScript 静态运行时，由 `project_nginx` 托管，不需要常驻 Node 后台。
- `client_engine` 只通过 `runtime_api` 访问运行态动态能力。

### 8.3 `runtime_api`

**职责**

- 作为工程运行网关，承接工程运行态用户、会话、权限、数据 API、报警动作、运行态动作和 WebSocket。

**核心能力**

- 工程运行态用户登录、登出和会话刷新
- `RuntimeSecuritySnapshot` 加载与权限校验
- 查询、点位、报警和动作 API
- WebSocket 实时数据通道
- 对接运行态数据引擎组

**协作边界**

- `runtime_api` 不承担采集、写入、报警规则计算和计算任务调度。
- `runtime_api` 不管理平台用户和设计态权限主数据。

### 8.4 `runtime_data_service`

**职责**

- 作为工程级运行态数据引擎，为节点侧运行工程提供数据接入、采集、计算、存储和本地数据服务能力。

**核心能力**

- 工程级运行态数据接入与采集
- 工程级计算、存储与本地数据服务
- 运行期数据接口与运行态数据支撑
- 组内多实例负载均衡与吞吐扩展

**协作边界**

- `runtime_data_service` 不承担平台治理、工程发布部署编排和页面解释职责。
- `runtime_data_service` 按工程运行单元部署，组内多实例服务同一个工程，不作为节点共享公共数据服务。

### 8.5 `runtime/node_agent`

**职责**

- 作为节点侧托管组件，负责版本部署、运行控制、生命周期管理与状态回传。

**核心能力**

- 制品下载与版本切换
- 工程 compose 或原生采集进程计划生成、端口分配、启停与探活
- 服务运行节点和纯采集节点的执行计划区分；纯采集节点只承接已授权运行工程的采集任务
- 节点状态、日志与结果回传
- 节点侧生命周期控制

**协作边界**

- `runtime/node_agent` 不承担页面语义解释与平台业务控制逻辑。
- 页面解释与运行行为由 `client_engine` 和共享运行内核负责。

### 8.6 `runtime/node_agent_front`

**职责**

- 作为节点本地管理前端，提供节点侧本地运维、查看与操作入口。

**核心能力**

- 节点本地状态查看
- 节点本地操作入口
- 本地运行与节点信息展示

**协作边界**

- `runtime/node_agent_front` 不承担平台主控制面职责，也不承担平台数据域职责。

## 9. 关键协作关系

InduForge 的长期协作关系遵循以下稳定原则：

- 设计层输出工程定义、页面定义和交互定义，由控制与管理层负责工程聚合与交付组织。
- 平台数据层为设计层和开发态预览提供统一的数据语义与平台侧数据服务能力。
- 控制与管理层负责平台治理、离线授权、发布部署、权限与项目控制。
- 共享运行内核承接预览与最终运行的共用运行能力，避免形成两套长期分叉的运行逻辑。
- 运行与节点层负责节点本地访问入口、工程运行引擎、工程级运行态数据引擎、节点托管与本地运维，不反向承接平台管理和平台侧数据治理职责。

## 10. 平台边界与非目标

InduForge 的长期边界包括：

- 平台不以通用办公流程平台为目标，而是聚焦工业互联网应用交付。
- 节点托管层不承担平台业务编排与产品治理能力。
- 数据工作台前端不等于平台侧数据域服务，运行态数据引擎也不等于平台侧数据服务。
- 开发态数据域与运行态数据域共享契约，但不共享同一实例，也不共享同一部署单元。
- 产品定义文档不承载阶段性排期、当前主线、任务拆分和实现命令。
