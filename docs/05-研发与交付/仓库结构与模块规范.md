# 仓库结构与模块规范

## 适用范围

本文是 [产品定义](../01-产品与架构/产品定义.md) 对应的目标代码组织和模块开发要求。当前目录仍保持原位；目标路径尚未实施，不能据此修改脚本、引用或生成不存在的模块。真实入口以当前列和模块代码为准。

保留多语言单仓，不因目录整理拆成更多独立服务。按交付生命周期划分，模块内按业务能力组织；只有形成独立依赖、权限、发布或部署边界时才拆包。

## 依赖和内部组织

- platform 通过 contracts、SDK 和公开运行协议交付工程，runtime / edge 的业务运行不导入平台内部实现。
- 平台账号、工程运行用户和节点身份分别管理；每个边界说明调用者、权限作用域与凭据来源。不得以统一 viewer 替代需要操作者身份的功能。
- Go 模块按已有业务域组织：领域逻辑、存储接口、HTTP 适配和外部客户端保持可辨识；不强制为简单功能建立多层空接口。
- Vue 模块把 API、路由页面、composable 和领域类型按功能归属，只有多个实际消费者才提升共享组件；工程源码模板不依赖平台内部源码。
- .NET 驱动只依赖共享契约与必要适配层。DevAgent 负责短链调试，Runtime 负责持续采集、缓存和重放，不复用调试身份运行生产任务。
- contracts 中的描述可复制进制品，不能在各模块维护手改副本。测试必须验证消费者读取相同版本。
- 业务数据库、对象存储、队列和现场缓存分别指定写入方。禁止跨服务直接改表；缓存不能成为第二套主事实。

## 各模块开发与验证要求

| 模块                  | 必须守住的边界                                                                                     | 与改动匹配的验证                                                        |
| --------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 控制面                | tenant / project / epoch 授权；发布可追溯；部署任务幂等；期望与观测分开                            | 对应 Go 包测试；权限负例；数据库基线变更验空库；部署重试与过期请求      |
| IDE                   | 后端权限为准；Cookie 会话；HTTP 获取权威状态，事件驱动刷新；工作区身份不串工程                     | 类型检查、权限与交互测试；真实入口检查加载、失败、刷新、重复点击        |
| 数据域                | 模型与预览分开；查询限额；事务；快照冻结；跨租户拒绝                                               | Go 服务/仓储测试、工件契约验证；真实数据库集成另列环境与结果            |
| DataCenter            | 按后端能力展示；增长数据分页；无在线采集执行器仍允许配置建模，保存依赖数据服务；真实调试须有执行器 | 类型检查、关键表单和批量操作测试；禁用、空态、错误、导入部分失败        |
| Designer / Workspace  | 当前工程上下文与编辑代次；受控 iframe；源码唯一事实；冻结与恢复不串写                              | 类型检查、请求/代理测试；浏览器登录、预览刷新、订阅与恢复验收           |
| Gateway / Runtime API | 工程与部署身份；服务端授权；不能伪造操作者；会话与动作经过真实入口                                 | Go 测试；匿名/越权/撤销/重复动作负例；通过 Gateway 的端到端验证         |
| RuntimeEngine         | 消息身份、顺序、幂等、背压、状态恢复与排空；业务数据不由中心心跳决定                               | Go 测试；重复/乱序/重放与存储失败；目标消息与数据库集成                 |
| Compute Sandbox       | 只读工件、固定依赖、纯计算、时间/内存/PID/网络限制                                                 | Go 测试；Linux 隔离与超时/越界验收，语言级沙箱不算隔离证据              |

| Node Console          | 本机操作边界、接入状态真实、敏感信息不进页面与日志                                                 | 前端构建及交互测试；离线、未接入、权限失败与重试                        |
| SDK / contracts       | 公开类型与事件一致；开发与运行适配分开；不暴露平台 Token                                           | SDK 测试、契约正反例、模板消费者构建                                    |

测试入口以根 package.json、模块 Makefile 或测试项目为准。默认 pnpm test / build 不覆盖所有 Go、.NET、SDK 和安装脚本；不能用聚合命令成功声称全仓通过。无真实服务授权时只运行自动清理的隔离测试，明确未验收的目标平台条件。

## 两类交付清单

平台包包含开发管理、工作区、平台存储与授权及部署管理；工程应用包包含 Release、运行组件、现场依赖、工程身份初始化和应用授权。两类包都需要版本清单、摘要、安装前检查、故障诊断及数据恢复路径。

运行包不携带平台开发账号、中心签名私钥、可写开发缓存或客户无权取得的源码。客户是否购买源码和二次开发权由交付范围决定；现场凭据在安装时装配。

正式客户版本前必须确定运行账号变更、数据备份、密钥轮换、存量数据升级和失败恢复策略。当前“空库最终基线”适用于开发阶段，不能宣称已经解决客户升级。
