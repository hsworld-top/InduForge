# 数据中心 Modbus 寄存器建模工作台设计

> 日期：2026-05-25
> 范围：`datacenter/` Modbus 接入源工作台、`data_service/` Modbus 寄存器建模接口、数据点同步与运行契约输出。
> 目标：将 Modbus 接入源工作台定义为运行态采集契约的寄存器变量建模入口，支持多从站地址、寄存器组、变量、解析规则、数据点自动生成、建模校验、辅助预览和运行态读取预估。

## 1. 定位

Modbus 工作台不是长期采集控制台，也不是运行态发布入口。它负责把 Modbus 设备或网关下的寄存器地址建模成平台可消费的变量和数据点，并通过外部统一发布入口进入运行态契约。

工作台内部负责：

- 维护 Modbus 寄存器组。
- 手工新建变量，或通过粘贴表格、地址段生成批量导入变量。
- 支持一个 Modbus 接入源下管理多个从站地址，也就是 `UnitId / SlaveId`。
- 保存寄存器区域、用户地址、协议地址、数据类型、字节序、字序、倍率、偏移、单位、轮询周期和读写权限。
- 自动生成或同步 `data_points(source_type='modbus.register')`。
- 展示变量最近值与质量，作为辅助预览结果。
- 执行建模校验并定位问题。
- 展示运行态读取预估，让用户理解变量会被合并成多少次读取请求。

工作台内部不负责：

- 长期轮询、重连、退避和质量码持续处理。
- 多运行态节点的 Owner / Lease / Failover 执行。
- 外部运行契约发布。
- 手动维护运行态读取计划。

## 2. 当前现状

当前后端已有：

- `data_connections(type='modbus')`：通用接入源主表。
- `data_modbus_configs`：Modbus 连接配置表，字段包括 `mode`、`host`、`port`、`serial_config`、`slave_id`、`start_address`、`quantity`、`poll_interval_ms`、`options`。
- `data_points`：统一数据点表，支持通过 `source_type`、`source_id` 和 `source_config` 关联协议侧定义。
- 连接测试：Modbus TCP 做端口可达探测；Modbus RTU 做基础配置校验。

当前前端已有：

- 创建 Modbus 接入源表单。
- 接入源详情页配置展示。
- `IndustrialProtocolWorkbench.vue` 占位式工作台，当前只按连接配置生成示例寄存器行。

当前缺少：

- Modbus 寄存器组表。
- Modbus 变量 / 寄存器定义表。
- Modbus 变量与数据点的专用同步逻辑。
- 面向工作台的 Modbus 建模校验接口。
- 面向运行态的 Modbus 寄存器变量和读取计划契约输出。

## 3. 用户概念

用户只需要理解三个核心概念：

- **寄存器组**：按产线、设备、区域组织变量。
- **变量**：用户关心的业务值，例如电机转速、温度、启停状态。
- **从站地址**：Modbus 的 `UnitId / SlaveId`，用于区分同一个 TCP 网关或串口总线下的不同设备。

界面上建议优先使用“从站地址”，必要时在辅助说明中显示 `UnitId`。例如：

```text
从站地址(UnitId)：1
```

## 4. 数据模型

新增 `data_modbus_register_groups`，用于保存寄存器组。

建议字段：

- `id`
- `project_id`
- `connection_id`
- `parent_id`
- `name`
- `description`
- `sort_order`
- `created_by`
- `updated_by`
- `created_at`
- `updated_at`

新增 `data_modbus_registers`，用于保存用户建模的 Modbus 变量。

建议字段：

- `id`
- `project_id`
- `connection_id`
- `group_id`
- `name`
- `code`
- `unit_id`
- `area`
- `address`
- `address_base`
- `protocol_address`
- `quantity`
- `data_type`
- `byte_order`
- `word_order`
- `bit_index`
- `scale`
- `offset`
- `unit`
- `poll_interval_ms`
- `timeout_ms`
- `retry_count`
- `access_level`
- `description`
- `sort_order`
- `status`
- `created_by`
- `updated_by`
- `created_at`
- `updated_at`

字段说明：

- `area`：`coil`、`discrete_input`、`input_register`、`holding_register`。
- `address`：用户输入的地址，例如 `40001`。
- `address_base`：地址基准，例如 `modicon`、`one_based`、`zero_based`。
- `protocol_address`：系统换算后的协议地址，例如 `40001` 对应 Holding Register 的协议地址 `0`。
- `quantity`：寄存器数量。普通数值类型由系统根据 `data_type` 自动推导，高级类型允许用户设置。

每条 `data_modbus_registers` 自动同步一条 `data_points`：

- `source_type = 'modbus.register'`
- `source_id = data_modbus_registers.id`
- `source_config` 包含 `connectionId`、`unitId`、`area`、`protocolAddress`、`quantity`、`dataType`、`byteOrder`、`wordOrder`、`bitIndex`、`scale`、`offset`、`pollIntervalMs`、`accessLevel`
- `refresh_mode = 'polling'`
- `status = 'active'`

删除 Modbus 变量时，不物理删除对应数据点，改为将数据点标记为 `invalid`。

主界面采用与 OPC UA / MQTT 家族化一致的三栏结构：

- 左侧：寄存器组树，支持搜索、新建、编辑、删除和选择。
- 中间：当前寄存器组下的变量表格，承担主要浏览与操作。
- 右侧：随选择对象变化，展示寄存器组信息或变量详情、解析规则、数据点、读取预估和校验问题。

## 6. 变量表格

表格列：

```text
变量名 | Code | 从站地址 | 区域 | 用户地址 | 协议地址 | 类型 | 字节序 | 数据点 | 最近值 | 质量 | 状态 | 操作
```

字段含义：

- `变量名`：用户可读名称，允许用户自定义。
- `Code`：变量标识符，同一连接下唯一。
- `从站地址`：`UnitId / SlaveId`。
- `区域`：Coil、Discrete Input、Input Register、Holding Register。
- `用户地址`：用户熟悉的地址，例如 `40001`。
- `协议地址`：系统换算后的 0-based 协议地址，例如 `0`。
- `类型`：变量解析后的数据类型，例如 `float32`。
- `字节序`：例如 `ABCD`、`BADC`、`CDAB`、`DCBA`。
- `数据点`：系统自动同步的 `data_points.path`。
- `最近值`：变量预览或后端最近值接口返回的辅助结果。
- `质量`：辅助预览质量，未预览时显示 `-`。
- `状态`：建模状态与数据点状态。
- `操作`：编辑、删除。

## 8. 运行态读取预估

运行态读取预估只用于说明运行态将如何合并读取，不需要用户手动配置。

它回答三个问题：

- 用户建了多少变量。
- 运行态预计会把这些变量合并成多少次读取。
- 当前建模是否可能给设备造成过高读取压力。

合并规则：

- 不同连接不合并。
- 不同从站地址不合并。
- 不同寄存器区域不合并。
- 不同轮询周期不合并。
- 地址连续或小间隔地址可合并，最终不能超过 Modbus 单次读取上限。

用户界面中不建议使用“覆盖变量”这个词，统一使用“本次读取变量数”。

示例：

```text
用户变量：
电机转速：从站地址=1，Holding Register，40001，float32
电机温度：从站地址=1，Holding Register，40003，float32

运行态可合并为：
从站地址=1，Holding Register，读取范围 40001-40004，本次读取变量数=2
```

## 10. 用户流程

```text
进入 Modbus 接入源
→ 创建或选择寄存器组
→ 导入变量，或手工新建变量
→ 填写从站地址、寄存器区域、用户地址和解析规则
→ 系统换算协议地址
→ 系统自动生成 modbus.register 数据点
→ 用户检查变量表和右侧配置
→ 查看运行态读取预估，判断读取压力
→ 执行建模校验
→ 可选变量预览，确认地址和解析规则
→ 返回外部统一发布运行契约
```

## 11. 校验规则

建模校验应覆盖：

- 变量名为空。
- `code` 为空或同连接下重复。
- 从站地址为空或越界。默认建议合法范围为 `1-247`，可允许 TCP 场景的特殊 `0`。
- 寄存器区域为空或不合法。
- 用户地址无法根据地址基准换算为协议地址。
- 协议地址小于 0。
- 寄存器数量小于等于 0。
- `float32`、`int32`、`uint32` 至少需要 2 个寄存器。
- `float64`、`int64`、`uint64` 至少需要 4 个寄存器。
- Coil / Discrete Input 默认只支持 `bool`。
- `bitIndex` 只能在 `0-15`。
- 写权限只允许 Coil 和 Holding Register。
- Discrete Input 和 Input Register 不允许写入。
- 同一连接 + 从站地址 + 寄存器区域 + 地址范围重叠时提示 warning。
- 数据点未生成时报 error。
- 数据点已失效时报 warning。
- 寄存器组不存在时报 error。

## 12. 运行契约输出

外部发布运行契约时，应从 Modbus 建模表和数据点表汇总：

- Modbus 连接配置。
- Modbus 寄存器组。
- Modbus 变量定义。
- 数据点 path 与 `source_type='modbus.register'` 的映射。
- 轮询周期、解析规则、读写权限等运行态采集参数。
- 运行态读取计划 `readPlans`。

artifact 建议包含两个层次：

```json
{
  "registers": [],
  "readPlans": []
}
```

`registers` 保留用户建模结果，`readPlans` 给运行态高效执行。

读取计划生成原则：

- 按 `connectionId + unitId + area + pollIntervalMs` 分组。
- 地址排序后合并连续或小间隔地址。
- Holding Register / Input Register 单次读取默认不超过 125 个寄存器。
- Coil / Discrete Input 单次读取遵守 Modbus 点数上限。
- RTU 模式必须串行执行。
- TCP 模式可由运行态根据连接配置控制最大并发。

## 13. 高可用与运行态边界

后续多运行态节点时，最大风险是多个节点同时轮询同一台设备。设计原则：

```text
同一个 readPlan 同一时刻只有一个运行态 Owner。
```

运行态可采用：

- 基于连接或 readPlan 的 lease。
- consistent hashing 分片。
- lease TTL + fencing token。
- 节点掉线后的自动转移。
- 转移冷却时间，避免频繁抖动。

默认推荐按连接或从站地址分片。不要默认让多个节点同时采集同一个连接的同一个读取计划。
