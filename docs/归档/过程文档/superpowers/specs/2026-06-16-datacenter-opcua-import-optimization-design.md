# 数据中心 OPC UA 变量导入优化设计

> 日期：2026-06-16
> 范围：`datacenter/` OPC UA 工作台变量导入弹窗与 `data_service/` OPC UA 批量导入接口。
> 目标：完整优化 OPC UA 工作台内的浏览导入和批量 NodeId 导入体验，并将后端批量导入改为可验证、事务化、不会半成功的流程。

## 1. 背景

当前 OPC UA 工作台已有变量导入入口：

- 浏览导入：从开发态会话浏览结果中选择变量节点。
- 批量 NodeId：在文本框中按行输入 `NodeId,类型,变量名`。
- 导入提交：前端把候选行发送到 `batchImportOpcuaNodes`，后端逐条调用创建变量逻辑。

现状问题：

- 浏览导入是扁平表格，缺少 OPC UA 地址空间的层级感。
- 批量 NodeId 只支持单一格式，复制粘贴容错不足。
- 前端缺少统一预检，用户不容易提前知道哪些行会跳过、哪些会失败。
- 后端批量导入逐条创建，遇到重复 NodeId、重复 Code 或数据点同步失败时，可能出现前几条已成功、后续失败的半成功状态。

## 2. 决策

本次采用“统一预检确认 + 后端事务导入”方案。

不在本次接入真实 OPC UA Server 地址空间浏览适配器。当前后端浏览结果仍可能来自已建模变量投影，但前端按真实浏览适配器可复用的 `parentId`、`nodeType`、`nodeId`、`dataType` 结构组织界面。

已确认规则：

- 重复 NodeId 默认跳过，不覆盖已有变量。
- Code 冲突自动生成唯一 Code，例如 `speed`、`speed_2`、`speed_3`。
- 批量 NodeId 支持智能解析常见粘贴格式。
- 浏览导入采用左侧树/路径浏览 + 右侧确认表。
- 提交时如存在跳过或错误行，二次确认“跳过 M 行、导入 N 行”。
- 导入弹窗提供批量默认值，确认表允许逐行微调。
- 单次批量导入上限为 1000 条。

## 3. 前端设计

### 3.1 弹窗结构

`OpcuaImportDialog` 保留两个入口页签：

- 浏览导入。
- 批量 NodeId。

两个入口都只负责产生候选行。候选行统一进入下方确认表，由同一套预检、编辑、错误展示和提交逻辑处理。

### 3.2 浏览导入

浏览导入改为树/路径浏览：

- 文件夹节点用于定位，不可导入。
- 变量节点可勾选。
- 已建模变量显示“已存在”，默认不可提交。
- 支持搜索 NodeId、节点名称、路径、数据类型。
- 支持刷新浏览结果。

树形数据由浏览结果的 `parentId` 构建。若后端返回的是扁平变量列表，前端仍按 `parentId` 和节点路径组织展示；若后续接入真实 OPC UA 浏览适配器，前端结构不需要大改。

### 3.3 批量 NodeId 智能解析

批量文本输入支持以下格式：

- 每行一个 NodeId，例如 `ns=2;s=Line1.Motor.Speed`。
- 逗号分隔：`NodeId,类型,变量名`。
- 空白分隔：`变量名 NodeId 类型`，其中 NodeId 通过 `ns=...`、`i=`、`s=`、`g=`、`b=` 等片段识别。
- CSV / TSV / Excel 粘贴内容，优先识别表头别名。

表头别名建议：

- 变量名：`变量名`、`名称`、`name`、`displayName`。
- Code：`Code`、`编码`、`code`。
- NodeId：`NodeId`、`节点ID`、`nodeId`。
- 数据类型：`数据类型`、`类型`、`dataType`、`type`。
- 单位：`单位`、`unit`。
- 采样周期：`采样周期`、`周期`、`samplingMs`、`interval`。
- 访问级别：`访问级别`、`发布能力`、`accessLevel`。
- 死区：`死区`、`deadband`。
- 描述：`描述`、`说明`、`description`。

解析失败的行进入确认表并标记问题，不直接丢弃。

### 3.4 统一确认表

确认表字段：

- 状态。
- 变量名。
- Code。
- NodeId。
- 数据类型。
- 采样周期。
- 访问级别。
- 死区。
- 单位。
- 问题说明。

行状态：

- `可导入`：字段完整、NodeId 未建模、Code 唯一。
- `已存在`：NodeId 已在当前连接建模，默认跳过。
- `重复`：本批次 NodeId 重复，或 Code 无法生成唯一值。
- `错误`：NodeId 为空、数据类型为空、采样周期无效等。

顶部摘要显示：

- 总候选数。
- 可导入数。
- 跳过数。
- 错误数。

交互：

- “只看问题”开关。
- “错误报告”导出，字段包括行号、状态、变量名、Code、NodeId、数据类型、问题说明。
- 批量默认值：采样周期、访问级别、死区、单位。
- 批量默认值应用后重新预检。
- 表内允许逐行编辑变量名、数据类型、采样周期、访问级别、死区、单位。
- Code 默认自动生成并显示，用户不需要手工处理常见冲突。

### 3.5 提交

提交按钮文案为 `导入 N 个变量`，其中 N 是可导入行数量。

当 N 为 0 时禁用提交。

当存在跳过或错误行时，点击导入弹出二次确认：

```text
本次将导入 N 个变量，跳过 M 行问题数据。是否继续？
```

用户确认后，前端只提交可导入行。问题行和已存在行不发送到后端。

## 4. 后端设计

### 4.1 批量导入事务

`OpcuaModelingService.BatchImportNodes` 改为批量事务流程，不再逐条调用 `CreateNode`。

流程：

1. 校验用户、项目、接入源类型。
2. 校验入参非空且不超过 1000 条。
3. 规范化每行字段：NodeId、变量名、Code、数据类型、采样周期、访问级别、死区、单位、描述。
4. 查询当前连接下已有 NodeId 和 Code。
5. 检查本批次 NodeId 重复。
6. 为缺失或冲突的 Code 自动生成唯一值。
7. 若仍存在不可导入行，返回清晰业务错误，不写入任何数据。
8. 在同一事务中插入变量并同步对应 `opcua.node` 数据点。
9. 任一变量或数据点写入失败，事务整体回滚。

### 4.2 重复处理

后端兜底规则：

- 请求中包含数据库已存在 NodeId：拒绝本次导入，错误中说明冲突 NodeId。
- 请求中包含本批次重复 NodeId：拒绝本次导入，错误中说明重复行。
- Code 冲突：自动生成唯一 Code。
- 自动生成唯一 Code 超过内部尝试上限仍失败：拒绝本次导入。

前端会提前过滤已存在 NodeId，但后端必须保留兜底，防止并发导入或绕过前端。

### 4.3 数据点同步

批量导入仍需为每个变量同步 `data_points`：

- `source_type = 'opcua.node'`
- `source_id = data_opcua_nodes.id`
- `source_config = { connectionId, nodeId, samplingMs, deadband, accessLevel }`
- `refresh_mode = 'subscription'`
- `status = 'active'`

变量和数据点必须处于同一个批量导入结果中。若数据点同步失败，变量写入也回滚。

## 5. API 影响

前端仍调用现有接口：

```text
POST /api/v1/data/projects/{projectId}/opcua/{connectionId}/nodes/batch-import
```

请求结构保持：

```json
{
  "groupId": "optional-group-id",
  "nodes": []
}
```

允许后端响应继续返回：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "list": []
  },
  "reqId": "..."
}
```

错误响应使用现有统一错误结构。除非实现时确认需要机器可读的逐行错误码，否则本次不新增全局错误码。

## 6. 非目标

本次不做：

- 真实 OPC UA Server 地址空间浏览适配器。
- 覆盖更新已存在 NodeId。
- 异步导入任务队列。
- 超过 1000 条的大批量虚拟表格导入。
- 导入后自动发布运行契约。

## 7. 验证

前端静态验证：

```text
pnpm --filter datacenter typecheck
```

后端验证：

```text
go test ./...
```

若全量 Go 测试耗时或环境依赖过重，至少执行 `data_service` 相关测试，并说明未验证范围。

手动验收建议：

- 打开 OPC UA 工作台，连接开发态会话后进入导入弹窗。
- 浏览导入中勾选变量，已存在变量显示为跳过，不进入提交。
- 批量 NodeId 粘贴多种格式，能解析并进入确认表。
- 本批次重复 NodeId 被标记为问题。
- Code 冲突自动补后缀。
- 批量默认采样周期、访问级别、死区、单位能应用到候选行。
- 存在问题行时点击导入，会二次确认跳过数量。
- 后端遇到重复 NodeId 请求时不写入任何变量。
- 后端任一数据点同步失败时批量事务回滚。
