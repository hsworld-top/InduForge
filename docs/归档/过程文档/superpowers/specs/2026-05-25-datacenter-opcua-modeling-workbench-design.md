# 数据中心 OPC UA 点位建模工作台设计

> 日期：2026-05-25
> 范围：`datacenter/` OPC UA 接入源工作台、`data_service/` OPC UA 点位建模接口、数据点同步与运行契约输出。
> 目标：将 OPC UA 接入源工作台定义为运行态采集契约的点位建模入口，完成变量组、变量、NodeId、采样策略、数据点自动生成、建模校验与辅助预览的闭环。

## 1. 定位

OPC UA 工作台不是长期采集控制台，也不是运行态发布入口。它负责把 OPC UA Server 中的节点建模成平台可消费的变量和数据点，并通过外部统一发布入口进入运行态契约。

工作台内部负责：

- 维护 OPC UA 变量组。
- 从 OPC UA 地址空间导入变量，或手工新建变量。
- 允许用户在导入确认或编辑变量时修改变量名，避免同名节点难以识别。
- 保存 NodeId、数据类型、采样周期、死区、访问级别等协议字段。
- 自动生成或同步 `data_points(source_type='opcua.node')`。
- 展示变量最近值与质量，作为辅助预览结果。
- 执行建模校验并定位问题。

工作台内部不负责：

- 长期采集、订阅、重连和质量码持续处理。
- 外部运行契约发布。
- 业务模型字段绑定主流程。
- 手动触发“自动映射数据点”。

## 2. 当前后端现状

当前数据库已有：

- `data_connections`：通用接入源主表，`type` 支持 `opcua`，`category` 可为 `protocol`。
- `data_opcua_configs`：OPC UA 连接配置表，字段包括 `endpoint`、`security_policy`、`security_mode`、`auth_type`、`username`、`password`、`sampling_ms`、`options`。
- `data_points`：统一数据点表，支持通过 `source_type`、`source_id` 和 `source_config` 关联协议侧定义。

当前数据库缺少：

- OPC UA 变量组表。
- OPC UA 变量 / 节点定义表。
- OPC UA 变量与数据点的专用同步逻辑。
- 面向工作台的 OPC UA 建模校验接口。

## 3. 目标数据模型

新增 `data_opcua_node_groups`，用于保存 OPC UA 变量组。

建议字段：

- `id`
- `project_id`
- `connection_id`
- `parent_id`
- `name`
- `description`
- `sort_order`
- `created_by`
- `updated_by`
- `created_at`
- `updated_at`

新增 `data_opcua_nodes`，用于保存用户建模的 OPC UA 变量。

建议字段：

- `id`
- `project_id`
- `connection_id`
- `group_id`
- `name`
- `code`
- `node_id`
- `browse_name`
- `display_name`
- `data_type`
- `unit`
- `sampling_ms`
- `deadband`
- `access_level`
- `description`
- `sort_order`
- `status`
- `created_by`
- `updated_by`
- `created_at`
- `updated_at`

每条 `data_opcua_nodes` 自动同步一条 `data_points`：

- `source_type = 'opcua.node'`
- `source_id = data_opcua_nodes.id`
- `source_config = { connectionId, nodeId, samplingMs, deadband, accessLevel }`
- `refresh_mode = 'subscription'`
- `status = 'active'`

删除 OPC UA 变量时，不物理删除对应数据点，改为将数据点标记为 `invalid`。

## 4. 主界面原型

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ OPC UA 工作台：一号产线 OPC UA                                                │
│ opc.tcp://192.168.1.10:4840                                                   │
│ 状态：12 个变量 · 12 个数据点 · 2 个校验问题                                   │
│ [测试连接] [从 OPC UA 导入变量] [新建变量] [变量预览] [建模校验] [刷新]          │
├──────────────────────┬──────────────────────────────────────┬────────────────┤
│ 变量组列表             │ 当前变量组：Motor01                  │ 右侧配置面板     │
│                      │                                      │                │
│ [搜索变量组]           │ [搜索变量] [批量操作] [更多]          │ 变量组信息       │
│ [+ 新建变量组]         │                                      │ / 变量信息       │
│                      │ 变量表格                              │                │
│ ▼ 一号产线             │ ┌──────────────────────────────────┐ │ 采样策略         │
│   ◉ Motor01           │ │ 变量名 | NodeId | 类型 | 数据点    │ │                │
│   ◉ Motor02           │ │ 最近值 | 质量 | 状态 | 操作        │ │ 数据点信息       │
│   ◉ Pump01            │ └──────────────────────────────────┘ │                │
│                      │                                      │ 校验问题         │
└──────────────────────┴──────────────────────────────────────┴────────────────┘
```

主界面采用三栏结构：

- 左侧：变量组树，支持搜索、新建、编辑、删除和选择。
- 中间：当前变量组下的变量表格，承担主要批量浏览与操作。
- 右侧：随选择对象变化，展示变量组信息或变量详情、采样策略、数据点信息和校验问题。

## 5. 变量组列表

```text
┌──────────── 变量组列表 ────────────┐
│ [搜索变量组]                        │
│ [+ 新建变量组]                      │
│                                    │
│ ▼ 一号产线                          │
│   ◉ Motor01        6 个变量          │
│   ◉ Motor02        4 个变量          │
│   ◉ Pump01         2 个变量          │
│                                    │
└────────────────────────────────────┘
```

变量组用于用户按产线、设备、功能区域组织 OPC UA 变量。根组可以是系统内置“未分组”，也可以允许用户新建顶层组。

## 6. 变量表格

表格列：

```text
变量名 | NodeId | 类型 | 数据点 | 最近值 | 质量 | 状态 | 操作
```

字段含义：

- `变量名`：用户可读名称。导入时默认来自 OPC UA 节点 `DisplayName`，其次 `BrowseName`，再次 `NodeId` 最后一段；导入确认阶段允许修改。
- `NodeId`：OPC UA 节点标识。
- `类型`：OPC UA 数据类型映射后的平台数据类型。
- `数据点`：系统自动同步的 `data_points.path`。
- `最近值`：变量预览或后端最近值接口返回的辅助结果。
- `质量`：辅助预览质量，未预览时显示 `-`。
- `状态`：建模状态与数据点状态，如 `活跃`、`失效`、`校验异常`。
- `操作`：查看、编辑、删除。

导入默认命名规则：

1. 使用 `DisplayName`。
2. 没有 `DisplayName` 时使用 `BrowseName`。
3. 没有 `BrowseName` 时使用 `NodeId` 最后一段。

导入确认表格中的变量名允许编辑，避免同名节点导入后用户难以识别。

## 9. 用户流程

```text
进入 OPC UA 接入源
→ 创建或选择变量组
→ 从 OPC UA 导入变量，或手工新建变量
→ 导入确认或新建表单中可修改变量名
→ 系统自动生成 opcua.node 数据点
→ 用户检查变量表和右侧配置
→ 执行建模校验
→ 可选变量预览，确认 NodeId 和类型
→ 返回外部统一发布运行契约
```

## 10. 校验规则

建模校验应覆盖：

- 变量名为空。
- `code` 为空或重复。
- `NodeId` 为空。
- 同一连接下 `NodeId` 重复。
- 数据类型为空。
- 采样周期无效。
- 死区无效。
- 数据点未生成。
- 数据点 path 冲突。
- 数据点已失效。
- 变量组不存在。

校验结果需要能定位到变量或变量组。

## 11. 接口边界

需要新增或完善的接口：

- 变量组列表、创建、更新、删除、移动。
- OPC UA 变量列表、创建、批量创建、更新、删除、批量移动、批量采样策略更新。
- OPC UA 节点浏览 / 搜索接口，用于导入变量。
- OPC UA 变量预览接口，用于短时读取当前组或选中变量。
- OPC UA 建模校验接口。
- 数据点同步逻辑，变量创建或更新后自动 upsert `opcua.node` 数据点。

所有接口继续遵循统一响应：`code`、`msg`、`data`、`reqId`。

## 12. 运行契约输出

外部发布运行契约时，应从 OPC UA 建模表和数据点表汇总：

- OPC UA 连接配置。
- OPC UA 变量组。
- OPC UA 变量定义。
- 数据点 path 与 `source_type='opcua.node'` 的映射。
- 采样周期、死区、访问级别等运行态采集参数。

运行态负责真实 OPC UA 连接、订阅、采集、质量码处理和重连。

## 13. 验证

静态验证：

- `pnpm --filter datacenter typecheck`
- `pnpm --filter datacenter build`
- `go test ./...` 或最贴近变更面的 `data_service` 测试

手动验收：

- 创建 OPC UA 变量组，左侧树刷新并选中。
- 导入变量时默认名称来自 OPC UA 节点名称，且允许修改变量名。
- 新建变量保存后自动生成数据点。
- 编辑变量采样策略后数据点 `source_config` 同步更新。
- 删除变量后对应数据点标记失效。
- 建模校验能列出问题并定位变量。
- 变量预览能回填最近值和质量，不影响外部运行契约发布入口。
