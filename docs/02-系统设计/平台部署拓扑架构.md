# 平台部署拓扑架构

本文描述当前代码中的部署路径与故障边界。商业交付目标见 [产品定义](../01-产品与架构/产品定义.md)；代码路径存在不表示已完成冷安装、断网或灾难恢复验收。

## 当前部署关系

```text
私有平台实例
├─ 中心服务器
│  ├─ 宿主 NodeAgent / Hostd / K3s 控制节点
│  ├─ induforge-system：入口、控制面、数据服务、中心存储
│  └─ Docker：代码工作区与 Release Builder
├─ Linux 工作节点
│  ├─ 宿主 NodeAgent / Hostd
│  ├─ K3s 工作节点：运行环境基础服务与工程工作负载
│  └─ NodeAgent 托管的原生采集进程
└─ Windows 采集节点
   └─ NodeAgent 与采集进程；不作为 Linux 工作节点加入

运行环境 if-env-*：节点集合、基础服务与工程调度范围
工程入口 → 同组 Runtime API → 现场 PostgreSQL / NATS
生产采集器 → NATS → RuntimeEngine → 运行数据与计算沙箱
```

[centerctl](../../scripts/k3s/center/centerctl) 将中心服务固定到中心节点；每个实例当前维护一套集群和唯一控制节点。环境可关联多台 Linux 节点，同一物理节点可以被多个环境复用，因此环境不等同于独立集群或物理隔离。

中心存储与运行环境存储分开管理。单中心和本地持久卷不具备多中心或自动存储故障转移承诺。

## 控制面、工作区与运行域

中心入口、dev_core、data_service、元数据库、缓存和对象存储由中心 K3s 清单管理。中心 Pod 健康检查、初始化和镜像版本保存见 [中心部署说明](../../scripts/k3s/center/README.md)。

代码工作区与 Release Builder 当前仍由 Docker 路径承载，控制服务因此保留宿主 Docker Socket 依赖。这是待审查的隔离边界，不能将中心迁到 K3s 描述成工作区也已迁入。发布构建使用独立受控镜像，不应打包编辑器和开发服务器。

工程工作负载由 [project_workload.go](../../dev_core/internal/ops/project_workload.go) 生成，并由 [kubernetes_reconciler.go](../../dev_core/internal/ops/kubernetes_reconciler.go) 调和和观测。原生采集配置由 [native_collector.go](../../dev_core/internal/ops/native_collector.go) 向获授权节点提供，NodeAgent 托管 .NET Collector；不能再将旧 Collector Pod 当作此路径的验收证据。

NodeAgent 内仍有本机运行组件激活实现。原生组件与 K3s 工作负载必须按真实入口分别检查，不能在文档中混成“全部原生”或“全部容器”。

## 网络与身份边界

| 通道                   | 用途及要求                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------- |
| 浏览器 → 平台入口      | 平台登录、开发和运维，使用同源 Cookie 与平台权限                                      |
| 开发页面 → 工程工作区  | 使用受控工作区地址、工程上下文和编辑代次；开发 HTTP 代理例外不扩大到生产              |
| NodeAgent → 中心       | 接入、命令、心跳、授权下载；生产要求受信 HTTPS                                        |
| 工厂浏览器 → 工程入口  | 与平台开发入口分开；当前网关为只读 viewer，完整工程用户登录仍需贯通                   |
| 工程入口 → Runtime API | 当前要求同组回环代理并注入工程 / 部署身份；不把内部数据服务暴露给浏览器               |
| 运行组件 → 基础服务    | 现场数据和消息通道，按部署身份约束凭据与资源                                          |
| 原生 Collector → NATS  | 当前中心实现生成 NodePort 和 nats:// 地址；传输保护、端口暴露及项目隔离需生产专项验收 |

平台账号、工程运行账号和节点机器身份互不替代。安装包不包含长期中心私钥；部署 Secret 不进入普通状态、页面或日志。现有原生包 development 配置不能作为生产安全承诺。

## 离线与故障边界

- 中心应用不可用时，已启动的运行组件不应被主动停止；但仍依赖其配置的 PostgreSQL、NATS、沙箱和存储可达。
- 关闭中心应用、关闭中心主机和断开公网分别验收。若基础服务承载在中心主机，同机停机也会影响现场运行。
- 节点失联仅说明观测过期；不能把最后一次健康状态作为当前事实，也不能因此删除数据。
- Release 校验失败不替换已确认版本；停止保留采集 WAL，明确删除才清理对应部署，旧代次不得清理新进程的数据。
- 基础服务分布、工程副本、消息持久化和故障接管分别验收，不能用“多节点”代替高可用证明。

## 交付入口收敛要求

当前 scripts/offline 仍有平台 Compose 安装，而正式中心已有 K3s 路径；独立工程应用包也不能用整个平台包代替。两类交付清单、数据与密钥归属、安装前检查、升级失败恢复、备份恢复和卸载影响必须统一后再形成客户发布版本。

本次文档整理不移动或改写安装器、scripts/docker 或 scripts/nginx。目标归属与模块要求见 [仓库结构与模块规范](../05-研发与交付/仓库结构与模块规范.md)；详细协议见 [NodeAgent 运行协议](../04-契约与规范/跨模块契约/node-agent-runtime-protocol.md)。
