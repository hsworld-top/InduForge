# 工程运行系统架构

## 1. 系统定位

工程运行系统部署在生产站点，承载发布后工程的页面、API、数据处理、报警、计算、存储和动作执行。

二级运行用户直接访问站点为工程分配的独立地址；中心平台不代理工程运行请求。

## 2. 站点共享底座

![工程运行系统技术架构](../assets/architecture/工程运行技术架构.svg)

可编辑源文件：[工程运行技术架构.drawio](../diagrams/工程运行技术架构.drawio)。

一个运行站点共享：

```text
K3s
NATS JetStream
Ingress Controller
StorageClass
站点监控与日志
Site NodeAgent（K3s 外）
```

站点服务不解析和管理工程页面资源；工程资源始终随 Project Release 走。

## 3. 工程隔离模型

| 平台对象 | 运行资源                               |
| -------- | -------------------------------------- |
| Site     | 一套 K3s                               |
| Site     | 一套 NATS JetStream                    |
| Project  | 一个 K3s Namespace                     |
| Project  | 一个 NATS Account                      |
| Project  | 独立 ServiceAccount、Secret、ConfigMap |
| Project  | 独立 PVC 和运行数据空间                |
| Release  | 独立不可变工程版本                     |

## 4. 工程 Namespace

```text
project-a
├─ release-loader Job
├─ project-nginx
├─ runtime-api
├─ data-engine-writer
├─ data-engine-alarm
├─ data-engine-compute
├─ data-engine-query
├─ ConfigMap / Secret
└─ Project PVC
```

`client_engine` 是由 `project-nginx` 托管的静态资源，不运行常驻 Node 服务。

## 5. 微服务形态

推荐少量镜像、多角色运行：

| 镜像                  | 角色                                 |
| --------------------- | ------------------------------------ |
| `project-nginx`       | 静态页面和工程 HTTP 入口             |
| `runtime-api`         | 登录、权限、查询、动作和 WebSocket   |
| `runtime-data-engine` | writer、alarm、compute、query、coord |
| `release-loader`      | 下载、校验和展开工程 Release         |

数据引擎角色使用独立 Deployment，便于故障隔离和独立扩缩，但共享同一代码和消息契约。

## 6. 交互方式

### 6.1 同步接口

```text
浏览器
→ Ingress
→ project-nginx
→ runtime-api
```

用于登录、Bootstrap、查询、历史数据、报警确认和动作请求。

### 6.2 可靠异步事件

```text
Collector
→ NATS JetStream
→ writer / alarm / compute
```

### 6.3 实时页面

```text
NATS
→ runtime-api
→ WebSocket
→ client_engine
```

### 6.4 文件

Release、导出文件和备份使用 S3/HTTPS/PVC，不通过 JetStream 传输。

## 7. 页面资源

```text
中心 S3
→ release-loader
→ 工程 PVC
→ project-nginx
→ 浏览器
```

浏览器不直接访问中心 S3；中心断网后已部署页面仍能加载。

## 8. 数据与存储

工程运行数据可以使用站点共享数据库基础设施，但必须按工程隔离 Database、Schema、用户或存储桶。工程 Namespace 只持有自己的连接凭据。

## 9. 离线自治

中心断开时继续可用：

- 页面加载和运行态登录。
- Collector 数据上行。
- JetStream 消息处理。
- Writer、Alarm、Compute 和 Query。
- 本地历史数据和运行 API。

中心断开时不可用：

- 新 Release 发布。
- 中心统一管理操作。
- 新授权或中心资源下载。

## 10. 高可用

- 小站点允许单节点 K3s 和单节点 JetStream。
- 重要站点使用 K3s HA 和三副本 JetStream。
- 高可用级别是站点部署 Profile，不改变工程业务契约。
