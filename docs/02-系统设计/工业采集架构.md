# InduForge 工业采集架构

## 1. 核心决策

- 工业采集从中心和 K3s 工程运行栈独立。
- Windows、Linux 的 Collector 全部采用原生进程。
- NodeAgent 分别以 Windows Service 和 systemd 托管 Collector 子进程。
- PLC、仪表和厂商协议通过内部商业协议适配器实现。
- OPC UA 使用 OPC Foundation 官方 .NET SDK。
- OPC DA 使用 Windows 专属 `opcda_worker`。
- 开发态与运行态复用同一驱动适配器和配置契约。

## 2. 运行结构

```text
Windows / Linux 采集节点
├─ NodeAgent
├─ collector-deployment-a-prod
│  ├─ PLC / Instrument Adapter
│  ├─ OPC UA Adapter
│  └─ WAL
├─ collector-deployment-b-dev
└─ opcda-worker-deployment-a-prod（仅 Windows）
```

Collector 不进入 Docker、K3s 或工程 Namespace。

## 3. 开发态

开发态 Collector 是按需启动的原生进程，负责连接测试、Browse、Read、Write、短时 Subscription 和诊断，不承担长期采集。

```text
datacenter
→ data_service
→ development Collector
→ 设备
```

中心没有 Collector 时仍可完成离线建模。

Windows + WSL2 开发环境中，JetStream 运行于 WSL2 Docker，Windows 原生 Collector 使用根目录 `.env` 中的 `IF_RUNTIME_BUS_URL` 连接，默认地址为 `nats://127.0.0.1:18222`。

## 4. 运行态

NodeAgent 为每个 ProjectDeployment 生成原生进程计划：

```text
industrial_collector --mode runtime --deployment <deploymentId> --release <releaseId>
```

运行态负责：

- 加载工程采集配置。
- 长期连接、轮询和 OPC UA Subscription。
- 质量与时间戳标准化。
- 本地 WAL、断线重连和补投。
- 发布到目标工程 NATS Account。

## 5. 驱动体系

### 5.1 PLC 与仪表协议

面向用户统一提供 S7、Modbus、三菱、欧姆龙、Allen-Bradley、基恩士、台达、汇川和信捷等协议或设备能力。底层可使用商业 SDK 实现，但供应商名称、授权方式和 SDK 版本只属于内部构建与运维信息，不进入公开 API、页面、工程配置、普通日志和错误码。Linux 驱动必须逐项实机认证。

### 5.2 OPC UA

负责 Endpoint、安全策略、身份认证、Browse、Read、Write、Subscription 和 Session 恢复。

### 5.3 OPC DA

基于 Windows COM/DCOM，以独立 `opcda_worker` 进程运行，通过本地 IPC 与对应工程 Collector 或运行适配层交互。

## 6. 多工程隔离

- 默认每工程一个 Collector 进程。
- 每个进程使用独立配置目录、WAL、日志和 NATS 凭据。
- 一个工程崩溃、升级或回滚不影响其他工程。
- 同一物理设备默认只能由一个主采集任务持有连接。

## 7. 程序与配置交付

- Collector 程序、内部协议 SDK 和驱动包属于节点能力包；工程 Release 只引用协议能力标识，不感知底层供应商。
- 协议类型、逻辑接入源、变量/数据点模型、采集周期、字段映射和逻辑消息目标属于工程
  Release；真实设备地址、认证材料、目标 deployment 的 NATS Account/Subject、Collector 节点
  分配、主备角色与 epoch 属于 DeploymentBinding/CollectorAssignment。
- 工程升级通常只更新采集配置；只有能力版本变化时才升级 Collector 程序。

## 8. JetStream 上行

```text
设备
→ Collector
→ 本地 WAL
→ NATS JetStream DATA_RAW
→ writer / alarm / compute
```

Collector 使用工程 Account 最小权限凭据，只允许发布本工程数据和消费自己的写入命令。

## 9. 平台能力矩阵

| 能力                   | Windows | Linux      |
| ---------------------- | ------- | ---------- |
| PLC/仪表 TCP、UDP 协议 | 支持    | 逐协议认证 |
| 普通串口协议           | 支持    | 逐设备认证 |
| Windows 专属原生依赖   | 支持    | 不支持     |
| OPC UA                 | 支持    | 支持       |
| OPC DA                 | 支持    | 不支持     |

## 10. 安全

- Collector 默认不开放公网端口。
- 本地诊断端口仅绑定 `127.0.0.1`。
- 写入测试需要权限、二次确认和审计。
- 商业 SDK 授权、设备密码和 NATS 凭据通过节点安全目录注入；授权信息不返回普通用户界面。
- OPC UA 私钥和 OPC DA DCOM 凭据不得进入工程 Artifact 明文。
