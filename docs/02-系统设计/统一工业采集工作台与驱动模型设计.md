# 统一工业采集工作台与驱动模型设计

## 1. 目标

本设计将数据中心内 OPC UA、Modbus、S7 及后续工业协议统一到同一套采集连接、点位模型、调试任务和工程级工作台中。

Windows Collector DevAgent 作为开发态短链调试执行环境。当前第一条真实实现使用 OPC UA 官方 SDK，后续可以接入 HSL 或其他工业通信 SDK，但平台公共 API、页面、工程配置和普通日志不得暴露底层 SDK 供应商、授权方式和实现类型。

最终要求：

- 新增工业协议不修改数据库字段。
- 新增工业协议不增加完整独立工作台。
- 没有 DevAgent 时仍可离线创建连接和建模。
- 调试代理和未来 Runtime Collector 共享驱动契约，但生命周期与认证方式独立。
- 采集点位与平台正式数据点保持清晰分层。

## 2. 本期范围

### 2.1 实现

- 仓库内版本化驱动 Manifest。
- `protocolFamily + driverId` 两级标识。
- JSON Schema 2020-12 与独立 UI Schema。
- 统一工业采集连接、点位分组和点位模型。
- 连接普通配置与加密密钥分离。
- 统一平台数据类型、结构化地址和采集策略。
- 采集点位自动、事务化生成正式数据点。
- 通用调试任务操作与 Agent 能力契约。
- 工程级统一工业采集工作台。
- OPC UA 连接测试、设备发现和点位读取。
- OPC UA、Modbus、S7 迁移到统一模型和统一工作台。
- 手工建点、设备发现和 Schema 驱动批量导入。
- 删除旧协议专属数据模型、API 和工作台外壳。

### 2.2 不实现

- 不在本期引入 HslCommunication NuGet 依赖。
- 不实现 HSL 授权注入和具体 HSL Adapter。
- 不实现 Modbus、S7 DevAgent 调试。
- 不实现 Write 和长期 Subscription。
- 不实现 Runtime Collector、WAL 和 JetStream 数据发布。
- 不实现 NodeAgent 或 K3s 工程部署。
- 不保留新旧工业采集模型的长期双写和兼容入口。

## 3. 总体架构

```text
数据中心统一采集工作台
        │
        ├─ 协议目录 API
        ├─ 采集连接/点位 API
        └─ 调试任务 API
        │
data_service
        ├─ Manifest 聚合与 Schema 校验
        ├─ 工业采集连接与密钥
        ├─ 点位分组与采集点位
        ├─ 正式数据点映射
        └─ Collector Dev 调试任务
        │
Windows Collector DevAgent
        ├─ 注册、心跳和能力上报
        ├─ 通用任务执行器
        └─ 驱动注册表
             ├─ OPC UA 官方 SDK Adapter
             └─ 后续认证驱动 Adapter
```

平台公共层只认识：

```text
protocolFamily
driverId
driverVersion
schemaVersion
operations
config
address
dataType
acquisition
```

平台公共层不得出现：

```text
HslCommunication
SDK 类型名和版本
SDK 授权码
内部驱动工厂
```

## 4. 驱动标识

使用两级标识：

```text
protocolFamily = mitsubishi
driverId = mitsubishi.mc-tcp-binary
```

`protocolFamily` 用于产品分类、筛选和展示；`driverId` 唯一确定连接 Schema、地址 Schema、操作能力和内部 Adapter。

示例：

```text
opcua / opcua.standard
modbus / modbus.tcp
modbus / modbus.rtu
siemens / siemens.s7-tcp
mitsubishi / mitsubishi.mc-tcp-binary
omron / omron.fins-tcp
allen-bradley / allen-bradley.cip
```

`driverId` 创建后不可直接修改。更换驱动需要重新创建连接，避免不兼容的配置和地址被错误转换。

## 5. 协议 Manifest

### 5.1 目录

公共协议契约放置于：

```text
runtime/collector_protocols/
├─ opcua.standard/
│  ├─ manifest.json
│  ├─ connection.schema.json
│  ├─ address.schema.json
│  ├─ ui.schema.json
│  └─ operations/
├─ modbus.tcp/
├─ modbus.rtu/
├─ siemens.s7-tcp/
└─ ...
```

构建时由 `data_service`、DevAgent 和未来 Runtime Collector 消费同一份契约。CI 必须检查 Manifest 摘要和 Adapter 描述一致。

### 5.2 Manifest 内容

```json
{
  "protocolFamily": "siemens",
  "driverId": "siemens.s7-tcp",
  "driverVersion": "1.0.0",
  "schemaVersion": 1,
  "displayName": "Siemens S7 TCP",
  "category": "plc",
  "transports": ["tcp"],
  "operations": ["connection.test", "point.read"],
  "dataTypes": [
    "bool",
    "int16",
    "uint16",
    "int32",
    "uint32",
    "float32",
    "float64",
    "string",
    "bytes"
  ],
  "acquisitionModes": ["polling"],
  "platforms": {
    "devAgent": ["windows-x64"],
    "runtime": []
  }
}
```

### 5.3 Schema

机器校验使用 JSON Schema 2020-12。页面布局使用独立 UI Schema。

平台扩展关键字限定为：

```text
x-induforge-secret
x-induforge-sensitive-log
x-induforge-unit
x-induforge-advanced
x-induforge-address-text
```

后端校验永远以 JSON Schema 为最终权威，不能依赖 UI Schema。

### 5.4 认证白名单

底层 SDK 中存在某个驱动类，不代表平台自动支持。驱动进入公共协议目录前必须具备：

- Manifest 和全部 Schema。
- Adapter 实现。
- 地址转换和类型映射测试。
- Agent 操作测试。
- 真实设备或可验证模拟测试。
- Windows/Linux 支持声明。
- 安全和授权检查。

## 6. 统一数据模型

### 6.1 独立工业采集域

工业采集连接不再挂接通用 `data_connections`。普通接入源与工业采集分别拥有独立主表、API 和页面生命周期，正式数据点通过 `source_type = collector.point` 关联采集点。

具体协议和驱动只进入工业采集域，不进入普通接入源类型枚举。

### 6.2 工业采集连接

```text
data_collector_connections
├─ id                     PK
├─ project_id
├─ name
├─ status
├─ enabled
├─ display_order
├─ protocol_family
├─ driver_id
├─ driver_version
├─ schema_version
├─ config                 JSONB
├─ metadata               JSONB
├─ created_by
├─ updated_by
├─ created_at
└─ updated_at
```

`config` 只保存非敏感配置，并通过对应 Connection Schema 校验。

### 6.3 连接密钥

```text
data_collector_connection_secrets
├─ id
├─ connection_id
├─ secret_key
├─ encrypted_value
├─ encryption_key_version
├─ created_at
└─ updated_at
```

唯一约束为 `connection_id + secret_key`。普通查询只返回敏感字段是否已配置。

### 6.4 点位分组

```text
data_collector_point_groups
├─ id
├─ project_id
├─ connection_id
├─ parent_id
├─ name
├─ sort_order
├─ metadata JSONB
├─ created_at
└─ updated_at
```

设备发现树是 Agent 临时结果，不完整落库。用户确认导入后才根据需要创建工程点位分组。

### 6.5 采集点位

```text
data_collector_points
├─ id
├─ project_id
├─ connection_id
├─ group_id
├─ code
├─ name
├─ description
├─ address                 JSONB
├─ address_text
├─ address_schema_version
├─ data_type
├─ element_count
├─ read_options            JSONB
├─ acquisition             JSONB
├─ enabled
├─ sort_order
├─ metadata                JSONB
├─ created_at
└─ updated_at
```

`address` 是平台结构化地址的唯一权威数据。`address_text` 是平台生成的可读值，用于展示、搜索和导出。Adapter 负责将 `address` 转换为底层 SDK 地址。

### 6.6 数据点映射

采集点位与正式数据点保持两层模型：

```text
collector_points：如何从设备读取
data_points：平台如何引用和消费
```

复用 `data_points` 的来源字段：

```text
source_type = collector.point
source_id = collectorPointId
source_config = 映射、缩放或转换配置
```

导入采集点位时，在同一事务内创建 `collector_points` 和对应 `data_points`。

## 7. 统一数据类型

平台数据类型使用稳定枚举：

```text
bool
int8
uint8
int16
uint16
int32
uint32
int64
uint64
float32
float64
decimal
string
bytes
datetime
```

数组使用 `element_count` 表示，不增加数组专属类型。字节序、字符串长度和编码进入 `read_options`。

Adapter 将平台类型映射到具体 SDK Read/Write 方法。公共数据不得保存 .NET 或 SDK 类型名。

## 8. 采集策略

点位从当前阶段开始保存版本化 `acquisition JSON`：

```json
{
  "mode": "polling",
  "intervalMs": 1000,
  "timeoutMs": 3000,
  "deadband": null,
  "changeOnly": false,
  "priority": "normal"
}
```

Manifest 声明驱动支持的采集模式和参数范围。DevAgent 本期不执行长期采集，未来 Runtime Collector 直接消费相同策略。

## 9. Schema 与版本

连接保存 `driverVersion + schemaVersion`，点位保存 `addressSchemaVersion`。

规则：

- 新建对象使用当前最新 Schema。
- Manifest 升级后不静默改变旧配置含义。
- 工作台显示需要升级的配置。
- 用户显式执行升级。
- 当前开发阶段允许使用一次性迁移，不编写复杂兼容分支。
- 工程 Release 固定驱动和 Schema 版本快照。
- Agent 和 Runtime Collector 必须明确声明支持对应版本。

## 10. 后端 API

### 10.1 驱动目录

```text
GET /api/v1/data/collector/drivers
GET /api/v1/data/collector/drivers/{driverId}
```

列表支持分页、搜索、协议族、类别和传输类型筛选。详情返回 Manifest、Connection Schema、Address Schema、UI Schema 和 Operation Schemas。

### 10.2 连接

```text
GET    /api/v1/data/projects/{projectId}/collector/connections
POST   /api/v1/data/projects/{projectId}/collector/connections
GET    /api/v1/data/projects/{projectId}/collector/connections/{connectionId}
PUT    /api/v1/data/projects/{projectId}/collector/connections/{connectionId}
DELETE /api/v1/data/projects/{projectId}/collector/connections/{connectionId}
```

创建和更新必须在一个事务中完成主表、工业采集扩展和密钥写入。

### 10.3 分组与点位

分组按 `parentId` 按需加载。点位列表必须提供服务端分页、搜索、筛选和排序。

批量接口包括：

```text
POST /points/batch
POST /points/update-batch
POST /points/delete-batch
POST /points/move-batch
```

前端不得循环逐条写入。

### 10.4 导入

```text
GET  /api/v1/data/collector/drivers/{driverId}/points/import-template
POST /api/v1/data/projects/{projectId}/collector/connections/{connectionId}/points/import-preview
POST /api/v1/data/projects/{projectId}/collector/connections/{connectionId}/points/import-commit
```

导入预览按页返回错误和候选点位。提交只接收 `importId` 和确认选项，由后端事务化写入。

## 11. 通用调试任务

### 11.1 操作名

```text
connection.test
device.browse
point.read
point.write
point.subscribe.preview
```

不再使用 `opcua.browse`、`opcua.read` 等协议专属操作名。

### 11.2 平台任务

平台任务只接收已保存对象引用：

```json
{
  "agentId": "agent-1",
  "connectionId": "connection-1",
  "operation": "point.read",
  "input": {
    "pointIds": ["point-1"]
  }
}
```

连接配置必须先保存再调试。平台任务表只保存引用、脱敏输入、状态和审计。

### 11.3 Agent 执行信封

Agent 领取任务时，后端临时解析连接配置、密钥和点位地址，生成内部执行信封。密钥不进入任务审计、普通日志或任务结果，Agent 不持久化设备密钥。

### 11.4 状态机

```text
queued → running → succeeded
                 → failed
queued/running → cancelled
queued/running → expired
```

一个任务只能被一个 Agent 领取，一个 Agent 同时只执行一个任务。领取和终态转换必须使用事务。

## 12. DevAgent 驱动契约

基础接口：

```csharp
public interface IIndustrialDriver
{
    DriverDescriptor Descriptor { get; }
    Task<ConnectionTestResult> TestConnectionAsync(...);
}
```

可选能力接口：

```text
IDeviceBrowser
IPointReader
IPointWriter
IPointSubscriptionPreview
```

驱动不支持某项能力时不实现对应接口。Agent 根据实际接口生成能力上报。

驱动注册表维护：

```text
driverId → Adapter Factory
```

启动时校验 Manifest、驱动版本、Schema 版本和操作能力一致性。

## 13. OPC UA 第一适配器

现有 OPC UA 官方 SDK 驱动标识为：

```text
protocolFamily = opcua
driverId = opcua.standard
```

本期实现：

- 匿名认证。
- 连接测试。
- 按需 Browse。
- 批量 Read。
- NodeId 结构化地址。
- OPC UA 数据类型到平台类型映射。
- StatusCode 到统一质量映射。

本期不实现 Write、长期 Subscription、用户名密码、证书私钥、历史访问和 Method Call。

## 14. HSL 后续边界

HSL 仅作为 Agent 内部 Adapter 的一种实现来源。公共层不得直接依赖 HSL 的 `IReadWriteNet` 或具体设备类型。

未来 HSL Adapter 负责：

- 创建具体通信对象。
- 配置连接属性。
- 将平台结构化地址转换为 HSL 地址字符串。
- 将平台数据类型映射到 HSL Read/Write 方法。
- 转换 HSL 结果和错误。
- 释放通信对象。

正式接入 HSL 前必须确认商业授权、Windows/离线授权注入、Linux 可用性、驱动包交付和真实设备认证。HSL 授权属于 Agent 或节点能力包，不属于工程连接配置。

## 15. 统一采集工作台

入口：

```text
数据中心 → 工业采集
```

工作台是工程级页面：

```text
顶部：当前工程、DevAgent 选择和状态
左侧：全部工业采集连接列表
右侧：当前连接的配置、发现、点位和实时调试
```

Agent 是工作台临时调试环境，不写入接入源数据。浏览器可以按工程记住上次选择的 Agent。

新增采集源统一使用向导：

```text
选择协议族 → 选择驱动 → Schema 表单 → 创建
```

没有 Agent 时仍允许创建、保存、手工建点和批量导入；测试、发现和实时读取按钮禁用。

页签：

```text
连接配置
设备发现（驱动支持时显示）
点位
实时调试
```

OPC UA、Modbus、S7 不再拥有独立用户工作台。协议差异只通过 Manifest、Schema 和小型扩展组件实现。

## 16. 点位来源

统一支持：

1. 设备发现：驱动支持 `device.browse` 时显示。
2. 手工新增：使用 Address Schema 渲染表单。
3. 批量导入：由 Manifest 生成 CSV/XLSX 模板，后端批量校验和事务化提交。

设备发现结果不全量落库。用户勾选并确认后才创建采集点位、分组和正式数据点。

## 17. 迁移与删除

本期直接迁移 OPC UA、Modbus、S7 配置、分组和点位到统一模型。迁移完成并验证后删除：

- 协议专属配置表。
- 协议专属分组和点位表。
- 旧 Repository、Service 和 Handler。
- 旧独立工作台外壳。
- 协议专属任务操作。

不保留长期双写。Down 迁移只恢复结构，不承诺恢复已经转换的数据内容。

1. 无 Agent 时创建和保存 OPC UA、Modbus、S7 连接，发现和读取按钮保持禁用。
2. 启动 Windows DevAgent 后确认能力显示为 `opcua.standard@1.0.0`，Schema 版本为 1。
3. 使用匿名 OPC UA 模拟服务完成连接测试、按需浏览、勾选建点和批量读取。
4. 检查普通连接查询、任务详情和日志中均不存在密钥明文。
