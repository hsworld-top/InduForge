## 2. 高优先级问题

### DC-WB-001 MQTT 批量映射操作按钮的 tooltip 会遮挡或扩大点击区域

- **优先级**：P1
- **类型**：MQTT 批量变量映射
- **复现步骤**：
  1. 打开 MQTT 批量变量映射订阅。
  2. 在映射规则区域将鼠标移到“解析预览”或行操作图标附近。
  3. 移动鼠标到按钮并点击。
- **实际结果**：tooltip 浮层可能出现在按钮上方或覆盖相邻操作区域；按钮焦点保持时浮层不会及时消失。Wujie 内嵌场景下偏移更明显，可能导致点击命中浮层而不是按钮。
- **代码证据**：
  - `InduFrame/packages/datacenter/src/features/access-sources/mqtt/MqttBatchMappingPanel.vue` 仍存在多个 `el-tooltip`，表格列还使用 `show-overflow-tooltip`。
  - 规则操作区使用 `.mqtt-batch-mapping__rule-actions`，当前实现曾通过 `:deep(.el-tooltip__trigger)` 改变触发器宽度，容易扩大命中区域。
  - 全局 Element Plus Popper 定位策略与 Wujie iframe 的坐标系叠加，不能只靠 `strategy: fixed` 解决。
- **修复建议**：
  - 解析、保存、删除、复制等可直接点击的动作按钮不要包 tooltip；需要说明时使用按钮 `aria-label` 或不遮挡的静态文字。
  - 行操作图标只让图标本身作为触发器，禁止把整行或整列设置为 `.el-tooltip__trigger`。
  - 对必须保留的 tooltip 统一设置 `teleported`、合适的 `append-to` 和 `popper-class`，并在按钮 `mouseleave`/点击后关闭；逐项检查 Wujie 内和普通页面的定位。
  - 不用 tooltip 承担禁用态说明；禁用按钮旁显示一次性的静态原因。
- **验收标准**：在 MQTT、HTTP、SQL、Kafka、WebSocket 和 Redis 工作台分别悬停、点击所有带 tooltip 的图标，浮层不得覆盖目标按钮或相邻按钮；按钮一次点击成功，键盘焦点不影响再次点击。桌面宽度和窄窗口各验收一次。

### DC-WB-002 全局 tooltip 问题不能只修 MQTT 单个按钮

- **优先级**：P1
- **类型**：公共交互组件
- **实际结果**：HTTP 保存按钮和 MQTT 行操作均观察到浮层因焦点或定位残留而不消失。只移除“解析预览”一个 tooltip 不能覆盖所有使用 Element Plus tooltip 的地方。
- **修复建议**：建立工作台公共图标按钮规范，逐个盘点 `el-tooltip`、`show-overflow-tooltip`、`el-tooltip__trigger` 和自定义 Popper；区分“文本溢出提示”和“动作说明”，不要使用同一套默认定位参数。
- **验收标准**：对所有工作台执行 tooltip 清单回归，记录组件、触发元素、挂载容器、是否可点击和键盘行为；没有未登记的 tooltip 触发器。

### DC-WB-003 SQL“保存并更新数据点”不会保存已修改的 SQL

- **优先级**：P1
- **类型**：SQL 类工作台
- **实际结果**：已保存查询修改 SQL 后直接点击“保存并更新数据点”，只更新输出配置；数据点 GET 仍使用数据库中旧 SQL。界面文字容易让用户认为 SQL 与数据点会一起保存。
- **代码证据**：`SqlQueryWorkbench.vue` 的更新数据点逻辑仅在临时查询缺少 `queryId` 时先保存查询；已有查询直接更新 outputs。
- **修复建议**：已有查询存在脏 SQL 时，按钮动作应先保存 SQL，再更新输出配置；或把按钮改名为“更新输出配置”，并在 SQL 未保存时阻止操作并给出明确动作。
- **验收标准**：修改已保存 SQL，点击该按钮后刷新 GET，结果必须来自新 SQL；任一步失败都要保留脏状态并明确失败阶段。

### DC-WB-004 SQL 输出配置修改缺少草稿保护

- **优先级**：P1
- **类型**：SQL 输出配置/数据点
- **实际结果**：修改字段提取或输出模式后，关闭标签或离开工作台可能不提示，未保存配置会丢失。当前草稿保护主要检查 SQL `modified`，没有覆盖 output config 的修改状态。
- **修复建议**：把 SQL 文本、参数定义和输出配置合并为同一工作台草稿状态；关闭标签、切换接入源、离开页面和浏览器刷新都应提示。
- **验收标准**：分别只修改 SQL、只修改输出配置、同时修改两者，关闭/离开时均出现一次准确提示；保存后不再提示。

### DC-WB-005 Kafka 整包规则保存成功但样本预览不可用

- **优先级**：P1
- **类型**：Kafka 整包消费规则
- **界面实测**：规则“教程遥测整包”保存成功，状态显示不可用，点击拉取样本提示“读取 Kafka 预览配置失败”。
- **实际结果**：用户无法判断是 Broker、连接配置、Topic、分区策略还是预览接口问题；规则已经保存但没有可用的逐项错误信息。
- **修复建议**：拆分“规则保存”和“Broker 预览连接”的错误状态；展示服务端错误码、目标地址脱敏信息、Topic、分区策略及下一步建议；保存成功后不要把规则整体标记为不可用。
- **验收标准**：错误配置、Broker 不可达、Topic 不存在、无消息和权限失败分别显示不同原因；修正后可重新测试，不需要删除重建规则。

### DC-WB-006 Kafka 字段候选去重只覆盖当前页

- **优先级**：P1
- **类型**：Kafka 字段映射
- **实际结果**：字段候选使用当前分页 `fields.value` 判断已存在字段。已有映射在其他页时可能再次被标记为可创建，最终由后端重复约束失败或产生不一致提示。
- **代码证据**：`KafkaFieldMappingPanel.vue` 的候选过滤只使用当前页字段集合。
- **修复建议**：使用后端全量存在性查询或专用字段路径校验接口；至少在打开候选前加载全部已存在路径，不要把当前页数据当作全量集合。
- **验收标准**：创建超过一页字段映射后再次解析样例，任何已存在路径都不能进入可创建列表。

### DC-WB-007 WebSocket 消息流无限增长

- **优先级**：P1
- **类型**：WebSocket 会话工作台
- **实际结果**：消息数组持续追加并全量渲染，没有条数上限、虚拟列表、搜索、复制、清空和时间戳；长时间连接或高频消息会造成内存和渲染压力。
- **修复建议**：增加最大消息数和丢弃策略；消息区使用虚拟列表；提供搜索、复制、清空、暂停自动滚动和时间戳；显示当前缓存条数及是否丢弃旧消息。
- **验收标准**：持续发送超过上限后页面仍流畅，内存不随消息无限增长；用户能定位、复制和清空单条或全部消息。

### DC-WB-008 Studio 会话失效时工作台恢复路径不完整

- **优先级**：P1
- **类型**：Studio、Wujie 工作台公共会话
- **界面实测**：验收过程中 Studio 自动回到登录页，已经打开的工作台无法继续操作。
- **实际结果**：用户只能重新登录，工作台当前标签、草稿和测试上下文没有明确恢复策略。
- **修复建议**：统一处理 `401/票据无效`：暂停请求、保留本地非敏感草稿、提示重新登录；重新登录后恢复菜单/视图/工作台标签，或明确告知需要重新打开。长时间空闲应在失效前提示。
- **验收标准**：让会话过期后点击工作台操作，只出现一次登录提示；重新登录后未保存 SQL、HTTP、WebSocket 草稿按产品约定恢复或明确丢弃原因。

## 3. 中优先级问题

### DC-WB-009 MQTT 通配符订阅没有可用的发布目标输入

- **优先级**：P2
- **实际结果**：发布测试中的 Topic 输入框固定为订阅 Topic。订阅使用 `+` 或 `#` 时，用户无法在发布面板输入实际发布 Topic；而 MQTT 发布本身不能使用通配符。
- **修复建议**：通配符订阅进入发布测试时，将 Topic 改为可编辑输入，并预填一个去掉通配符的示例；校验发布 Topic 不含通配符。

### DC-WB-010 Kafka 缺少主区“新建消费规则”空状态按钮

- **优先级**：P2
- **实际结果**：树为空时主要依赖左侧入口，主区没有就地创建动作，首次用户不容易发现下一步。
- **修复建议**：空状态提供“新建消费规则”和“新建分组”；创建后自动定位到新规则。

### DC-WB-011 WebSocket 连接成功状态和会话地址文案不一致

- **优先级**：P2
- **实际结果**：卡片可显示“未配置 WebSocket”，但地址实际保存在会话配置中，文案会让用户误以为接入源缺少配置。
- **修复建议**：区分“接入源未配置地址”“当前会话未配置地址”“尚未连接”三种状态。

### DC-WB-012 WebSocket 消息 JSON 模式不校验 JSON

- **优先级**：P2
- **实际结果**：编辑器选择 JSON 只改变语法模式，发送前直接发送文本；非法 JSON 也可能进入发送流程。
- **修复建议**：JSON 模式发送前执行解析校验，错误定位到编辑器；文本模式保持原样发送。

### DC-WB-013 HTTP JSON 请求体格式错误仍可保存

- **优先级**：P2
- **实际结果**：JSON 编辑器解析失败时会把原字符串写入请求体对象，保存可能继续进行，直到发送或后端校验才失败。
- **修复建议**：JSON 模式保存和发送前都阻止非法 JSON，错误定位到请求体；原始文本应切换到 Raw 模式。

### DC-WB-014 HTTP 请求缺少取消和重试操作

- **优先级**：P2
- **实际结果**：发送后只能等待超时；网络错误只有 toast，没有取消当前请求或按原参数重试的明确入口。
- **修复建议**：发送按钮在请求中变为“取消”；失败响应旁提供“重试”，保留上一次请求摘要。

### DC-WB-015 MQTT 批量保存不是原子操作

- **优先级**：P2
- **实际结果**：批量保存实现为批量删除、批量创建及多个单项更新并发，中途失败可能已经部分写入。
- **修复建议**：优先增加后端事务式批量接口；无法一次完成时显示已创建、已更新、已删除和失败明细，并提供再次提交前的差异预览。

### DC-WB-016 SQL 表重命名后已有标签仍引用旧表名

- **优先级**：P2
- **实际结果**：重命名表只更新标签标题和 table 字段，已有预览 SQL 仍引用旧表名；再次运行可能报错，重新打开同一表还可能创建新标签。
- **修复建议**：重命名后更新关联标签 ID、SQL 引用及缓存；无法安全改写 SQL 时关闭旧预览并提示重新打开。

### DC-WB-017 SQL 表列表全量加载，未遵守增长列表分页约定

- **优先级**：P2
- **实际结果**：普通 SQL 库表列表一次加载后在前端过滤，表数量增长会增加首屏和内存压力。
- **修复建议**：对表搜索、分页和排序使用后端接口；与查询列表、TDengine 对象树保持相同的加载更多模式。

### DC-WB-018 SQL 截断提示提到导出任务，但界面没有导出入口

- **优先级**：P2
- **实际结果**：结果因行数、字节或超时被截断时，提示文案暗示可以使用后续导出任务，但当前界面没有对应操作。
- **修复建议**：实现导出任务，或将文案改为真实可用的解决方式，不要承诺尚未提供的功能。

## 4. 低优先级和文案问题

### DC-WB-019 WebSocket 输出字段依赖最近一条消息但缺少空状态引导

- **优先级**：P3
- **实际结果**：没有接收样本时不会出现响应字段候选；用户不清楚需要先连接并接收一条 JSON 消息。

- **优先级**：P3

### DC-WB-021 TDengine 只读能力需要在入口和弹窗中明确说明

- **优先级**：P3
- **实际结果**：前端隐藏建表、修改、重命名、删除和插入入口，但用户只能通过缺少按钮推断限制。
- **修复建议**：在工作台标题或接入源信息处显示“只读查询/结构浏览”，必要时给出权限范围说明；不要把隐藏入口误解为故障。

使用已有订阅“教程设备遥测”继续验证：整包、单变量、批量变量三种模式；新建/编辑/删除、规则保存、映射保存、解析预览、变量监控、发布测试、通配符 Topic 和 tooltip 回归。

### 5.6 HTTP/WebSocket/Kafka

- HTTP：参数、认证、请求头、JSON/Raw/Form Body、响应 Body/Headers、输出字段、超时、TLS 和非法 JSON。
- WebSocket：请求头、认证、子协议、JSON/文本消息、连接/断开、收发消息、输出字段、超时、重连和关闭标签。
- Kafka：整包规则、字段规则、样例粘贴、样本拉取、字段候选去重、编辑/启停/删除、空状态和 Broker 错误。
