# 数据中心概览

## 模块定位

- `datacenter` 是平台数据工作台前端，为项目提供数据连接、查询、数据点、协议接入、计算调试和数据消费入口。

## 核心能力

- 数据连接配置与管理
- IF 内置运行库建模与开发态调试：关系库、时序库、实时库、消息库
- 查询定义、执行与复用入口
- 数据点定义、查看与调试
- 数据点自定义属性默认值配置
- 按接入源、工业采集连接、计算单元和数据点配置开发态历史存储
- MQTT、协议接入与数据工作台操作
- 计算与数据调试入口
- 点位优先的报警配置、组合报警、工程通知和报警历史设置

## 正式边界

- `datacenter` 是平台数据工作台前端，不承担平台侧数据域后端实现。
- `datacenter` 通过 `data_service` 获取平台侧与开发态数据域能力。
- `datacenter` 不承担页面渲染、工程聚合和节点托管职责。

## 关键交付件

- 数据连接配置
- 查询定义
- 数据点定义
- 历史存储配置
- 协议接入配置
- 计算与调试入口
- 报警开发态配置、工程级别与升级规则、通知渠道与报警历史设置

## 工业采集边界

- 数据中心负责工业接入源、变量、采集计划和数据点建模，不直接加载工业 SDK 或连接现场设备。
- “历史存储”只配置保存方式、IF 时序库/TDengine 目标和保留时间；当前值存储不对用户暴露，历史查询仍在对应接入源工作台使用 SQL 完成。
- 数据点操作列提供“自定义属性”入口，按点维护字符串 Key 和默认值；不在列表增加属性列，也不提供来源继承或批量配置。
- “报警”按独立报警项分页集中管理，一行对应一个数据点上的一条报警；同一点可同时拥有越限、变化率、偏差、质量、陈旧和离线等报警。多点创建生成多条独立项，表格支持当前选择或全部筛选结果的批量启停、目录、通知、兼容条件替换和删除。目录默认收起且只用于筛选整理；数据点页面只读展示全部有效报警并跳转报警单元。普通报警支持 Excel 模板、导出、预览和事务导入，组合报警仍在专用工作台维护。开发调试使用带时间戳、质量和离线状态的样本序列，并逐步展示匹配、暂停、活动/候选等级和剩余延时。
- 计算与报警的左侧目录复用统一树面板规范，包括标题、搜索、全部节点、工具按钮、选中态和滚动区域。计算树不展示分页控件；接口仍分页读取并由前端自动合并完整计算单元列表，目录子级按需加载。
- “报警历史”只配置节点内置报警库的保存开关、保留期限和通知投递记录开关，不展示存储目标，也不提供历史查询。
- 计算触发支持手动、周期、每日、每周、每月、每年、数据点变化和条件触发；日历计划明确 IANA 时区，支持开始/结束时间、最大执行次数以及未来五次预览。点变仅接受 bool、string 和数值数据点，并可配置兼容的变化类型、防抖和数值死区。条件表达式复用已声明的标量数据点变量，可组合选择进入、持续和离开阶段；持续表示条件成立期间引用数据点再次变化时执行。所有非手动触发均属于节点运行配置，开发态只校验和保存，不自动执行。
- 计算调试能力完全以后端 capabilities 为准；独立沙箱不可用时禁用语法检查与试运行，不回退到服务宿主执行。
- 计算树标题栏提供“工程依赖”弹窗，支持在线安装和离线导入 JavaScript/Python 依赖；在线版本可选且默认获取最新，包名、实际版本和导入名由后端从包元数据确定。计算单元依赖面板只读展示当前代码自动识别的引用，不再让每个单元重复维护或下载依赖。
- TDengine 是可查询的开发态接入源与历史目标，使用 `ws/wss` 结构化连接并提供只读 SQL 工作台；不展示建表、改表、删表和行编辑。
- OPC UA、S7、Modbus、OPC DA 及后续工业驱动统一进入“工业设备工作台”，按 Manifest 只显示真实的连接、浏览、读取和诊断能力；当前 115 个驱动均明确为只读采集，不展示写入或订阅伪入口。
- 真实连接、开发态调试和运行态采集由独立 `industrial_collector` 或 Windows `opcda_worker` 执行。
- 没有在线调试执行器或采集节点时，仍允许完整配置和建模，但禁用真实连接、浏览、读取和写入操作。
- 详细边界见 [工业采集架构](../../02-系统设计/工业采集架构.md)。

## 质量关注点

- 数据工作台操作与 `data_service` 提供的正式能力保持一致。
- 数据对象定义与设计态、运行态消费契约保持连续。
- 数据中心不承载 IF 对象库；设计资源、工程包和发布产物对象能力归设计中心、发布链路或平台资源管理边界。
- 关键数据工作台入口具备最小可回归验证能力。

## 入口与调试

### 正式入口

- 正式入口由 `dev_ide` 宿主通过 Wujie 打开，工程、租户、主题与会话回调通过子应用上下文注入。
- 正式入口不再依赖 URL 里的 `token`、`refreshToken`、`theme`、`pid`、`tenant` 作为主链路上下文。
- 数据中心收到 `401` 时调用宿主的统一续租任务并重试原请求；续租失败时通知宿主统一退出，不在子应用内自行跳转。

### 独立调试

- 需要单独调试数据中心时，使用 `/datacenter/debug`。
- `/datacenter/debug` 允许脱离 IDE 运行，但只用于本地调试；正式入口 `/datacenter/` 在缺少本地 token 或 projectId 时会回跳 `dev_ide`。
- 调试正式链路时，应从 `dev_ide` 内打开数据中心标签页，再检查 bootstrap 消息、主题同步和续租回传是否正确。

### `handoff` 与恢复

- 子应用被单独打开成浏览器标签页后，只要本地仍保留可复用的 token 与工程上下文，就允许继续独立运行；缺少上下文时仍会依赖 `handoff` 回附 IDE。
- `handoff` 只保存恢复映射，不保存 token 等敏感信息；丢失或过期时会降级回 IDE 首页。
- 子应用内部组件应优先从本地上下文读取 `projectId`、`tenantId` 等工程信息，避免重新依赖旧的 URL 参数。
