> Review 日期：2026-08-24
>
> Review 范围：数据中心前端、`data_service`、数据库最终基线、工程快照与发布 Artifact。
> 本文只审查数据中心开发态的配置、建模、调试、保存、批量维护、快照和发布输出。节点侧采集、调度、历史写入、报警计算、通知投递和历史查询均不属于本次整改范围。

## 1. 结论

当前数据中心已经具备较完整的开发态信息架构，数据点分页与跨页批量、工业连接和变量建模、来源级历史配置、点位报警项、组合报警、通知与报警历史等主要形态基本合理。

阶段 A 已完成计算调试隔离、真实能力契约、结构化调度、外部密钥、专用连接更新和 TDengine 只读工作台。当前仍不进入数据契约检查：接入源删除影响、计算保存事务、数据点引用保护、外部 SQL 规模边界和报警试算语义属于阶段 B/C 的剩余阻断项，应继续按本文顺序整改。

优先级定义：

- **P0**：阻止契约冻结、可能造成安全问题、开发态配置损坏、错误成功提示或开发调试不可用。
- **P1**：试点前应完成的功能闭环、语义一致性、规模化和关键易用性问题。
- **P2**：体验一致性、工程质量、文档和后续增强项。

### 2.1 明确排除项

以下内容属于节点运行态，不作为本文缺陷，也不进入 P0/P1/P2：

- 工业驱动是否已经具备节点运行平台和正式采集执行器。
- timer/datapoint_change 是否由 `data_service` 在开发态自动调度。
- 历史库自动建表、采样写入、清理任务和历史查询。
- 报警活动实例计算、确认、消音、通知投递和历史写入。
- 节点侧计算任务调度、并发、重试、补偿和错过触发处理。

本文仍会检查这些运行态配置在开发态是否可填写、字段是否明确、校验是否正确、快照/Artifact 是否完整且不泄密，但不检查节点是否已经执行它们。

## 3. 工业采集

### 3.1 全量驱动现状

当前共有 115 份驱动 Manifest，协议族主要分布如下：Melsec 13、Omron 8、Siemens 7、Modbus 6、Keyence 6、Inovance 6、Allen-Bradley 6，其他协议族合计 63。

全量能力统计：

- 115/115 仅声明 `polling`。
- 115/115 仅声明 `windows-x64` 开发调试代理。
- 115/115 的 `platforms.runtime` 均为空。
- 115/115 支持 `connection.test/open/close/point.read`。
- 0/115 支持 `point.write`。
- 0/115 支持订阅式采集。
- 只有 OPC UA 支持 `device.browse`。
- 110/115 支持 `point.elementCount`；EC Fan、IEC 60870-5-104、OPC UA、RKC 串口和 RKC TCP 五个驱动未声明该能力。

这些统计用于说明当前开发态可配置和可调试的能力边界。`platforms.runtime` 为空属于后续节点实现状态，不作为本次数据中心缺陷或整改项。

## 7. 计算模块

### 7.1 总体判断

计算是当前风险最大的模块。页面看起来已经是通用脚本计算平台，但后端实际上更接近“开发态手动执行 JS/Python + 少量预取 SDK”的原型。应先收缩对外承诺或补齐执行隔离和真实能力，再进入契约检查。

## 8. 报警模块

### 8.1 当前合理部分

- 普通报警已经变成“一点多报警项”，同一点可同时配置越限、变化率、偏差、离线等报警。
- 多点创建在事务中生成独立报警项，后续可独立编辑和启停。
- 越限报警支持任意数量等级和 `highest_matching`，组合报警使用输入别名及受限表达式。
- 表格后端分页，具备当前选择/全部结果批量操作和 Excel 预览/应用流程。
- 数据点页面保持只读摘要并跳转报警模块，避免多入口编辑。
- 工程通知、渠道加密密钥和报警历史配置的开发态边界清晰。

## 11. 建议整改顺序

### 阶段 A：先消除错误承诺和安全风险（已完成）

1. 计算的开发调试区只展示真实可调试的 SDK；定时/点变继续作为节点触发配置保留，但必须完成结构校验并明确“开发态不自动执行”。
2. 将计算调试迁入隔离执行器，禁止继承服务环境和宿主目录/网络。
3. 外部接入源密钥改成密钥表 + secret reference，清理 Artifact 明文。
4. 修复 MQTT 等专用接入源更新链路；TDengine 使用独立 WebSocket 运行时提供真实只读 SQL 工作台，不复用关系库适配器或通用建表能力。

### 阶段 B：修复数据一致性和事务

1. 增加接入源删除影响检查与事务化删除。
2. 修复数据点有效性筛选口径和计算引用删除保护。
3. 事务化计算单元/输出点保存，禁止吞掉输出写错误。
4. 为外部 SQL 增加超时、行数和响应体限制。

### 阶段 C：修正报警语义

1. 把条件结果升级为 matched/not_matched/paused 三态。
2. 实现分级越限活动等级与候选等级的独立延时。
3. 修正变化率、transition 延时、死区字段和重叠判断。
4. 补质量报警和 stale 报警，完善时间序列试算。

### 阶段 D：清理开发残留并收敛产品闭环

1. 删除无引用组件、Store、composable、mock 预览和空 Scheduler，完成后执行前后端全量构建。
2. 删除 `alarm_low/alarm_high` 数据列及 DTO/API/快照全链路，按最终基线直接重置本地开发库。
3. 计算强类型多输出和计算单元历史作用域。
4. SQL/HTTP/WebSocket/Redis 标量/字段映射。
5. 工业协议族地址助手、诊断和能力状态。
6. 统一分页、树加载、底部批量栏、筛选文案和公共弹窗。
7. 清理 `@ts-nocheck`、阶段性命名、并行读模型、临时日志和旧文档。

## 13. 建议的代表性验收矩阵

无需 115 个驱动都人工重复同一套测试，但不能只测一个 Siemens。工业采集建议按能力差异选择：

- Siemens S7 TCP：数据块、Bool/数值/字符串/数组。
- Modbus TCP 与 RTU：网络/串口、位区/字区、字节序和数组。
- Melsec MC：厂商地址体系和重复目录治理。
- Omron FINS：地址区和类型映射。
- Allen-Bradley CIP：Tag/数组和特殊类型。
- OPC UA：浏览、NodeId、datetime 和数组。
- IEC 60870-5-104：无 elementCount 的特殊点模型。
- MQTT-RPC 或 HTTP 类工业驱动：非传统 TCP/串口传输。

外部接入源则每类至少覆盖：新建、编辑后真实配置生效、测试、创建数据点、当前值语义、删除占用、快照往返和 Artifact 脱敏。
