> Review 日期：2026-08-26（第二轮整体复核）
>
> Review 范围：数据中心前端、`data_service`、数据库最终基线、工程快照与发布 Artifact。
> 本文只审查数据中心开发态的配置、建模、调试、保存、批量维护、快照和发布输出。节点侧采集、调度、历史写入、报警计算、通知投递和历史查询均不属于本次整改范围。

## 1. 结论

当前数据中心已经具备较完整的开发态信息架构，数据点分页与跨页批量、工业连接和变量建模、来源级历史配置、点位报警项、组合报警、通知与报警历史等主要形态基本合理。

阶段 A、B、C、D 的原定后端契约、数据安全、事务和开发态试算项已完成；第二轮从真实页面交互反向检查发现的契约检查、创建响应、未保存保护、请求乱序和定时器 UI 问题也已完成整改。经自动校验和侧边浏览器再次验收，当前结论修正为：**数据中心开发态功能已具备进入正式数据契约检查的条件，第二轮没有遗留 P0/P1/P2 阻断项**。节点运行态执行仍按本文边界排除，不能由本结论外推为节点侧已完成；开发态外部 SQL 连通性已另用本地 PostgreSQL、MySQL、TDengine 和 SQL Server 兼容实例实测，结果见 1.8。

优先级定义：

- **P0**：阻止契约冻结、可能造成安全问题、开发态配置损坏、错误成功提示或开发调试不可用。
- **P1**：试点前应完成的功能闭环、语义一致性、规模化和关键易用性问题。
- **P2**：体验一致性、工程质量、文档和后续增强项。

阶段 B 原四项此前已经完成，本轮对超出原阶段范围的跨聚合保存继续做了全局收口。用户可见写操作的最终事务矩阵如下：

| 用户操作                       | 同一事务内必须完成                                        | 事务外操作与处理方式                                           |
| ------------------------------ | --------------------------------------------------------- | -------------------------------------------------------------- |
| 普通/专用连接保存              | 主连接、协议明细、密钥替换或删除                          | 连通测试单独执行并保存独立测试摘要，不与配置保存伪装为同一事务 |
| SQL 查询保存                   | 查询主记录、参数                                          | 查询预览独立执行；普通保存不创建或改写数据点                   |
| SQL 查询生成数据点             | 输出映射、生成数据点                                      | 由右侧状态按钮显式提交；默认完整结果集，高级模式按列/字段提取  |
| SQL 查询删除                   | 锁定查询和生成点、引用检查、删除查询、无引用输出点失效    | 无                                                             |
| HTTP 请求 / WebSocket 会话保存 | 主对象、请求配置、输出映射、生成数据点                    | 外部请求预览和临时会话是独立结果                               |
| Redis Key 输出创建             | 所有 Key 与字段映射先完整校验，再一次写入输出映射和生成点 | 外部取样在事务前完成；任一取样或校验失败时不进入数据库写事务   |
| MQTT / Kafka 映射保存          | 来源配置、映射、生成点和密钥                              | Broker 预览独立执行并返回自己的失败结果                        |
| 工业连接 / 采集点保存删除      | 连接、点配置、生成点、引用检查和失效处理                  | 代理连接/读取测试独立执行并保存测试摘要                        |
| 计算单元保存删除               | 单元、输入引用、规范化输出、生成点、依赖/引用检查         | 沙箱调试先执行，调试输出与运行记录在成功提交阶段另用单事务写入 |
| 历史配置保存                   | 配置、目标整体替换和版本递增                              | 目标连通状态只作风险提示，不参与配置事务                       |
| 报警项保存删除                 | 报警项、条件、组合输入、通知引用、版本递增                | 通知测试发送独立执行，不写报警运行投递记录                     |

## 13. 建议的代表性验收矩阵

日常回归可按能力差异选取代表驱动；驱动目录、Schema 或通用工作台发生系统性调整时，应再次执行 115 类全量建模验收。代表性通信验收建议选择：

- Siemens S7 TCP：数据块、Bool/数值/字符串/数组。
- Modbus TCP 与 RTU：网络/串口、位区/字区、字节序和数组。
- Melsec MC：厂商地址体系和重复目录治理。
- Omron FINS：地址区和类型映射。
- Allen-Bradley CIP：Tag/数组和特殊类型。
- OPC UA：浏览、NodeId、datetime 和数组。
- IEC 60870-5-104：无 elementCount 的特殊点模型。
- MQTT-RPC 或 HTTP 类工业驱动：非传统 TCP/串口传输。

外部接入源则每类至少覆盖：新建、编辑后真实配置生效、测试、创建数据点、当前值语义、删除占用、快照往返和 Artifact 脱敏。

本轮新增的 UI 代表性验收矩阵：

| 场景              | 成功路径                                                           | 失败/边界路径                                                                                                          |
| ----------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 契约检查          | 运行后按后端 `list/summary/checkedAt` 展示，可查最新记录和历史     | 后端返回 failed/error、无历史、超时、Schema 不匹配时不得显示“已满足”；超过单页上限的数据点/查询/计算单元仍必须参与检查 |
