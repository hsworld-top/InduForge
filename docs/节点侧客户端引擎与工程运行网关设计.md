# 节点侧客户端引擎与工程运行网关设计

## 1. 文档定位

本文档定义节点侧工程运行界面的客户端引擎、工程入口和工程运行网关如何实现，以及它们与运行态数据引擎之间的交互边界。

本文档只覆盖最终运行态。开发态预览仍由设计中心和平台侧 `data_service` 承接。

## 2. 核心结论

1. `client_engine` 是 Vue + TypeScript 实现的静态客户端运行时。
2. `client_engine` 由工程 `project_nginx` 托管，不需要常驻 Node 后台。
3. Node/Vite 只用于构建期，不作为节点侧运行时依赖。
4. `runtime_api` 是工程运行网关，承接所有运行态动态 API。
5. 工程运行态用户、会话、角色和权限由 `runtime_api` 基于 `RuntimeSecuritySnapshot` 本地闭环处理。
6. `client_engine` 不直接访问 NATS、IF 内置库、外部数据库、采集器或数据引擎内部角色。
7. `project_nginx` 是工程 compose 内唯一对外入口，并映射一个由 `node_agent` 分配的宿主机端口。

## 3. 运行形态

```text
用户浏览器
  ↓
node-ip:<project-port>
  ↓
project_nginx
  ├─ /                         -> client_engine 静态资源
  ├─ /assets/*                 -> client_engine 构建产物
  ├─ /project/*                -> 工程 manifest、页面 schema、工程资源
  ├─ /runtime-config.json      -> node_agent 生成的运行配置
  ├─ /api/runtime/*            -> runtime_api
  ├─ /api/data/*               -> runtime_api
  ├─ /api/alarm/*              -> runtime_api
  ├─ /api/action/*             -> runtime_api
  ├─ /ws/*                     -> runtime_api
  └─ /collector-upstream/*     -> runtime_api 或 NATS 代理
```

工程内部：

```text
project-compose
├─ project_nginx
├─ client_engine 静态资源
├─ runtime_api[n]
├─ data_engine_collector[n]
├─ data_engine_writer[n]
├─ data_engine_alarm[n]
├─ data_engine_compute[n]
├─ NATS JetStream
└─ IF 内置库
```

## 4. project_nginx

`project_nginx` 是工程运行栈唯一对外入口。

职责：

- 映射一个宿主机端口。
- 托管 `client_engine` 静态资源。
- 托管工程发布包内的页面 schema 和资源文件。
- 托管 `node_agent` 生成的 `runtime-config.json`。
- 反向代理运行态动态 API 到 `runtime_api`。
- 反向代理 WebSocket 到 `runtime_api`。
- 按需代理采集盒子上行入口。
- 按需代理 IF消息库 MQTT 入口。

非职责：

- 不做工程运行态业务权限判断。
- 不连接数据库。
- 不理解页面 schema。
- 不执行采集、报警和计算。

## 5. client_engine

### 5.1 职责

`client_engine` 是浏览器内运行的静态客户端引擎。

职责：

- 加载 `runtime-config.json`。
- 加载工程 `manifest.json`。
- 加载页面 schema 和工程资源。
- 使用共享运行内核解释页面。
- 渲染运行态组件。
- 执行绑定表达式、页面变量和组件事件。
- 通过 Data SDK 调用 `runtime_api`。
- 建立 WebSocket 实时订阅。
- 根据权限摘要控制菜单、页面、按钮和动作显隐。

非职责：

- 不直接连接数据库、NATS、IF 内置库或外部接入源。
- 不执行可信权限判断。
- 不处理工程用户密码校验。
- 不执行服务端脚本。
- 不承担采集、报警和计算。

### 5.2 构建与托管

`client_engine` 使用 Vue + TypeScript 实现。

```text
开发构建：Node / pnpm / Vite
运行托管：project_nginx
运行形态：静态 HTML / JS / CSS
```

运行态不启动 Node 后台。所有动态能力都走 `runtime_api`。

### 5.3 启动流程

```text
1. 浏览器访问工程端口。
2. project_nginx 返回 index.html。
3. 浏览器加载 client_engine 静态资源。
4. client_engine 请求 /runtime-config.json。
5. client_engine 请求 /project/manifest.json。
6. client_engine 检查本地 token。
7. client_engine 调用 /api/runtime/auth/me。
8. 未登录时显示工程运行态登录页。
9. 登录成功后请求 /api/runtime/bootstrap。
10. 根据 bootstrap 返回的页面、权限和项目摘要渲染工程界面。
```

### 5.4 runtime-config.json

`runtime-config.json` 由 `node_agent` 在启动工程时生成，不包含密钥。

```json
{
  "projectId": "proj_001",
  "projectCode": "factory_demo",
  "version": "2026.05.26-001",
  "apiBase": "/api",
  "wsBase": "/ws",
  "manifestUrl": "/project/manifest.json",
  "defaultLocale": "zh-CN",
  "runtimeKernelVersion": "1.0.0"
}
```

## 6. runtime_api

`runtime_api` 中文名为“工程运行网关”。它是工程运行态唯一可信动态 API 后端。

### 6.1 职责

`runtime_api` 负责：

- 工程运行态用户登录、登出、刷新和当前用户查询。
- 加载 `RuntimeSecuritySnapshot`。
- 校验运行态 token 和会话。
- 校验页面、动作、查询、数据点、报警等资源权限。
- 返回客户端启动所需 bootstrap。
- 执行查询、点位读取、历史查询。
- 处理报警确认、消音和运行态动作。
- 提供 WebSocket 实时数据通道。
- 对接 `runtime_data_service` 组。
- 记录运行态安全审计。

`runtime_api` 不负责：

- 平台用户管理。
- 编辑工程运行态用户和角色主数据。
- 采集协议执行。
- 时序批量写入。
- 报警规则计算。
- 计算任务调度。

### 6.2 工程运行态用户

工程运行态用户是最终工程访问用户，不等同于平台用户。

主数据由 `dev_core` 管理，发布时进入 `RuntimeSecuritySnapshot`：

```json
{
  "runtimeUsers": [
    {
      "id": "ru_001",
      "username": "operator01",
      "displayName": "操作员01",
      "status": "enabled",
      "passwordHash": "...",
      "passwordAlgo": "argon2id",
      "roleIds": ["operator"]
    }
  ],
  "runtimeRoles": [
    {
      "id": "operator",
      "name": "操作员"
    }
  ],
  "runtimeGrants": [
    {
      "roleId": "operator",
      "resource": "page:home",
      "actions": ["view"]
    },
    {
      "roleId": "operator",
      "resource": "datapoint:s7.line1.temp",
      "actions": ["read"]
    }
  ]
}
```

运行态离线时，`runtime_api` 仍应能基于本地快照完成登录和授权。

### 6.3 API 分组

建议 API 分组：

```text
POST /api/runtime/auth/login
POST /api/runtime/auth/logout
POST /api/runtime/auth/refresh
GET  /api/runtime/auth/me
GET  /api/runtime/bootstrap

POST /api/data/query/:queryId/execute
POST /api/data/datapoints/latest
POST /api/data/datapoints/history

GET  /api/alarm/instances
POST /api/alarm/instances/:id/ack
POST /api/alarm/instances/:id/silence

POST /api/action/:actionId/execute

WS   /ws/data
WS   /ws/runtime
```

所有接口响应应遵循统一运行态响应结构：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {},
  "reqId": "req_xxx"
}
```

### 6.4 权限校验

权限必须双层处理：

- `client_engine` 根据 bootstrap 权限摘要控制界面显隐。
- `runtime_api` 对每个动态请求做最终可信校验。

前端隐藏按钮不能替代服务端权限校验。

## 7. 数据交互

### 7.1 首屏数据

```text
client_engine
  -> /api/runtime/bootstrap
  -> /api/data/datapoints/latest
  -> /api/data/query/:queryId/execute
```

首屏数据应尽量批量请求，避免组件逐个发起接口调用。

### 7.2 实时订阅

```text
collector / compute
  -> NATS JetStream
  -> writer / alarm
  -> runtime_api WebSocket
  -> client_engine
```

`client_engine` 应按页面生命周期自动订阅和取消订阅。高频点位更新应在浏览器侧做批量合并，避免每条消息触发完整渲染。

### 7.3 页面动作

```text
用户点击按钮
  -> client_engine Action Engine
  -> runtime_api /api/action/:actionId/execute
  -> runtime_api 权限校验
  -> runtime_data_service 或外部连接
  -> 返回动作结果
```

## 8. 与数据引擎边界

`runtime_api` 是客户端和数据引擎之间的唯一可信 API 边界。

| 能力 | 承担方 |
| --- | --- |
| 页面渲染 | `client_engine` |
| 登录、会话、权限 | `runtime_api` |
| 查询接口 | `runtime_api` |
| WebSocket | `runtime_api` |
| 采集 | `runtime_data_service` collector |
| 写入 | `runtime_data_service` writer |
| 报警计算 | `runtime_data_service` alarm |
| 计算任务 | `runtime_data_service` compute |
| 内部事件流 | NATS JetStream |
| 数据存储 | IF 内置库或用户外部库 |

## 9. 与 node_agent 边界

`node_agent` 负责：

- 生成 `runtime-config.json`。
- 生成 `docker-compose.runtime.yml`。
- 分配工程宿主机端口。
- 启停 `project_nginx`、`runtime_api` 和数据引擎角色。
- 聚合健康状态。
- 回传运行状态。

`node_agent` 不负责：

- 工程运行态用户登录。
- 页面 schema 解释。
- 查询、报警、动作执行。
- 采集协议逻辑。

## 10. 待冻结问题

1. `runtime_api` 是否独立镜像，还是与 `runtime-data-engine` 同镜像不同 role。
2. 工程运行态 token 签名密钥的生成、轮换和本地存储方式。
3. `runtime-config.json` 的正式 JSON Schema。
4. WebSocket 消息格式和断线补偿策略。
5. 页面 schema 是否需要按权限在 `runtime_api` 服务端裁剪，还是首版只在客户端显隐并由接口强校验。
