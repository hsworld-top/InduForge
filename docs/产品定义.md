# 产品定义

## 1. 模块定位

InduForge 是一个面向工业场景的低代码交付平台。当前阶段目标不是先做完整节点运行闭环，而是先完成设计、数据建模与开发态预览主线，并为后续发布、部署和节点运行奠定基础。

## 2. 目标用户

### 当前已实现对应用户

- 平台管理员
- 系统管理员
- 工程管理员
- 运维管理员
- 工程开发人员

### 共创后建议目标用户

- 方案架构师
- 可视化开发工程师
- 数据集成工程师
- 运维工程师
- 现场使用方

## 3. 核心问题

### 当前已实现

- 工程设计、数据接入、节点控制的分工主干已建立

### 共创后建议目标

平台应解决以下问题：

- 工业应用交付依赖多个角色协作，当前流程碎片化
- 设计、数据、部署、运行之间容易断层
- 设计器缺少稳定、可复用到运行态的预览能力
- 节点现场环境复杂，需支持可观测、可回滚、可维护的运行机制

## 4. 功能范围

## 6. 核心能力

### 当前已实现

- 平台主数据管理
- 运维控制面

- 设计器内核主干

### 共创后建议目标

- 发布态契约稳定
- 契约稳定可供 AI 模块开发继续推进

## 7. 关键流程

### 流程1：设计交付流程

1. 在 `dev_ide` 创建工程
2. 在 `designer` 配置页面、变量、绑定
3. 在 `datacenter` 配置连接、查询、Tag、数据点
4. 在 `designer` 中进入开发态预览
5. 通过 `dev_core/datacenter` 获取预览所需数据
6. 预览内核完成页面解释、渲染和基础绑定
7. 后续再进入发布与部署链路

### 流程2：运维流程

1. 节点发起注册申请
2. 平台审批通过
3. 节点上报心跳
4. 运维选择部署/启停/回滚
5. 节点执行并上报结果
6. 平台展示当前状态与失败原因

## 9. 与其他模块协作关系

- `designer` 输出页面结构给 `dev_core`
- `datacenter` 输出数据语义给 `dev_core` 和预览/运行共享内核
- `dev_core` 当前先统一工程聚合与预览支撑，后续再强化制品与部署编排
- `dev_ide` 负责可视化管理与操作入口
- `node_agent` 当前阶段后置
- 共享渲染内核同时服务预览和后续 Runtime

## 10. 当前已实现能力

- 平台侧主链路已具备 70% 左右的管理与控制面能力
- 节点控制面已具备较高完成度
- 真正共享渲染内核与开发态预览主线尚未开始实施

## 11. 共创后建议目标

- 在本期完成开发态预览和共享渲染内核
- 将平台从“可配置”推进到“可预览、可演进到可交付”
