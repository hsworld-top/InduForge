# FEATURES

## 分类原则
- Table Stakes：不做会直接影响可用性的基础能力。
- Differentiators：形成平台竞争力的增强能力。
- Anti-Features：当前阶段明确不做，避免范围失控。

## Table Stakes（v1 必须保稳）

### 项目与权限
- 多租户/用户/角色的基础管理可用。
- 项目权限与资源访问校验一致。
- 后端错误码与响应体可被前端统一消费。

### 设计与发布
- 设计器可输出稳定发布态数据结构。
- 发布产物包含运行必需文件（manifest、pages、assets、data）。
- 发布失败可定位，成功后可追踪版本。

### 部署与运行
- 节点能接收部署指令并执行启动/停止/回滚。
- Runtime 暴露最小健康状态接口（`/health`、`/status`）。
- 平台可见节点与运行状态，支持排障。

### 数据与实时
- 数据连接可管理，查询与订阅链路稳定。
- MQTT/Socket 通道在核心场景可持续工作。

## Differentiators（v1.1+ 优先）
- 发布契约校验器（发布前自动校验 schema/manifest）。
- 跨模块可观测仪表（发布、部署、运行、数据链路统一视图）。
- 节点侧灰度与回滚策略可配置化。

## Anti-Features（当前阶段不做）
- 全面视觉重设计与主题系统重构。
- 移动端 App 或多终端统一壳工程。
- 替换现有核心栈（Express/Sequelize/Vue）的大改造。

## 复杂度与依赖
| 类别 | 复杂度 | 关键依赖 |
|---|---|---|
| 响应与错误契约统一 | 中 | `dev_core` 路由、中间件、前端请求封装 |
| 发布契约闭环 | 高 | `designer` 导出、`dev_core` 打包、NodeAgent 解析 |
| Runtime 状态可观测 | 中 | NodeAgent API、平台采集与展示 |
| 权限策略收敛 | 中 | 鉴权中间件、角色能力模型、回归测试 |

## 结论
v1 应该聚焦“稳定可交付”：先把契约、部署、观测打通，再推进增强能力。
