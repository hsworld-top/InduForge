# 文档审计报告

## 审计原则

- 代码、库表、接口、已实现能力优先级高于旧文档。
- 旧文档仅作为历史设计意图和阶段性方案参考。
- 当文档与现状冲突时，优先认定为文档过期，除非代码明显只实现了半成品。
- 本报告中的处理建议分为：保留、修订、重写、归档。

## 主要冲突点

1. `dev_ide` 文档写“运维管理待开发”，但代码已形成成熟运维页。
2. Designer refactor 文档对 RuntimeEngine、动作系统、多端支持描述明显超前，而运行时目录为空。
3. 平台高层设计文档将很多目标态能力写成了现状，容易误导后续 AI 开发。
4. NodeAgent 文档主体可信，但未完全反映近几次“中心绑定、审批、SQLite bootstrap、前端嵌入静态资源”的变更。
