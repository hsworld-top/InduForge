# designer AI 分发包

## 1. 模块定位
- `designer` 是低代码页面设计器。
- 当前阶段的核心职责是：输出稳定的发布态工程 Schema，并承接开发态预览宿主。

## 2. 当前已实现
- 编辑器内核、页面模型、属性面板、绑定与表达式基础能力已存在。
- 页面、组件树和基础配置可保存。

## 3. 当前缺口
- 编辑态模型与发布态模型未正式分离。
- `project.json`、`page.json`、组件节点、绑定对象没有冻结的导出协议。
- 与 Runtime 的消费格式尚未彻底对齐。

## 4. 本模块目标
- 冻结发布态 Schema。
- 在设计器内落地预览宿主。
- 导出结果可被共享渲染内核直接消费。
- 为导出和预览流程提供校验和诊断。

## 5. 直接输入
- [产品定义](../../docs/产品定义.md)
- [开发态预览专项计划](../docs/process/platform/开发态预览专项计划.md)
- [发布态 Schema 契约](../../docs/contracts/designer-publish-schema.md)
- [designer.task](./tasks/designer.task.md)

## 6. 输出物
- `project.json`
- `pages/<pageId>.json`
- 预览宿主
- 导出校验结果
- 设计器运行时兼容说明

## 7. 关键对象
- 页面
- 组件节点
- 绑定对象
- 全局变量
- 入口页配置

## 8. 必须遵守的约束
- 发布态只保留 Runtime 必需字段
- 不把编辑器内部状态带入运行态
- 白名单组件优先：`text`、`image`、`button`、`table`、`container`

## 9. 模块边界
### 本模块负责
- 发布态工程结构
- 导出校验
- 导出诊断信息
- 预览入口与预览容器

### 本模块不负责
- 制品打包
- 节点部署
- 独立运行态宿主

## 10. 验收标准
- 发布态文件结构稳定
- `entryPageId`、`routePath`、绑定对象通过校验
- 设计器内可预览入口页
- 共享渲染内核不需要二次大规模转换即可消费

## 11. 建议推进顺序
1. 冻结 `project.json`
2. 冻结 `page.json`
3. 冻结组件节点与绑定结构
4. 接入预览宿主
5. 增加导出校验和诊断

## 12. 非目标
- 不扩复杂动作系统
- 不扩多视图
- 不扩复杂权限模型
